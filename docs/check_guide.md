# 今の本での照合の手順（②・D-017・SPEC R8）

著作権のある今の訳・注釈書・辞書は、本文を使わず、判定だけを使います。

- 内容が食い違う文があれば、その回の公開を保留します。
- 内容が同じなら、何も変えません。

## 決まり

- 使う本は、手に取れる紙の本だけにします（自分の本か、図書館で借りた本）。
  - 電子書籍（コピー防止つき）は使いません。
  - 有料の辞書サービス（JapanKnowledge など）は使いません。規約で、写しや AI への入力を禁じていることが多いためです。
- 本の該当箇所は、照合のときにその場で入力します。渡す先は手元の Ollama（127.0.0.1）だけです。
- 残すのは次の4つだけです。
  - 判定のラベル（一致・食い違い・触れていない）
  - 言い回しの近さ（コードで数える）
  - 本の書誌とページ
  - 照合した人と日
- 本の文は、どこにも残しません。ファイル・DB・ログ・画面のどれにも書きません。
- AI に理由の文を書かせません。言い換えの形で本の表現が漏れるためです。
- クラウドの AI（Claude など）には、本の文を渡しません。
- 入力するのは、主張にかかわる所だけにします（1500字まで）。

### 法律上の注意

- 入力した時点で写しができます。この使い方は、著作権法30条の4（人が内容を楽しむ目的ではない利用）に頼っています。判例はありません。
- 30条の4で作った写しを、画面に出すなどして人が楽しむ形で使うと、複製をしたとみなされます（49条1項2号）。本の文を画面・ログ・AI の答えに出さない決まりは、そのためにも守ります。
- 利用者の考え（D-017）：使うのは今の本の表現ではなく、内容（考え・解釈・事実）の確認だけです。台本に本の表現は出しません。
- 弁護士への相談は任意です。相談するなら、尋ねたいことは次の2つです。
  - 照合という目的が、「思想を楽しむ目的」に当たらないか
  - 30条の4の3号ではなく、柱書き（本文）に頼ってよいか

## Ollama の設定（照合に使う Mac で、最初に1回）

Ollama は 127.0.0.1 で動いていても、次の場合は要求を ollama.com へ転送します。

- 名前が `:cloud`・`-cloud` で終わるモデル
- クラウドのモデルを取り込んだもの（マニフェストに remote_host を持つもの）

koten は照合の前に次のことを確かめ、当てはまれば止めます。

- モデルの名前
- Ollama の `/api/show` の remote_host
- 送った文を記録に残す設定（OLLAMA_DEBUG_LOG_REQUESTS と OLLAMA_DEBUG=2）

設定のほうでも、次のようにしておきます。

1. Ollama を新しい版にします（`ollama -v` で版を見る）。古い版には、記録に本文を書くものがありました。
2. Ollama のクラウドを止めます。`~/.ollama/server.json` に `{"disable_ollama_cloud": true}` と書き、Ollama を起動し直します。起動の記録（`~/.ollama/logs/server.log`）に「Ollama cloud disabled: true」と出れば止まっています。
3. 照合に使う Mac では、Ollama にサインインしません。
4. Ollama アプリの設定では、Expose（ほかの機器からの接続）と Browser（ウェブページからの接続）を入れません。
5. 本の文は `ollama run` やアプリのチャット画面に貼りません。シェルの引数（`curl -d` など）にも書きません。履歴に残るためです。

## 照合のしかた

1. 本を台帳に書きます（config/ref_books.csv。本の文の列は作れません）。

   | 列 | 書くこと |
   |---|---|
   | book_id | `B-` で始まる ID |
   | title・people・publisher・year・edition・isbn | 書誌（people は著者・訳者・注釈者） |
   | kind | translation・annotation・dictionary・kundoku・other |
   | medium | paper_owned（自分の紙の本）か paper_library（図書館の紙の本） |
   | covers | 扱う古典（lunyu など。メモ） |
   | show_in_description | 説明欄の「参考にした本」に出すか（yes・no） |
   | affiliate_query | アフィリエイトの検索語 |
   | note | 自分の言葉で60字まで |

2. 照合する文を見ます。

   ```sh
   uv run koten check books
   uv run koten check list --episode E20261101-01
   ```

   - 文に番号（C1…）が付きます。既定では、一節か語釈・解釈のある章の文だけを出します。全部の文を見るときは `--all` を付けます。
   - E20261101-01 は例です。`koten episode list` で、実際の回の ID を見てください。

3. 照合します。本を開き、該当箇所を写真に撮ります。写真から文字をコピーします（Live Text）。コピーしたら、次のどちらかで渡します。

   ```sh
   pbpaste | uv run koten check run --episode E20261101-01 --claim C5 --book B-gendai --page 23ページ
   ```

   - コピーせずに渡すときは、パイプ（`pbpaste |`）を付けずに実行します。貼り付けて、最後に Ctrl-D を押します。端末には表示されません。
   - 例の C5・B-gendai・23ページは、自分の値に置き換えてください。
   - 照合のあと、Mac のクリップボードは自動で空にします。残すときは `--keep-clipboard` を付けます。
   - 本の写真はアプリで保存しないでください。iCloud 写真に上がります。カメラの画面のまま文字をコピーするか、撮った写真をすぐ消します。
   - 照合のあとは、端末のスクロールの記録を Cmd-K で消すと安心です。
   - クリップボードの履歴を残すアプリ（Raycast・Alfred など）を使っているなら、照合のあいだは止めます。

4. 判定を見ます。

   | 判定 | すること |
   |---|---|
   | 一致（内容が同じ） | 何も変えない |
   | 触れていない | 何も変えない |
   | 食い違い | 公開を保留する |
   | 言い回しが本に近い | 公開を保留する。判定が一致でも保留にする（今の訳の写しになるおそれがあるため） |

   - 「言い回しが近い」の基準は、次のどちらかです。字数はふるい分けの目安で、法律の線ではありません。
     - 同じ並びが12字以上続く
     - 台本の文の4字の並びのうち、35%以上が本にある
   - AI を使わずに、自分で読んで判定を残すこともできます（`--verdict same`・`differs`・`not_covered`。言い回しが近いときは `--close`）。

5. 保留を解きます。

   - 保留は、文の位置ではなく文の中身に付きます。
     - 食い違った文が台本のどこかに同じ中身で残っていれば、文を直すまで保留のままです。人の判定で「一致」を足しても、文の位置が変わっても、解けません。
     - `--close` を付けると、厳しくする向きにだけ働きます（コードの数えた結果と合わせ、どちらかが近ければ近い）。
   - 言い回しの近さは、自分たちの言葉だけで数えます。一節・語釈・時代の解釈など、DB から差し込む部分は数えません。保護期間の切れた訓読が今の本と同じでも、保留にはしません。
   - 照合の AI への接続は、プロキシ（HTTP_PROXY や Mac のシステムのプロキシ）を通しません。本の文がプロキシのアプリの画面や記録に残らないようにするためです。

   ```sh
   uv run koten check status --episode E20261101-01
   ```

   - 直すときは、今の本を閉じて書きます。根拠にするのは、原文と保護期間の切れた資料（明治の訓読・古い辞書・古い英訳）です。
   - 今の本の言い回しを直して使うことはしません。本の文を AI に渡して書き直させることもしません。
   - 直した文は、同じ本でもう一度照合します。一致か触れていないになり、言い回しも近くなければ、保留が解けます。
   - 文を台本から消したときは `uv run koten check resolve --episode E20261101-01 --key ch2-s3#1 --note 段落を削った` のように、理由を書いて解きます。文が残っているあいだは解けません。
   - `koten episode list` の回には「※照合で食い違いあり」が付きます。公開（M6・M7）の前に、必ず `check status` で保留が無いことを確かめます。
