## 2. 全体の構成

```
 Apple Watch ─→ iPhone アプリ ──(HTTPS: /api/*)──→ サーバー（Cloudflare Workers + D1）←─ SwitchBot のクラウド
                  │  ▲                                  │  ▲                              （5分ごと＋Webhook）
                  │  └──── 通知（APNs）──────────────────┘  │
                  └ ショートカット（充電の記録）              │
                                                            └──(HTTPS: /ai/*)── Claude Code のスケジュールされたタスク
                                                                                （1日1回、食事の目安を出す）
```

### 2.1 認証（Phase 1 は自分専用）
合言葉（トークン）を3種類に分け、それぞれ使える API を絞る。

| 合言葉 | 使う人・もの | 使える API |
|---|---|---|
| `APP_TOKEN` | iPhone アプリ | `/api/*` |
| `AI_TASK_TOKEN` | Claude Code のタスク | `/ai/*`（食事の記録を読み、目安を書き込むだけ） |
| `ADMIN_TOKEN` | あなた（動作確認） | `/admin/*` |

どれも `Authorization: Bearer <合言葉>` で送る。Phase 3 で Sign in with Apple に置き換える。

## 3. アプリとサーバーの間の決まり（API）

時刻はすべて **UTC のエポックミリ秒**（`1764000000000` の形）。日付は利用者のタイムゾーンでの `YYYY-MM-DD`。

### 3.1 アプリ → サーバー（送る）

#### `POST /api/health/batch` — HealthKit のデータ
```json
{
  "samples": [
    { "uuid": "…", "type": "sleepAnalysis", "start": 1764000000000, "end": 1764001800000,
      "valueText": "asleepCore", "source": { "name": "Apple Watch", "productType": "Watch7,1" } },
    { "uuid": "…", "type": "heartRateVariabilitySDNN", "start": 1764000000000, "end": 1764000060000,
      "value": 42.1, "unit": "ms", "source": { "name": "Apple Watch", "productType": "Watch7,1" } }
  ],
  "buckets": [
    { "type": "heartRate", "start": 1764000000000, "minutes": 5, "avg": 58, "min": 55, "max": 63 },
    { "type": "stepCount", "start": 1764000000000, "minutes": 60, "sum": 532 }
  ],
  "workouts": [
    { "uuid": "…", "activityType": "running", "start": 1764000000000, "end": 1764001800000,
      "energyKcal": 320, "distanceM": 5000, "avgHeartRate": 150, "effort": 7 }
  ],
  "deleted": ["<HealthKit で削除されたデータの uuid>"]
}
```

| 区分 | 送り方 | 対象 |
|---|---|---|
| `samples` | 測った値そのまま（HealthKit の uuid つき） | 睡眠ステージ、HRV、呼吸数、血中酸素、呼吸の乱れ、手首皮膚温、安静時心拍、歩行時の平均心拍、心拍数の回復、VO2max、心の状態、マインドフルネス、カフェイン、飲酒 |
| `buckets` | 一定の時間ごとの集計 | 心拍数（**5分ごと**の平均・最小・最大）、歩数・移動距離・上った階数・アクティブカロリー・エクササイズ・スタンド・日光・環境音・ヘッドフォンの音量（1時間ごと） |
| `workouts` | 1回ごとの概要 | ワークアウト |
| `deleted` | 削除されたデータの uuid | すべて |

- 心拍数は、夜の詳細画面で部屋の値と重ねるため、[分析の設計の2.4](./analysis.md#24-サーバーに送る細かさ) の「1時間ごと」から **5分ごと**に細かくした。
- 同じ uuid・同じ時間の集計を送り直したら、上書きする（何度送っても結果は同じ）。
- 1回に送るのは 5,000件・1MB まで。過去1年分の取り込みは、アプリが小分けにして送る。
- 単位は型ごとに決めておく（心拍は回/分、HRV は ms、血中酸素は %、温度は ℃、カロリーは kcal、時間は分、カフェインは mg、飲酒は杯）。

#### `POST /api/logs/batch` — 手入力・ショートカット・スクリーンタイムの記録
```json
{
  "logs": [
    { "id": "<アプリが作る uuid>", "kind": "meal", "occurredAt": 1764000000000,
      "data": { "text": "豚骨ラーメン、餃子", "amount": "normal", "meal": "dinner" } },
    { "id": "…", "kind": "morningFeeling", "occurredAt": 1764000000000, "data": { "score": 4 } },
    { "id": "…", "kind": "bath",          "occurredAt": 1764000000000, "data": {} },
    { "id": "…", "kind": "caffeine",      "occurredAt": 1764000000000, "data": { "item": "コーヒー", "mg": 90 } },
    { "id": "…", "kind": "alcohol",       "occurredAt": 1764000000000, "data": { "item": "ビール 350ml", "drinks": 1 } },
    { "id": "…", "kind": "charger",       "occurredAt": 1764000000000, "data": { "state": "connected" } },
    { "id": "…", "kind": "screenUsage",   "occurredAt": 1764000000000, "data": { "cumulativeMinutes": 35 } }
  ],
  "deleted": ["<取り消した記録の id>"]
}
```

| kind | 中身 | いつ作られるか |
|---|---|---|
| `meal` | 料理名の文字、量（`small` / `normal` / `large`、任意）、食事の種類（`breakfast` / `lunch` / `dinner` / `snack`、任意） | 記録画面 |
| `morningFeeling` | すっきり度 1〜5 | 朝のレポートを開いたとき・記録画面 |
| `bath` | なし（時刻だけ） | 記録画面 |
| `caffeine` / `alcohol` | 品名と量。HealthKit にも書き込む | 記録画面 |
| `charger` | `connected` / `disconnected` | ショートカットの自動化 |
| `screenUsage` | 夜の時間帯の使用時間の合計（分） | スクリーンタイムの節目の記録（5分ごと） |

#### そのほか
| API | 内容 |
|---|---|
| `GET` / `PUT /api/settings` | タイムゾーン、目標の就寝・起床時刻、通知のオン・オフ、目安の値（CO2・湿度・室温）、機器の役割（4.2） |
| `POST /api/devices/apns` | 通知を受け取るための iPhone の識別子（デバイストークン） |
| `PUT /api/meals/:id/estimate` | 食事の目安を利用者が直したとき |

### 3.2 サーバー → アプリ（見せる）
| API | 内容 | 使う画面 |
|---|---|---|
| `GET /api/home` | 今の部屋の状態（室温・湿度・CO2・明るさ）、昨夜の要点、就寝まであと何分か | ホーム |
| `GET /api/days?from=&to=` | 1日 = 1行の表（いつもとの差つき） | 推移・夜の一覧 |
| `GET /api/nights/:date/timeline` | その夜の睡眠ステージ・心拍と、部屋の値・出来事（窓・入浴・食事・スマホ・充電）を時刻つきで | 夜の詳細 |

### 3.3 Claude Code のタスク ↔ サーバー
| API | 内容 |
|---|---|
| `GET /ai/meals/pending` | まだ目安を出していない食事の記録（料理名・量・食べた時刻だけ） |
| `POST /ai/meals/:id/estimate` | 目安を書き込む（サーバーが値の範囲を確かめる） |

## 4. サーバーの設計

### 4.1 データベースに足す表
| 表 | 中身 |
|---|---|
| `health_samples` | HealthKit の測った値（uuid ごと） |
| `health_buckets` | 5分・1時間ごとの集計 |
| `workouts` | ワークアウトの概要 |
| `user_logs` | 手入力・ショートカット・スクリーンタイムの記録 |
| `meal_estimates` | 食事の目安（生成AI か、利用者が直したもの） |
| `user_settings` | 設定（JSON） |
| `apns_devices` | 通知の送り先 |
| `day_queue` | 計算し直す必要がある日 |
| `days` | 1日 = 1行の表（値は JSON で持つ） |
| `notifications_sent` | 送った通知（同じ通知を2回送らないため） |

### 4.2 機器の役割
部屋の値を「どの機器の値として使うか」を決める。基本は機器の種類と名前から自動で決め、設定で変えられる。

| 役割 | 自動で決める方法 |
|---|---|
| `co2`（CO2・室温・湿度の主な値） | 種類が `MeterPro(CO2)` |
| `bedPresence`（在床・枕元の明るさ） | 種類が `Presence Sensor` |
| `window` / `door` | 種類が `Contact Sensor` で、名前に「窓」「window」/「ドア」「door」を含む |
| `ceilingLight` | 種類が `Ceiling Light` / `Ceiling Light Pro` |
| `curtain` | 種類が `Curtain3` |
| `purifier` / `tv` | 種類が `Plug Mini (JP)` で、名前に「加湿」「空気清浄」/「テレビ」「TV」を含む |
| `hub` | 種類が `Hub 3` |

SwitchBot アプリで機器に「窓」「ドア」「加湿空気清浄機」「テレビ」のような名前を付けておけば、設定は要らない。

### 4.3 1日 = 1行の表の計算
**いつ計算するか**: アプリからデータが届いたら、影響する日を `day_queue` に入れる。5分ごとの実行のついでに、たまった日を**数日分ずつ**計算する（無料プランは1回の処理時間が短いため。過去1年分の取り込み後は、数時間かけて全部の日を計算する）。

**1晩の区切り方**（[分析の設計の3.1](./analysis.md#31-区切り方)）
1. 睡眠ステージのうち、Apple Watch のものを使う（ほかのアプリの睡眠データは使わない）。
2. 「眠っている」区間（コア・深い・レム・不明）を、60分以内の切れ目ならつなげて1つの睡眠にする。
3. 18時〜翌朝8時に始まった睡眠のうち、いちばん長いものを「その夜」とする。日付は起きた日。
4. **布団に入った時刻**: 人感センサー Pro が、寝つく前からずっと人を検知し続けていた最初の時刻（寝つく3時間前まで）。センサーの値がなければ HealthKit の「就床」、それもなければ不明とする。

**計算する値**（いずれも [分析の設計の3.2](./analysis.md#32-列例) の列）
| 区分 | 値 | 計算のしかた |
|---|---|---|
| 睡眠 | 寝ついた時刻、起きた時刻、実睡眠時間、深い・レム・コアの時間、睡眠効率、寝つきまでの時間、中途覚醒（回数・時間） | 睡眠ステージから。中途覚醒は、眠っている区間の切れ目が2分以上のもの [TBD] |
| 睡眠中の体 | 平均心拍・最低心拍、HRV、呼吸数、血中酸素、手首皮膚温 | 寝ついてから起きるまでの値 |
| 部屋（睡眠中） | 室温・湿度・CO2（平均・最高・目安を超えた時間）、明るさ、窓・ドアを開けていた時間、加湿空気清浄機の運転時間 | データベースの集計（SQL）で出す |
| 寝る前（布団に入る前の2時間） | 照明（ついていた時間・明るさ・色温度）、消灯した時刻、テレビをつけていた時間、布団に入ったときの CO2 | 同上 |
| 寝る前の行動 | 入浴・最後の食事から就寝までの時間、夕食の目安（重さ・脂っこさ・辛さ）、夜食、カフェイン（量・最後の時刻）、飲酒、スマホを最後に使った時刻、布団の中でスマホを使っていた時間、充電器につないだ時刻 | 記録から |
| 日中（前の日に起きてから布団に入るまで） | 日光（合計・午前中）、歩数、エクササイズ、スタンド、アクティブカロリー、ワークアウト（合計・強さ・終えた時刻）、昼寝 | HealthKit の集計から |
| 翌朝 | 朝の体感、その日の安静時心拍 | 記録・HealthKit から |
| データの質 | 睡眠中に Watch のデータがあった割合、部屋のデータがあった割合 | 7割未満の夜は比較から外す（[分析の設計の7章](./analysis.md#7-間違った結論を出さないための決まり)） |

**いつもとの差（基準線）**: 表には「その日の値」だけを保存し、いつもとの差はアプリに見せるときに直近28日から計算する。過去の日を計算し直しても、差の計算がずれないようにするため。

### 4.4 通知
| 通知 | いつ | 内容 |
|---|---|---|
| 寝る前の確認 | 目標の就寝時刻の60分前（設定で変えられる） | 部屋の状態が目安を外れていれば、何をすればよいかを伝える（例:「CO2 が 1,250ppm です。寝る前に5分ほど換気しましょう」）。問題がなければ送らない [TBD] |
| 朝のレポート | 起きたことがわかり、その夜の計算が終わったあと | 実睡眠時間、寝つきまでの時間、部屋で目立ったこと（例:「CO2 が最高 1,450ppm」） |

- 睡眠中（目標の就寝時刻〜起床時刻、または在床中）は送らない。同じ通知は1日1回まで（要件定義書 FR-604・605）。
- Apple の通知の仕組み（APNs）を、サーバーから直接使う。Cloudflare Workers から送れるかは M4 の最初に確かめる [要確認]。必要なもの: Apple Developer Program で作る通知用の鍵（.p8）、鍵の ID、チーム ID、アプリの ID。

## 5. 食事の目安（Claude Code のスケジュールされたタスク）

| 項目 | 内容 |
|---|---|
| 動かす時刻 | 毎朝 5:30（日本時間）。朝のレポートの前に終わらせる |
| 手順 | ① `GET /ai/meals/pending` で目安がまだの食事を取る → ② 料理名から目安を出す → ③ `POST /ai/meals/:id/estimate` で書き込む |
| 指示書 | `server/ai/meal-estimation-task.md`（タスクに渡す文章。M3 で作る） |
| 動く場所 | クラウドの Claude Code。サーバーの URL に通信できるようにし、`AI_TASK_TOKEN` を安全に渡す設定が要る（サーバーを公開したあとに設定する） |

目安の形（サーバーが範囲を確かめる）:
```json
{
  "kcal": 850, "proteinG": 30, "fatG": 35, "carbsG": 100,
  "caffeineMg": 0, "alcoholDrinks": 0,
  "greasiness": 3, "spiciness": 1, "volume": 3,
  "confidence": "medium",
  "items": [{ "name": "豚骨ラーメン", "kcal": 650 }, { "name": "餃子（6個）", "kcal": 200 }]
}
```
`greasiness`（脂っこさ）・`spiciness`（辛さ）・`volume`（量の多さ）は 1〜3 の3段階。

## 6. iPhone アプリの設計

### 6.1 基本
| 項目 | 内容 |
|---|---|
| 対応する iOS | iOS 26 以降 |
| 作り方 | Swift / SwiftUI / Swift Charts。Xcode のプロジェクトは XcodeGen で設定ファイル（`ios/project.yml`）から作る（設定を文字で管理でき、変更点がわかりやすいため） |
| 構成 | アプリ本体と、スクリーンタイムの節目を受け取る拡張機能（DeviceActivityMonitor）の2つ。2つの間は App Group でデータを受け渡す |
| 必要な権限 | HealthKit（バックグラウンドでの受け取りを含む）、Family Controls（スクリーンタイム）、App Groups、通知（Push Notifications） |
| サーバーの URL と合言葉 | 設定画面で入力し、キーチェーンに保存する |

### 6.2 画面
| 画面 | 内容 |
|---|---|
| ホーム | 昨夜の要点、今の部屋の状態、就寝まであと何分か、朝の体感の入力 |
| 夜の詳細 | 睡眠ステージ・心拍と、CO2・室温・明るさ・在床を同じ時間軸に重ねたグラフ。窓・入浴・食事・スマホ・充電の出来事の印 |
| 推移 | 週・月ごとの睡眠と部屋の値のグラフ |
| 記録 | 食事（料理名・量）、入浴、カフェイン、飲酒。食事の目安の確認と修正 |
| 設定 | サーバーの URL と合言葉、目標の就寝・起床時刻、通知、HealthKit・スクリーンタイムの許可、データの再送 |

### 6.3 HealthKit のデータを送る仕組み
| 仕組み | 内容 |
|---|---|
| 差分の取得 | 型ごとに「前回どこまで送ったか」（アンカー）を覚えておき、新しく増えた分と削除された分だけを取る |
| バックグラウンドでの受け取り | 新しいデータが記録されたら iPhone がアプリを起こすように登録する（睡眠ステージはすぐ、そのほかは1時間ごと） |
| 集計 | 心拍数は5分ごと、歩数などは1時間ごとに集計して送る |
| 過去分の取り込み | 初回だけ、過去1年分を1か月ずつに分けて送る |
| 送れなかったとき | 送る予定のデータを端末に保存しておき、次に起きたときに送り直す |

### 6.4 充電の記録（ショートカット）
- アプリに「充電を記録」という操作（App Intent）を用意する。
- ショートカットアプリの「オートメーション」で「充電器に接続したとき」「充電器から外したとき」の2つを作り、それぞれ「充電を記録（つないだ / 外した）」を実行するようにする。設定の手順はアプリができたら書く。

### 6.5 スクリーンタイムの節目の記録
- 初回に Family Controls の許可を求め、見張る対象として「すべてのアプリとカテゴリ」を選んでもらう。
- 毎晩 20時〜翌5時の間、使用時間の合計が5分増えるたびに、拡張機能が時刻を記録する。アプリが次に起きたときにサーバーへ送る。
- 1晩に登録できる節目の数に上限があるかは [要確認]（上限があれば10分刻みにする）。
