# 作業手順書（何を・どの画面で・どうするか）

> 方針: **売買の判断は粒度の大きい足（H1・H4。銘柄ごとに学習で選ぶ）、約定の再現は M5**。
> 本番は **フィリップ・キャピタル証券の MT5 + Windows ミニPC + EA**、研究と学習は **Mac**。
> 画面の名前は MT5 の日本語表示の例。版によって少し違うことがあるので、近い名前の項目を探すこと。
> 証券会社の手続き・仕様は変わるので、各ステップで公式サイトを確認すること。

## 1. Mac の準備（ターミナル）

**画面**: Launchpad →「その他」→「ターミナル」

1. Homebrew を入れる（https://brew.sh の 1 行のコマンドを貼り付けて実行）
2. Python と Git を入れる
   ```bash
   brew install python@3.12 git
   ```
3. ツールを取得して準備する
   ```bash
   cd ~
   git clone https://github.com/bunkoko/bunkoko.git
   cd bunkoko
   git checkout claude/gracious-gates-f8a38x      # main に取り込まれるまではこのブランチ
   python3.12 -m venv .venv
   source .venv/bin/activate                      # ターミナルを開き直したら毎回これを実行
   pip install -e ".[dev]"
   pytest -q                                      # 全部 passed になること
   python scripts/train.py --demo                 # 合成データで最後まで動くこと（数分〜10分）
   ```
4. VS Code で `bunkoko` フォルダを開く（ファイル → フォルダーを開く）。以降の設定ファイルの編集はここで行う

## 2. デモ口座を申し込む（ブラウザ）

**画面**: フィリップ・キャピタル証券の公式サイト → FX → 取引ツール・ダウンロード →「Phillip MT5 デモ口座のご案内」→ 申込フォーム

1. 必要事項を入力して申し込む
2. 表示される **口座 ID・パスワード・サーバー名** を控える（メールにも届く）
3. 同じページから **Mac 版 MT5** をダウンロードしてインストール
4. **有効期限は 1 か月**。手順 4（データの書き出し）は期限内に済ませる

## 3. MT5（Mac）の初期設定

**画面**: MT5（Mac）

1. **ログイン**: ファイル → 取引口座にログイン → 口座 ID・パスワード・サーバー名
2. **履歴をたくさん持てるようにする**: ツール → オプション →「チャート」タブ →
   「チャートの最大バー数」を **Unlimited**（無制限）→ OK → MT5 を再起動
3. **銘柄を表示する**: 表示 → 気配値表示 → 一覧の上で右クリック →「すべて表示」。
   銀（XAGUSD）・金（XAUUSD）・WTI（XTIUSD）・ブレント（XBRUSD）・USD/JPY があるか確認。
   **名前が違う場合はメモ**（`config/train.toml` の `symbol_map` に追加する）
4. **銘柄仕様をメモする**: 気配値表示で銘柄を右クリック →「仕様」。各銘柄について次をメモ

   | 項目（仕様画面） | 何に使う |
   |---|---|
   | 契約サイズ | 1 ロット = 何オンス / 何バレルか |
   | 最小ロット・ロットステップ・最大ロット | 最小単位・刻み・上限 |
   | 桁数（Digits）・ティックサイズ | スプレッド列の換算（point） |
   | ストップレベル | 現在値から逆指値までの最小距離 |
   | 証拠金率（または必要証拠金） | 証拠金の計算 |
   | スワップ（買い・売り） | 金利調整額（保有コスト） |
   | 取引時間 | 毎日の休止・週末の時間 |

## 4. データを書き出す（MT5 の「銘柄」画面）

**画面**: MT5 → 表示 → 銘柄（Windows は Ctrl+U）→「チャートバー」（または「バー」）タブ

1. 銘柄を選ぶ（例: XAGUSD）、時間足を **M5**、期間を **2020/12/01 〜 今日** にして「リクエスト」
2. 表が出たら「バーをエクスポート」（「エクスポート」）→ 保存先を `bunkoko/data/`、名前を `XAGUSD_M5.csv` に
3. 同じ銘柄で時間足を **H1** にして同様に `XAGUSD_H1.csv`
4. 4 銘柄すべてで繰り返し、最後に USD/JPY の H1（`USDJPY_H1.csv`）

| 書き出すファイル | 用途 |
|---|---|
| `XAGUSD_M5.csv`, `XAUUSD_M5.csv`, `XTIUSD_M5.csv`, `XBRUSD_M5.csv` | 約定の再現（必須の方針）。H1・H4 もここから作れる |
| `XAGUSD_H1.csv`, `XAUUSD_H1.csv`, `XTIUSD_H1.csv`, `XBRUSD_H1.csv` | 売買の足（M5 より古くまで遡れることが多い） |
| `USDJPY_H1.csv` | 円換算 |

- H4・D1 は書き出さなくてよい（自動で作る）
- M5 は 1 銘柄 40 万本前後・数十 MB になる。書き出しが途中で止まる場合は **期間を分けて** 書き出し、
  `XAGUSD_M5_2021.csv`、`XAGUSD_M5_2022.csv` のように名前を付けて全部置く（自動でつなげる）
- デモのサーバーが M5 をどこまで遡れるかは「リクエスト」の結果で分かる。足りなければ本口座開設後に再取得
- フィリップの商品 CFD は 2020 年 12 月 7 日開始なので、それより前は無い

## 5. データを点検する（ターミナル）

**画面**: ターミナル（`cd ~/bunkoko && source .venv/bin/activate` の後）

```bash
python scripts/check_data.py
```

出力の読み方:

| 出力 | 意味 | 対処 |
|---|---|---|
| 「時刻: 週の始まりは…日曜夕方 → OK」「毎日の休止は 17 時台 → OK」 | サーバー時刻の読み方が正しい | – |
| ⚠「…読まれている。server_tz を X にして再点検」 | 時刻がずれている（EIA 前の停止などがずれる） | `config/train.toml` の `server_tz` を直して再実行。夏冬で 1 時間ずれるなら `"ny_close"` |
| 「売買 H1 / 約定の再現 M5（M5 は YYYY-MM-DD から…）」 | M5 が無い期間は H1 の高値・安値で推定 | そのままでよい（M5 を遡れれば改善） |
| ⚠「約定を再現する細かい足（M5）が無い」 | その銘柄の M5 を置き忘れ | 手順 4 で書き出す |
| 「スプレッド: 中央値… / 広がる時間帯…」 | M5 のスプレッド列から測った実際のスプレッド | 次の手順で設定に反映 |
| ⚠「実測スプレッドが銘柄仕様と大きく違う」 | 仕様の値が古いか、point（桁数）が違う | 手順 3 のメモと照合 |
| 「時間足ごとのコスト」 | 往復コストが損切り幅の何 % か | H1 が「不向き」なら `signal_timeframes = ["H4"]` も検討 |

## 6. コスト・仕様・指標カレンダーを反映する（ターミナル + VS Code）

1. 実測スプレッドを入れた銘柄仕様ファイルを作る
   ```bash
   python scripts/check_data.py --write-instruments config/instruments_measured.json
   ```
2. VS Code で `config/instruments_measured.json` を開き、手順 3 のメモで直す

   | 項目 | 入れる値 |
   |---|---|
   | `min_qty` / `qty_step` / `max_qty` | 最小ロット・ロットステップ・最大ロット × 契約サイズ（例: 0.1 ロット × 100oz = 10） |
   | `margin_rate` | 証拠金率（5% なら 0.05） |
   | `tick_size` / `point` | ティックサイズ / 10 の −桁数 乗（桁数 3 なら 0.001） |
   | `stop_level` | ストップレベル（ポイント）× point |
   | `financing_long` / `financing_short` | 年率コスト ≒ 1 日のスワップの支払額 ÷ 建玉金額 × 365（受け取りならマイナス） |
   | `slippage` | デモで成行を数回出し、注文時の価格と約定価格の差の平均 |
   | `verified` | 確認したら `true` |

3. `config/train.toml` の `[data]` を書き換える
   ```toml
   instruments = "config/instruments_measured.json"
   events = "config/events.csv"
   ```
4. 指標カレンダーを作る: `config/events_example.csv` をコピーして `config/events.csv` にし、
   FOMC・米 CPI・米雇用統計・祝日でずれた EIA の日時（UTC）を公式の発表予定から転記する

## 7. 学習する・レポートを読む（ターミナル + VS Code）

```bash
python scripts/train.py
```

- 4 銘柄 × 4 戦略 × H1・H4 で約 2,600 通り。M5 の Mac なら数分〜十数分の見込み
- 結果は `output/train/<日時>/`。VS Code で `report.md` を開き（右上のプレビューで表として見える）、上から順に読む

| レポートの見出し | 見るところ |
|---|---|
| 判定 | 「基準を満たした」か。満たさなければ本番に使わない |
| 検証期間の成績 | **「実際の資金・全ルールで再現」の列**（年率・最大DD・シャープ・取引回数・レバレッジ） |
| 本番用の構成 | 銘柄ごとの戦略・時間足・1回の損失。これが EA に入る |
| 期間ごとの結果 | 採用される戦略・時間足が期間ごとにばらばらでないか（ばらばらなら不安定） |
| 時間足ごとのコスト | 採用された時間足のコストが「良好」か |

**判定が満たない場合**: 設定を少しずつ変えて何度も学習し直すと、それ自体が「偶然良く見える設定探し」になる。
変えるのは根拠があるもの（実測コストの反映漏れ、明らかに不向きな時間足の除外など）だけにする。

詳しくは [roadmap.md フェーズ 4・5](roadmap.md#フェーズ-4-証券会社を決める4週目)。要点:

## 9. Windows ミニPC の準備（BIOS・Windows の設定）

**購入時の条件**: Windows 11 **Pro**（Home は遠隔操作の受け側になれない）、有線 LAN ポート、
メモリ 8GB 以上、N100/N150 クラス以上の CPU で十分

| 画面 | 設定 |
|---|---|
| BIOS（起動直後に Del か F2） | 「Restore on AC Power Loss」（AC 電源復帰時）を **Power On**（停電後に自動で起動） |
| 設定 → システム → 電源 | 画面を消す: 任意 / **スリープ: なし** |
| 設定 → アカウント → サインイン オプション | 「Windows Hello サインインのみを許可する」を **オフ** |
| Win+R → `netplwiz` | 「ユーザーがこのコンピューターを使うには…」のチェックを外す → パスワード入力（**自動ログイン**） |
| 設定 → システム → リモート デスクトップ | **オン**（PC 名をメモ） |
| 設定 → Windows Update → 詳細オプション | アクティブ時間を「手動」で 0〜23 時など広めに（勝手な再起動を減らす） |
| 設定 → 時刻と言語 | 「時刻を自動的に設定する」オン |
| ネットワーク | 有線 LAN で接続。ルーターで IP を固定しておくと遠隔操作が楽 |

**Mac からの遠隔操作**: App Store で「Windows App」を入れる → PC を追加 → PC 名（または IP）→ Windows のユーザー名・パスワード

**MT5（Windows）**: フィリップのサイトから Windows 版 MT5 を入れてログイン（試運転はデモ、本番は本口座）。
手順 3 の「チャートの最大バー数 = Unlimited」もここで設定。
**自動起動**: Win+R → `shell:startup` → 開いたフォルダに MT5 のショートカットを置く

## 10. EA を入れる（MetaEditor・MT5 Windows）

1. **EA を置く**: MT5 → ファイル →「データフォルダを開く」→ `MQL5\Experts` に
   `mql5/Experts/CfdCommodityEA.mq5` をコピー（Mac から Windows App のドライブ共有かクラウド経由で渡す）
2. **コンパイル**: MT5 のツールバーの MetaEditor（または F4）→ ナビゲータで `CfdCommodityEA.mq5` を開く →
   「コンパイル」（F7）→ 下の「エラー」タブが **エラー 0** か確認。
   **エラーが出たら、その内容をコピーして送ってください**（この環境ではコンパイルを確認できていない）
3. **学習結果を置く**: 学習結果の `ea/*.txt` を **共通フォルダ** に置く。
   場所: MT5 → ファイル →「データフォルダを開く」→ 1 つ上の階層 → `Common` → `Files`
   （`%APPDATA%\MetaQuotes\Terminal\Common\Files`）。
   指標カレンダーも `cfdbot_events.csv` という名前でここに置く
4. **自動売買を許可**: MT5 → ツール → オプション →「エキスパートアドバイザ」タブ →「アルゴリズム取引を許可」にチェック。
   ツールバーの「アルゴリズム取引」ボタンを押して **緑** にする
5. **チャートを開く**: 学習結果の `ea/` にあるファイルごとに 1 枚。気配値表示で銘柄を右クリック →「チャート表示」→
   時間足を **ファイル名の末尾の時間足**（例: `cfdbot_SILVER_donchian_H1.set` なら H1）にする
6. **EA を貼る**: ナビゲータ →「エキスパートアドバイザ」→ `CfdCommodityEA` をチャートへドラッグ →
   - 「パラメータの入力」タブ →「読み込み」→ 該当の `.set` を選ぶ
   - 続けて次を手で設定

     | 項目 | 値 |
     |---|---|
     | `ea_magic` | チャートごとに別の番号（2609001, 2609002, …。上 4 桁は全チャート同じにする） |
     | `ea_param_file` | `.set` と同じ名前の `.txt`（例: `cfdbot_SILVER_donchian_H1.txt`） |
     | `ea_risk_scale` | デモでは 1.0、本番開始時は 0.25〜0.5 |
     | `ea_push_notify` | true |
   - 「共通」タブ →「アルゴリズム取引を許可」にチェック → OK
7. **確認**: チャート右上の EA 名の横のアイコンが有効表示になっていること。
   下の「ツールボックス」→「エキスパート」タブに `CfdCommodityEA start …` と `loaded N params …` が出ていること。
   時間足が違うと「このパラメータは N 分足用」と警告が出て止まる

## 11. EA と Python の突き合わせ（ストラテジーテスター → Mac）

1. **画面**: MT5（Windows）→ 表示 → ストラテジーテスター（Ctrl+R）
2. 設定: エキスパート = CfdCommodityEA、銘柄、時間足（ファイル名どおり）、期間 = 直近 1 年、
   モデル =「1 分足 OHLC」、初期証拠金 = 1,000,000 JPY
3. 「パラメータの入力」で `.set` を読み込み、**`ea_log_signals` を true** にして「スタート」
4. 終わったら共通フォルダ（手順 10-3）の `cfdbot_signals_<MT5の銘柄名>_<magic>.csv` を Mac の
   `bunkoko/output/compare/` にコピー
5. Mac のターミナルで比べる
   ```bash
   python scripts/compare_signals.py --final output/train/<日時>/final.json --symbol SILVER \
       --ea-log output/compare/cfdbot_signals_XAGUSD_2609001.csv
   ```
6. 「結果: 一致」になれば OK。差分が出たら出力をそのまま送ってください（原因を直す）

## 12. 通知の設定（iPhone・MT5 Windows）

1. iPhone の MT5 アプリ → 設定 →「チャットとメッセージ」（「メッセージ」）→ 表示される **MetaQuotes ID** を控える
2. MT5（Windows）→ ツール → オプション →「通知」タブ →「プッシュ通知を有効にする」にチェック → MetaQuotes ID を入力 →「テスト」
3. iPhone に届けば OK。EA は発注・決済・発注拒否・停止を通知する
4. （任意）n8n に送る: n8n の Webhook ノードの URL を EA の `ea_webhook_url` に入れ、
   ツール → オプション →「エキスパートアドバイザ」→「WebRequest を許可する URL」にも追加

## 13. デモで実運用（1〜3 か月）

**毎週やること**:

1. MT5（Windows）→ ツールボックス →「口座履歴」タブで先週の取引を確認（右クリックでレポート保存も可）
2. Mac で最新のデータを書き出し直して（手順 4）、同じ期間を再現する
   ```bash
   python scripts/replay.py --final output/train/<日時>/final.json --start <EA を動かし始めた日>
   ```
   出力の取引一覧（日本時間）と MT5 の口座履歴を比べる。エントリーの有無・方向・決済理由がおおむね同じならよい。
   価格の差はスプレッド・スリッページ分だけのはず
3. iPhone の通知に「発注拒否」「決済失敗」「停止」が無いか

**期間中に一度は確認すること**: Windows を再起動しても MT5・EA が自動で再開し、二重に発注しないか /
週末・EIA 発表前に新規が止まるか / LAN ケーブルを抜いて戻したときの挙動

**デモの期限（1 か月）**: 切れる前に再申込みし、新しい口座で MT5 にログインし直す（EA の設定はそのまま）

## 14. 少額で本番

1. MT5（Windows）→ ファイル → 取引口座にログイン → **本口座**
2. 各チャートの EA の設定（チャート上で右クリック → エキスパートアドバイザ → 設定）で **`ea_risk_scale` を 0.25〜0.5**
3. 3 か月ほど、手順 13 と同じ毎週の確認を続ける。想定の範囲（取引回数・勝率・最大 DD）に収まっていれば 1.0 に戻す
4. **全停止した場合**（高値から 25% 下落で新規停止）: 通知が来る。原因を確認してから、
   MT5 → ツール → グローバル変数（F3）で `cfdbot.g2609.halt` を削除すると再開する

## 15. 毎月の運用（30 分）

1. MT5 から M5・H1 を書き出し直して `data/` を上書き（手順 4）
2. `python scripts/check_data.py` → 注意が増えていないか
3. 指標カレンダー（`config/events.csv`）に翌月分を追加
4. `python scripts/train.py` → `report.md` の判定と本番用の構成を、前回と比べる
5. 変化が小さければ `ea/*.txt` を Windows の共通フォルダに上書き（EA は 60 分ごとに読み直す）。
   **戦略・時間足・銘柄の組み合わせが変わった場合** は、手順 10 のチャートの貼り直しが必要
6. 年 1 回: 確定申告（CFD の損益は申告分離課税。FX などと損益通算でき、損失は 3 年繰り越せる）

## 困ったとき

| 症状 | 確認すること |
|---|---|
| EA が何もしない | ツールバーの「アルゴリズム取引」が緑か / エキスパートタブのエラー / 時間足がファイル名と同じか |
| エキスパートタブに `not enough bars` | ツール → オプション → チャート →「チャートの最大バー数」が Unlimited か |
| 「発注拒否」の通知 | 証拠金不足・最大ロット超え。証拠金率の変更が無いか公式のお知らせを確認 |
| 学習で「失敗 N 件」 | 表示されたエラーの例をそのまま送ってください |
| `check_data.py` で時刻の注意 | 手順 5 の表のとおり `server_tz` を直す |
| 突き合わせで差分 | 記録の最初の方だけなら EA の `ea_calc_bars` を増やす。それ以外は出力を送ってください |
