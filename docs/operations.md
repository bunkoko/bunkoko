# 作業手順書（Windows なしで進める版）

> 方針: **売買の判断は粒度の大きい足（H1・H4。銘柄ごとに学習で選ぶ）、約定の再現は M5**。
> **Windows は用意しない**。データ取得・学習・EA のコンパイルとテスト・デモの試運転はすべて **Mac 版 MT5**
> （中身は Windows 版 MT5 を Wine で動かしたもの。EA・ストラテジーテスター・MetaEditor が使える）で行い、
> 本番の 24 時間運用は **MQL5 VPS**（MT5 のメニューから借りる仮想サーバー。月 15 ドル前後）に任せる。
> 画面の名前は MT5 の日本語表示の例。版によって少し違うことがあるので、近い名前の項目を探すこと。
> 証券会社・MQL5 VPS の手続きや料金は変わるので、各ステップで公式サイトを確認すること。

## 構成

| 役割 | どこで | 補足 |
|---|---|---|
| データの書き出し・EA のコンパイル・ストラテジーテスター | Mac 版 MT5 | スクリプト `CfdExportBars` で全銘柄を一括で書き出す |
| 点検・学習・比較 | Mac のターミナル（＋ iPad） | 今までどおり |
| デモの試運転（1〜3 か月） | Mac 版 MT5 | Mac をスリープさせない。止まっても逆指値は証券会社側にあるので、困るのはシグナルの見逃しだけ |
| **本番の 24 時間運用** | **MQL5 VPS** | Mac の MT5 から「移行」するだけ。移した後は Mac を閉じてよい |
| 監視 | iPhone・iPad の MT5 アプリ（通知・建玉）、Mac の MT5（VPS のログ） | – |

### MQL5 VPS の制約と、その対策（EA とツールで対応済み）

| MQL5 VPS の制約 | そのままだと困ること | 対策 |
|---|---|---|
| 共通フォルダのファイルは移らない | パラメータの `.txt`・指標カレンダーの CSV を EA が読めない | **プリセット（.set）に全部入れる**。指標の日時は `ea_events_utc_1〜3` に 4 か月分（最大 42 件）。`scripts/mt5_files.py install` が自動で書く |
| グローバル変数は移らない | DD 停止の基準（最高資産）・建玉ごとの初期損切り幅が消える | **EA が口座履歴から復元**（最高資産 = 確定損益の最高値。初期損切り幅 = 建てたときの注文の逆指値） |
| 移行するには Mac の「アルゴリズム取引」がオンである必要があり、移行すると自動でオフになる | 平日に移行すると、その間だけ Mac と VPS の両方で動きうる | **移行は市場が閉まっている週末（土曜の朝以降）に行う**。移行後に Mac の「アルゴリズム取引」を押さない |
| 設定の変更は「移し直し」で反映 | 毎月のパラメータ更新 | 毎月 1 回、週末に Mac でプリセットを読み込み直して移行（手順 16） |
| ログは VPS 側にある | Mac の「エキスパート」タブには出ない | ナビゲータの仮想サーバーを右クリック →「ジャーナル」 |
| シグナル記録の CSV を取り出せない | – | EA と Python の突き合わせは Mac のテスターで行う。本番の確認は口座履歴と `replay.py` |

## 1. Mac の準備（ターミナル）

**画面**: ターミナル（⌘ + スペース で Spotlight を開き「ターミナル」と入力して Enter）

Homebrew が入っていれば、次をまとめて貼り付けて Enter するだけ。Python 本体とパッケージは `bunkoko` フォルダの中
（`.python` と仮想環境 `.venv`）だけに入り、Mac 全体には入らない（Homebrew で入るのは道具の `uv` だけ）。

```bash
cd ~ && git clone https://github.com/bunkoko/bunkoko.git && cd bunkoko && git checkout claude/gracious-gates-f8a38x && ./cfd setup
```

- 中でやること: uv を入れる → Python 3.12 と仮想環境を作る → パッケージを入れる → テスト → 合成データで学習の動作確認
- **終わったと言える状態**: 最後に「準備完了」と出る（10〜15 分）。途中で止まったら、表示をそのまま送ってください
- 以降のコマンドはすべて `cd ~/bunkoko` のあと **`./cfd <コマンド>`**（仮想環境の Python で動くので activate は不要。一覧は `./cfd help`）
- 新しい版を取り込むときは `./cfd update`
- Homebrew が無い場合は https://brew.sh の 1 行を実行し、最後に出る「Next steps」の行も実行してから上を実行

## 2. デモ口座を申し込む（ブラウザ）

**画面**: フィリップの公式サイト（phillip.co.jp）→ CFD の MT5 のページ（証券CFD・商品CFD のフィリップMT5）→
デモ口座の申込フォーム

1. 名前・メールアドレスなどを入力 →「確認画面」→「申込」（本人確認書類は不要）
2. メールで届く **ログイン ID・パスワード・サーバー名** を控える（サーバーは本番・デモとも `PhillipSecuritiesJP-PROD` と案内されている）
3. 同じページの「MacOS 版ダウンロード」から zip を落とす → ダブルクリックで解凍 →「MetaTrader 5.pkg」をダブルクリック →
   画面の指示どおりインストール（初回の起動は時間がかかることがある）。
   M シリーズの Mac で「Rosetta をインストール」の案内（Apple のサポートページ 102527）が出たら「インストール」を押す
   （Mac 版 MT5 は Windows 版を Intel 用の互換レイヤーで動かしているため Rosetta が要る。ターミナルなら
   `softwareupdate --install-rosetta --agree-to-license`）
4. **有効期限は 1 か月**。手順 5（データの書き出し）は期限内に済ませる

**Mac 版 MT5 の操作の注意**: メニュー（ファイル・表示・ツール…）は Mac の画面上端ではなく **MT5 のウィンドウの中** にある。
ショートカットは Windows と同じく **control** キー（⌘ ではない）。F4・F7 などは **fn** を押しながら

## 3. MT5 の初期設定（MT5）

1. **ログイン**: ファイル → 取引口座にログイン → ログイン ID・パスワード・サーバー →「ログイン」。
   気配値表示の価格が動けば OK
2. **履歴を全部持てるようにする**: ツール → オプション →「チャート」タブ →
   「チャートの最大バー数」を **Unlimited**（無制限）→ OK → **MT5 を終了して起動し直す**
3. **銘柄を表示する**: 表示 → 気配値表示 → 一覧の上で右クリック →「すべて表示」。
   銀（XAGUSD）・金（XAUUSD）・WTI（XTIUSD）・ブレント（XBRUSD）・USD/JPY があるか確認。
   `XAGUSD.ps01` のような後ろに記号が付いた名前でよい（ツールが自動で対応する）。
   **同じ銘柄が 2 つ以上ある場合や、まったく違う名前の場合だけ** 実際の名前を送ってください

銘柄の仕様（契約サイズ・最小ロット・証拠金率・スワップなど）と口座の種類（ネッティング/ヘッジング）は、
手順 5 のスクリプトが自動で書き出し、手順 6 で設定に反映する。「仕様」画面を見てメモする必要は無い。

## 4. EA とスクリプトを入れてコンパイル（ターミナル → MetaEditor）

Mac 版 MT5 のフォルダは `~/Library/Application Support/…/drive_c/…` の奥にあって Finder では探しにくいので、
ツールが自動で探してファイルを置く。

1. **ターミナル**: MT5 の場所を確認
   ```bash
   ./cfd where
   ```
   `[0]` のデータフォルダが、MT5 → ファイル →「データフォルダを開く」で開く場所と同じならよい
   （違うときは以降のコマンドに `--terminal 1` などを付ける）
2. **ターミナル**: EA とスクリプトを置く
   ```bash
   ./cfd mt5
   ```
3. **MetaEditor**: MT5 → ツール →「MetaQuotes Language Editor」（fn + F4）→ 左のナビゲータ →
   `Experts` の `CfdCommodityEA.mq5` をダブルクリック →「コンパイル」（fn + F7）→ 下の「エラー」タブが **0 errors** か確認
   （warnings は出てもよい）。同じように `Scripts` の `CfdExportBars.mq5` もコンパイル。
   **エラーが出たら、「エラー」タブの内容を全部コピーして送ってください**（この環境ではコンパイルを確認できていない）
4. **MT5**: ナビゲータ（表示 → ナビゲータ）の「エキスパートアドバイザ」に `CfdCommodityEA`、
   「スクリプト」に `CfdExportBars` が出ること（出なければ右クリック →「更新」）

## 5. データを書き出す（MT5 のスクリプト）

1 本ずつ書き出す代わりに、スクリプトで全銘柄・全時間足と銘柄仕様・口座情報をまとめて書き出す（毎月の更新もこれで行う）。

1. **MT5**: 何かのチャートを 1 枚開く（気配値表示で XAGUSD を右クリック →「チャート表示」など。銘柄は何でもよい）
2. ナビゲータ →「スクリプト」→ `CfdExportBars` をチャートへドラッグ →「パラメータの入力」タブで確認 → OK

   | 項目 | 値 |
   |---|---|
   | `symbols` | `XAGUSD,XAUUSD,XTIUSD,XBRUSD`（そのままでよい。`XAGUSD.ps01` のような名前は自動で探す） |
   | `timeframes` | `M5,H1` |
   | `fx_symbol` | `USDJPY`（円換算用。H1 だけ書き出す） |
   | `from_date` | `2020.12.01`（フィリップの商品 CFD は 2020 年 12 月 7 日開始） |

3. 下の「ツールボックス」→「エキスパート」タブに 1 ファイルずつ結果（本数・期間・サーバーの履歴の最初の日）が出て、
   最後に「9 / 9 ファイルを書き出した」と表示される。M5 は履歴のダウンロードで数分かかる
   （スクリプトはサーバーにある最初の日まで取れるのを待つ。1 ファイル最大 5 分）
4. 結果の行の末尾を見る

   | 表示 | 意味 | 対処 |
   |---|---|---|
   | 何も無い | 指定日（2020/12/01）から全部取れた | – |
   | 「サーバーの履歴がこの日から」 | サーバーにそれより前が無い | そのままで可 |
   | ⚠「最大バー数で頭打ち」 | MT5 の「チャートの最大バー数」の制限 | 手順 3 の Unlimited にして MT5 を再起動し、もう一度実行 |
   | ⚠「ダウンロードが終わっていない」 | 待ち時間内に取り切れなかった | もう一度実行（続きから取れる） |

- H4・D1 は書き出さなくてよい（自動で作る）。MT5 はどの時間足も M1 の履歴から作るので、M5 と H1 は同じ期間まで遡れるはず
- 手で書き出す場合（スクリプトが使えないとき）: 表示 → 銘柄 →「バー」タブ → 銘柄・時間足・期間 →「リクエスト」→
  「エクスポート」。保存先の選択では、Mac のフォルダは **Z: ドライブ**（Mac の `/` と同じ）から
  `Users/<名前>/bunkoko/data` を辿る。名前は `XAGUSD_M5.csv` の形にする

## 6. データを取り込み、点検し、銘柄仕様を作る（ターミナル）

```bash
./cfd data
```

中でやること: 書き出したファイルを `data/` に取り込む → 点検 → MT5 の銘柄仕様と実測スプレッドから
`config/instruments_measured.json` を作る → この Mac だけの設定 `config/local.toml` に登録（学習がこれを使う）。

**出力を全部送ってください**。読み方と、直す必要があれば設定の修正はこちらで行う。参考までに主な出力:

| 出力 | 意味 |
|---|---|
| 「口座: … / ネッティング（またはヘッジング）」 | 口座の種類・レバレッジ・デモか本口座か |
| 「仕様（MT5 から）: 契約…、最小…、証拠金率…、保有コスト…」 | 自動で反映した銘柄仕様 |
| 「時刻: … → OK」 | サーバー時刻の読み方が正しい（⚠ なら `server_tz` を直す） |
| 「スプレッド: 中央値… / 広がる時間帯…」 | M5 のスプレッド列から測った実際のスプレッド |
| 「時間足ごとのコスト」 | 往復コストが損切り幅の何 % か（H1 が「不向き」なら H4 だけにする） |

- `config/local.toml` と `config/instruments_measured.json` は git で管理しない（`./cfd update` で最新版を取り込んでもぶつからない）
- スリッページ（`slippage`）だけは仮の値のまま。デモで実測できたら反映する

## 7. 指標カレンダーを確認する

`config/events.csv` に、2027 年 1 月までの FOMC・米 CPI・米雇用統計・祝日でずれた EIA の日時（UTC）を用意してある
（公表済みの予定から作成。「推定」と付いたものは公式の予定が出たら直す）。設定（`config/train.toml` の `events`）も済み。
毎月の更新（手順 16）で 4 か月先まで追加する。

## 8. 学習する・レポートを読む（ターミナル + VS Code）

```bash
./cfd train
```

- 4 銘柄 × 4 戦略 × H1・H4 で約 2,600 通り。M5 の Mac なら数分〜十数分の見込み
- 結果は `output/train/<日時>/`。`report.md` を VS Code やテキストエディタで開き（VS Code なら ⌘K → V で表として見える）、
  上から順に読む。**最初は `report.md` を丸ごと送ってください**（一緒に読む）

| レポートの見出し | 見るところ |
|---|---|
| 判定 | 「基準を満たした」か。満たさなければ本番に使わない |
| 検証期間の成績 | **「実際の資金・全ルールで再現」の列**（年率・最大DD・シャープ・取引回数・レバレッジ） |
| 本番用の構成 | 銘柄ごとの戦略・時間足・1回の損失。これが EA に入る |
| 期間ごとの結果 | 採用される戦略・時間足が期間ごとにばらばらでないか（ばらばらなら不安定） |
| 時間足ごとのコスト | 採用された時間足のコストが「良好」か |

**判定が満たない場合**: 設定を少しずつ変えて何度も学習し直すと、それ自体が「偶然良く見える設定探し」になる。
変えるのは根拠があるもの（実測コストの反映漏れ、明らかに不向きな時間足の除外など）だけにする。

## 8b. 学習が基準に届かないとき: 調整しない定番ルールで進める（ターミナル）

2026-10 の実データでは、学習（H4・H4+日足）は検証期間で基準に届かず、
数値をいじらない定番のトレンドルール（`config/baselines/turtle55_d1.json`: 55 日ブレイクで入り 20 日で手仕舞い、日足、4 銘柄）
のほうが成績が良かった。この場合は学習結果ではなく、この構成で進める。

さらに外部データの検証（[cross_asset.md](cross_asset.md) 6 章）で、「直近 20 日ですでに大きく動いた向き（ふだんの 1.5 倍超）には
入らない」が先物 20 年・フィリップ 5 年・使っていない 3 市場のすべてで効いたので、**今の構成は
`config/baselines/turtle55_d1_ext.json`**（資金 100 万円・1 回の損失 1.5%: シャープ 0.80・年率 6.4%・最大DD 9.0%・最悪の月 −2.6%）。
以下のコマンドの `turtle55_d1` は `turtle55_d1_ext` に読み替える。

1. 資金と 1 回の損失ごとの成績を比べる
   ```bash
   ./cfd table --final config/baselines/turtle55_d1.json --start 2021-06-01
   ```
   最大DD が停止（25%）より十分小さく、最悪の月を受け入れられる組み合わせを選ぶ
   （2026-10 の結果では資金 100 万円なら 1 回の損失 1.5%: シャープ 0.65・最大DD 14%）
2. 選んだ値を保存する（合計・グループの上限も同じ比率で上がる）
   ```bash
   ./cfd risk 0.015 --equity 1000000
   ```
3. EA のプリセットを作って MT5 に置く（手順 9 の 1. の代わり）
   ```bash
   ./cfd preset config/baselines/turtle55_d1.json
   ```
   以降の手順 9〜16 は、`output/train/<日時>/final.json` を `output/live/turtle55_d1/final.json` に読み替える
   （`./cfd ea` の代わりに `./cfd preset config/baselines/turtle55_d1.json`、本番開始時は `--risk-scale 0.5` を付ける）

## 9. プリセットを置き、EA と Python を突き合わせる（ターミナル → ストラテジーテスター）

1. **ターミナル**: 学習結果からプリセットを作って MT5 に置く
   ```bash
   ./cfd ea
   ```
   （最新の学習結果を使う。）最後に出る **「チャートと EA の対応」表** を控える（プリセット名・チャートの銘柄・時間足・magic・指標の件数）。
   プリセットには戦略のパラメータに加えて magic・リスク倍率・指標の日時まで入っているので、**手で直す項目は無い**
2. **MT5**: 表示 → ストラテジーテスター → 「設定」タブ

   | 項目 | 値 |
   |---|---|
   | エキスパート | `CfdCommodityEA` |
   | 銘柄・時間足 | 表の「チャート」「時間足」 |
   | 期間 | 直近 1 年（遅ければ半年） |
   | モデル | 「1 分足 OHLC」 |
   | 初期証拠金 | 1,000,000 JPY |

3. 「パラメータの入力」タブ → 表の上で右クリック →「読み込み」→ 表のプリセット名の `.set`
   （テスター用。シグナル記録 `ea_log_signals` がオンになっている）→「スタート」
4. 表の全行（銘柄）について 2〜3 を繰り返す（テスターの銘柄・時間足とプリセットを替えて「スタート」）
5. 終わったら **ターミナル**: 記録を取り込んで全銘柄をまとめて比べる
   ```bash
   ./cfd compare output/train/<日時>/final.json      # 定番ルールなら output/live/turtle55_d1/final.json
   ```
6. 最後の「まとめ」が全銘柄「一致」になれば OK。差分が出たら出力をそのまま送ってください

## 12. デモで実運用（1〜3 か月）

**毎週やること**:

1. MT5 → ツールボックス →「口座履歴」で先週の取引を確認（iPhone の MT5 アプリの「履歴」でも見られる）
2. 最新のデータを書き出して（手順 5 のスクリプト → `./cfd data`）、同じ期間を再現する
   ```bash
   ./cfd replay --start <EA が判断した最初の足の日付> --equity <デモ口座の開始時の資産>
   ```
   （`--start` は、ログの最初の `… の足を判断` の日付。平日に貼るとふつうは前の日の足。今のデモは下の「今の照らし合わせの指定」。
   `./cfd preset` で最後に置いた構成を使う。デモ口座は仮想資金が本番より大きいので、`--equity` で口座の金額に合わせる。
   EA は口座の資産から数量を決めるため）
   出力の取引一覧（日本時間）と口座履歴を比べる。エントリーの有無・方向・決済理由がおおむね同じならよい。
   価格の差はスプレッド・スリッページ分だけのはず。Mac が止まっていた期間の差は気にしない
3. EA のログと Python を 1 日ずつ照らし合わせる（2 と同じ `--start`・`--equity`）
   ```bash
   ./cfd demo-check --start 2026-10-07 --equity 10000000
   ```
   EA がエキスパートタブに毎日書く `… の足を判断: 終値 … → …、保有 N` の行（MT5 のデータフォルダの
   `MQL5/Logs/<日付>.log`。自動で探す）を、同じデータ・同じ構成の Python と比べる。見るもの:
   EA の記録が抜けた日（Mac のスリープなど）・終値・シグナルの有無と向き・行き過ぎの値・保有数、
   `発注拒否`・`決済失敗`・`order failed`・`entry rejected`・`stale bar`・最大DD などの行。
   最後に「一致／差あり」と差の理由の候補、下の「本番に進む条件」のうち数えられる分を出す
   （`output/demo_check/<日時>/report.md`）。`--start` は、その口座で EA が判断した最初の足の日付。
   書き出したときにまだ途中だった最後の足は比べず、次の書き出しで比べる。最初の足をまだ EA が判断していなければ
   「まだ比べられない」と出る。VPS に移したら、移した日までの Mac のログ（`MQL5/Logs/YYYYMMDD.log`）を別のフォルダに
   コピーし、VPS のログ（日付ごとのファイルのまま）のフォルダと **2 つ並べて** `--logs <Mac の分> <VPS の分>` に渡す
   （同じ名前のファイルがあっても両方読む。移した後の Mac のログは入れない。Mac の MT5 を開いたままだと
   EA が判断の行を書き続け、二重判断に数えられる）

   **今の照らし合わせの指定**（口座の切り替え・確かめ直しのたびに、ここを書き換える）:
   `--start 2026-10-07 --equity 10000000`（`--count-from` なし）。2026-10-15 に 10-06 から書き換えた: ログの最初の判断の行は
   10-07 の足（毎日の判断の行は 10-07 夕方の更新で入り、10-06 の足は前の版の EA が行を書かずに判断した）。この間の売買は無い
4. iPhone の通知に「発注拒否」「決済失敗」「停止」が無いか

### 本番に進む条件（事前登録: 2026-10-13、デモの照らし合わせの結果を見る前に決めた。結果を見てから変えない）

デモは 2026-10-06 から（構成 `config/baselines/turtle55_d1_ext.json`）。数え方は `./cfd demo-check` の「本番に進む条件」と同じ
（`scripts/demo_check.py` の先頭の定数）。「足」は銘柄ごとの日足 1 本（フィリップは土曜の朝までの短い足もある）、
「照らし合わせた足」は EA の判断の行と Python の両方がある足。数えるのは、開始日（`--start`。確かめ直しでは `--count-from`）
以降の足と、その最初の足を EA が判断した日（ふつうは翌日の 0 時）以降に書かれたログの行だけ（それより前のログは、
前の足・直す前・前の口座のものなので数えない）。書き出したときに途中だった足は比べない。

| # | 条件 | 数え方 |
|---|---|---|
| 1 | 期間 | 開始日からログの最後の日まで **28 日以上**、かつ照らし合わせた足の日付が **20 日以上**。書いた日が分からないログ（名前に日付が無く、行にも日時が無い）があれば満たさない |
| 2 | 記録の抜け | 抜けた足 ÷（照らし合わせた足 ＋ 抜けた足）が **10% 以下**（全銘柄で数える。EA の行が 1 つも無い銘柄はその足が全部抜け）、かつ **最後の 5 日に抜けが無い**。抜け = 次の足がログの最後の日までに始まっているのに、EA の判断の行が無い足。書いた日が分からないログがあれば満たさない |
| 3 | 終値・シグナル・行き過ぎ | 照らし合わせた足の **すべてで一致**。終値は EA の表示桁の半分以内、シグナルは有無と向き、行き過ぎの値は 0.006 以内（EA は小数 2 桁で書くため） |
| 4 | 保有数 | 照らし合わせた足の **すべてで一致**。ただし抜けた足の後、次に一致する足までは数えない（EA は止まっていた間の足を処理しないため）。数えない差は report に「数えない保有数の差」と出し、「一致／差あり」の判定にも入れない |
| 5 | 要確認の行 | 発注の失敗（`order failed`）・発注拒否・決済失敗・損切りの変更の失敗・最大DD での停止・足が足りない・設定の読み込みの問題・時間足違い・同じ足の二重判断が **0 件** |
| 6 | 取引 | EA のエントリー（判断の行の保有数が増えた回数、全銘柄）が **2 回以上** |
| 7 | 目で確認（数えない） | 口座履歴の各取引が `./cfd replay` の取引と、銘柄・向き・入った日・決済の理由で一致し、価格の差がスプレッド・スリッページ程度。再起動・週末と指標前の新規停止・通知の 3 つを各 1 回確かめ、日付を下に記録する |

- 1〜7 をすべて満たしたら、`--risk-scale 0.5` で本番（手順 14・15）へ進む
- 差（3・4）や要確認の行（5）が出たら本番に進まない。原因を直し（または原因を説明できると確かめ）、
  `--start` はそのままで `--count-from <直した日>` を足し（週末や月曜の朝 7 時より前に直したら、その前の土曜の日付）、直した日から **2 週間（14 日・照らし合わせた足 10 日）** を
  新しく確かめる（Python の再現は開始日から続けるので、持っている建玉もそのまま比べられる）。前の report.md は残す。
  直す前の失敗（発注拒否など）で建玉がずれたまま数え始めた場合、そのずれ（4 の保有数）は、次に一致する足まで数えない
  （抜けた足の後と同じ扱い）。上の「今の照らし合わせの指定」に `--count-from` を書き足す
- **12 週（2026-12-29）までに 6 が 2 回に届かないとき**: 1〜5・7 を満たしていれば `--risk-scale 0.25` で本番へ進む
  （55 日の高値・安値を抜けたときだけ入る戦略なので、取引が少ないこと自体は異常ではない）
- デモ口座の再申し込み（11 月初め）で口座が替わったら、新しい口座では保有が 0 から始まるので、
  `--start <新しい口座で EA が最初に判断した足の日付> --equity <新しい口座の資産>` で照らし合わせる
  （週末にログインし直すので、ふつうは土曜の日付。ログで新しい口座の最初の `… の足を判断` の日付を確かめる）。
  前の口座の分は `--end <古い口座の最後の足の日付>` を付けて report.md を作って残し、
  1（期間）と 6（取引）は 2 つの口座を足して数える。2〜5 はそれぞれの口座の期間で満たすこと。
  上の「今の照らし合わせの指定」を新しい口座の値に書き換える
- 2026-10-14 補足（照らし合わせの結果を見る前。基準の数値は変えていない）: 実物のログ（土曜の短い足を月曜の朝に判断する）と
  点検に合わせて、数える範囲（開始日より前のログ・途中の足・EA の行が無い銘柄・直す前から続く保有数のずれ）と、
  確かめ直し（`--count-from`）・口座の切り替え・VPS のログの渡し方を明確にした。あわせて、Python の再現（`./cfd replay` と
  demo-check）が開始日より前の過去を約 3 か月しか使っておらず、行き過ぎの絞り込み（252 本の値動きを使う）が開始から
  数十本のあいだ効いていなかったのを直した（EA と同じく、手元の過去を全部使う）

確かめた記録（日付と結果を足していく）:

## 14. MQL5 VPS を借りて本番を移す（MT5 のナビゲータ。**週末に行う**）

**準備**:

- mql5.com でアカウントを作る（無料）。支払い方法（カードなど）を用意
- MT5 → ツール → オプション →「コミュニティ」タブ → MQL5.com のログイン名・パスワードを入れる

**手順**（土曜の朝以降、市場が閉まっている間に）:

1. MT5 → ファイル → 取引口座にログイン → **本口座**
2. **ターミナル**: 本番用の設定とプリセットを作る（1 回の損失を半分にして始める）。
   1 回の損失 2%・最大の下落での停止 40% は、利用者が 2026-10-23 に決めた値（`docs/leverage.md` 5 章。デモは 1.5%・25% のまま）
   ```bash
   ./cfd table --final config/baselines/turtle55_d1_ext.json --start 2021-06-01 --equity <本口座の資金> --risk 0.01,0.02
   ./cfd risk 0.02 --equity <本口座の資金> --dd-halt 0.40
   ./cfd preset config/baselines/turtle55_d1_ext.json --risk-scale 0.5
   ```
   1 行目で「最小単位で見送り」が多ければ、資金が小さくて最小単位（金 1 オンスなど）でも損失が上限を超える。
   その銘柄はほとんど入れないので、資金を増やすか、そのまま進めるかを決めてから 2 行目へ
3. **MT5**: 手順 11 と同じく、表の行ごとにチャートを開いて EA を貼り、プリセットを読み込む
   （デモのチャートを使い回す場合は、チャートを右クリック → エキスパートアドバイザ → 設定 →「読み込み」）。
   **EA を貼ったチャート以外は閉じる**（開いているチャートは全部移る）
4. ツールバーの「アルゴリズム取引」ボタンが **緑** であること（オフだと EA が移らない）
5. ナビゲータ →「口座」の本口座を右クリック →「仮想サーバーを登録」（版によって「仮想ホスティング」）→
   遅延の小さいサーバーが自動で選ばれる → 期間（まず 1 か月）→ 支払い
6. 続く移行の画面で「エキスパートとインジケーター」（または「すべて」）を選んで **移行** → 完了の表示
7. 移行が終わると Mac の「アルゴリズム取引」は **自動でオフ** になる。
   **以後、Mac でこのボタンを押してオンにしない**（Mac と VPS の両方で発注してしまう）
8. **確認**: ナビゲータの口座の下に出る仮想サーバーを右クリック →「ジャーナル」→ 各チャートの
   `CfdCommodityEA start …`・`loaded N events`・`DD 停止の基準（最高資産）= …` が出ていること
9. Mac は閉じてよい（VPS が動かす）。月曜の朝、iPhone の MT5 アプリで注文・建玉が二重になっていないか確認

- Mac 版 MT5 に「仮想サーバーを登録」が出ない・移行できないときは、下の「別の選択肢」へ
- 料金・最大チャート数などは MQL5 の公式ページで確認（チャートは 4〜5 枚なので上限には余裕がある）

## 15. 少額で本番

1. 手順 14 で `--risk-scale 0.5`（1 回の損失 2% の半分 = 1%）で始めている。慎重にするなら 0.25
2. 毎週、手順 12 と同じ確認を続ける（ログは VPS のジャーナル）
3. 3 か月ほど、想定の範囲（取引回数・勝率・最大 DD）に収まっていれば、週末に
   `./cfd preset config/baselines/turtle55_d1_ext.json`（`--risk-scale` なし = 1 回の損失 2%）でプリセットを作り直して読み込み、移し直す
4. **全停止した場合**（高値から 40% 下落で新規停止。2026-10-23 に 25% から変えると決めた）: 通知が来る。原因を確認し、再開すると決めたら、
   `config/local.toml` の `[account]` に `peak_since = "2027-03-06"`（再開する日）を書き、週末に
   `./cfd ea …` でプリセットを作り直して読み込み、移し直す。それより前の高値を DD の基準にしなくなる
   （VPS では停止の記録を直接消せないため、この方法で基準を測り直す。以後もこの値は消さずに残す）

## 16. 毎月の運用（週末に 45 分）

1. **MT5（Mac）**: `CfdExportBars` を実行（手順 5）→ **ターミナル**: `./cfd data` → 注意が増えていないか
2. 指標カレンダー（`config/events.csv`）を **4 か月先まで** 追加
3. `./cfd train` → `report.md` の判定と本番用の構成を、前回と比べる
4. 問題なければプリセットを作り直す（`--risk-scale` は今の値）
   ```bash
   ./cfd ea --risk-scale 0.5
   ```
   ⚠ が出たら（指標カレンダーの残りが少ない等）直してから進む
5. **MT5（本口座）**: 各チャートを右クリック → エキスパートアドバイザ → 設定 →「読み込み」→ 新しいプリセット → OK。
   銘柄・戦略・時間足の組み合わせが変わったら、表に合わせてチャートの時間足を変える・閉じる・開く
   （magic は銘柄ごとに固定なので、戦略が変わっても保有中の建玉は新しい設定で管理が続く）
6. 「アルゴリズム取引」ボタンを **オン** → すぐにナビゲータの仮想サーバーを右クリック →「移行」→ 完了すると Mac 側は自動でオフ
   （週末なので、オンの間に Mac が発注することは無い）
7. VPS のジャーナルで開始を確認。VPS の契約期間（自動更新）も確認
8. 年 1 回: 確定申告（CFD の損益は申告分離課税。FX などと損益通算でき、損失は 3 年繰り越せる）

## 困ったとき

| 症状 | 確認すること |
|---|---|
| `./cfd where` が MT5 を見つけない | MT5 を一度起動してから再実行。それでもだめなら MT5 → ファイル →「データフォルダを開く」で場所を確かめ、`--mql5 <そのフォルダ>/MQL5 --common <…>/MetaQuotes/Terminal/Common/Files` で指定 |
| `CfdExportBars` で「銘柄が見つからない」 | 気配値表示の「すべて表示」で名前を確認し、`symbols` と `config/train.toml` の `symbol_map` を直す |
| `CfdExportBars` で ⚠「最大バー数で頭打ち」 | 「チャートの最大バー数」を Unlimited にして MT5 を再起動し、もう一度実行 |
| `CfdExportBars` で ⚠「ダウンロードが終わっていない」 | もう一度実行する（回線が遅いときは `wait_sec` を増やす） |
| EA が何もしない（デモ） | 「アルゴリズム取引」が緑か / エキスパートタブのエラー / 時間足が表と同じか |
| EA が何もしない（VPS） | VPS のジャーナルのエラー / 移行時に「アルゴリズム取引」が緑だったか（オフで移行すると動かない → 週末にオンにして移し直す） |
| 注文が二重になった | Mac の「アルゴリズム取引」がオンになっていないか（VPS に移した後はオフのまま） |
| エキスパートタブに `not enough bars` | 「チャートの最大バー数」が Unlimited か |
| 「発注拒否」の通知 | 証拠金不足・最大ロット超え。証拠金率の変更が無いか公式のお知らせを確認 |
| 学習で「失敗 N 件」 | 表示されたエラーの例をそのまま送ってください |
| `check_data.py` で時刻の注意 | 手順 6 の表のとおり `server_tz` を直す |
| 突き合わせで差分 | 記録の最初の方だけなら EA の `ea_calc_bars` を増やす。それ以外は出力を送ってください |
| `install` で「指標カレンダーの最後の予定が…」 | `config/events.csv` に翌月以降の FOMC・CPI・雇用統計を追加して、もう一度 `install` |

## 別の選択肢（Windows が必要になったら）

> **macOS 28 に注意**: Apple は macOS 28（2027 年の予定）で Rosetta をほぼ廃止すると発表している。今の Mac 版 MT5 は
> Rosetta で動いているので、MetaQuotes が対応版を出すまでは **macOS 28 に上げない**（手順 10 で自動アップデートは止めてある）。
> 本番は MQL5 VPS で動くので影響しないが、データの書き出し・コンパイル・VPS への移行に Mac 版 MT5 を使っている。
> 対応版が出なければ、下の Windows の VPS（Mac の Windows App から操作）か、Parallels などの Windows 11（ARM 版）に移す

MQL5 VPS が使えない・合わない場合の代わり。どちらも、中で動かすのは Windows 版 MT5 で、手順 4・9・11 はほぼ同じ。

| 方法 | 費用の目安 | 向いている場合 |
|---|---|---|
| **Windows の VPS を借りる**（FX・MT5 向けのもの） | 月 2,000〜4,000 円程度 | MQL5 VPS が使えない／パラメータファイルの自動読み直し（`ea_param_file`）やログのファイルを使いたい |
| Windows ミニ PC | 2〜4 万円 | 手元に置きたい（停電・回線断への備えが自分の責任になる） |

- Windows の VPS は、Mac の **Windows App**（App Store）で接続して操作する。グローバル変数・共通フォルダが
  そのまま使えるので、移し直しの手間は無い（パラメータは `.txt` を置き換えれば EA が 60 分ごとに読み直す）
- 停止後の再開は、チャートの EA の `ea_peak_since` に再開する日（`2027.03.06` の形）を入れ、
  MT5 → ツール → グローバル変数（F3）で `cfdbot.g2609.peak` と `cfdbot.g2609.halt` を削除する
