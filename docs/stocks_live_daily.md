# 日本株の予行演習: 毎日の手順（iPhone で見る 1 枚）

> 決まりの全部は `docs/stocks_live.md`。ここは、やることだけを短く書いた（2026-10-15）。
> **空運転（練習）の間は、注文は出さない。** 知らせの一覧を見て、「出したつもり」で 1 章の 2〜4 をなぞる。

## 1. 平日の流れ

1. **13:10 ごろ**: iPhone に「株の予行演習（今日の注文）」の知らせが来る（空運転の間は「空運転: 出すはずの注文」）。
   来ない日は、Claude に「今日の株の注文は？」と聞く。「今日は出す注文なし」なら、何もしない
2. **13:30 までに（遅くとも 13:50 まで）**: SBI 証券のアプリで、知らせの上から順に注文する。売りを先に、買いを後に
   - 買い: 銘柄の番号で探す →「S 株」の「買」→ 注文の画面
   - 売り: 持っている株の一覧（か銘柄の番号）→「S 株」の「売」→ 注文の画面
   - アプリの言葉が違ったら、いちばん近いものを選ぶ。分からなければ、画面の写しを Claude に送る
3. 注文の画面で、次のとおりにする
   - 市場: 東証（最初から選ばれているまま）
   - **預り区分: 必ず「特定」**（「NISA」が選ばれていることがあるので、毎回見る。NISA で持っているキオクシア HD・ディスコ・レーザーテックは予行演習では買わないので、売りの画面で NISA の株が出てきても触らない）
   - 株数: 知らせの株数
   - 価格: 成行
   - 執行条件: なし。期間: 当日中
4. **送信の前に見比べる 3 つ**: ① 銘柄の番号（4 けた） ② 買いか売りか ③ 株数。合っていたら送信する（取引のパスワードを聞かれたら入れる）
5. 間違えて送ったら: 14:00 より前なら、注文の照会から取り消す（直すことはできないので、取り消して出し直す）。約定してしまったら、そのまま Claude に伝える
6. 「受注停止」などで注文できない株があったら、その株は飛ばして、Claude に「○○は受注停止」と伝える
   - 売りが受注停止だったら: その日の **16:00 より後**に、同じ株の売りを出す（次の営業日の朝 9:00 の値段で売れる）
7. **夕方（15:30 より後）**: 約定の結果を Claude に伝える（言い方は 2 章）

## 2. Claude への伝え方

| こうなったら | こう言う（例） |
|---|---|
| 約定した | 「約定: 7203 買い 3 株 2,850 円」（何件でも。約定の画面の写しを送るのがいちばん確か） |
| 約定しなかった（失効した） | 「7203 は約定しなかった」 |
| 注文できなかった（受注停止） | 「7203 は受注停止」 |
| 今日は出さない | 「今日の注文は全部出さない」（一部だけ出さないのは誤りになる。出すなら全部） |
| 間違えた | 「7203 を 30 株で買ってしまった」など、そのまま |
| 明日の 13 時台に出せない | 「明日売る株を朝の売りにする」→ 今日の 16:00 より後に売りを出す |
| 止めたい | 「株の予行演習を止めて」（新しく買わない。持っている株は予定の日に売る）。再開は「予行演習を再開して」 |
| 様子を知りたい | 「予行演習の様子は？」 |
| 知らせが来ない | 「今日の株の注文は？」と「知らせが来ない」 |

## 3. 週に 1 回（たとえば金曜の夕方か週末）

1. Claude に「予行演習の様子は？」と聞く（記録上の資産・誤りの回数・止める決まり・練習の進み具合が分かる）
2. SBI のアプリで、持っている株（S 株・特定）が、Claude の記録と同じかを見比べる
3. 予行演習の外で、同じ口座で株を買った・売ったなら、その番号を Claude に伝える（その株は予行演習では買わない）
4. （約定の履歴の取り込みができてから）Mac の前で、SBI の約定の履歴を CSV で書き出す

## 4. 月に 1 回

1. SBI の口座の現金が、予行演習の金額（30 万円）より多くなっていないかを見る（多いと、押し間違えたときの金額の上限が大きくなる。余った分は銀行へ）
2. 取引の履歴で、予行演習の株を「NISA」で買っていないか（預り区分の間違い）を見る
3. 月の取引の報告の損益と、Claude の記録が大きく違わないかを、Claude と見る

## 5. 知らせの設定（最初に 1 回。Mac の前で）

- Claude が案内する。設定は、このリポジトリの外の `~/.bunkoko/notify.json` に書く（ほかの人が読めないよう、権限は 600）。**設定が無ければ、何も送らない**
- 知らせ方は差し替えられる。試す順番（調査役の第 4 回）:
  1. **Mac の「メッセージ」で自分あてに送る**（無料。Apple のサーバーだけを通る）。1 週間試して、iPhone で鳴らなければ次へ

     ```json
     {"enabled": true, "channels": [{"type": "imessage", "to": "自分の電話番号（+8190…）か Apple ID のメール"}]}
     ```

  2. **Mac の「メール」で自分あてに送る**（パスワードは要らない。iPhone のメールの通知を ON にする）

     ```json
     {"enabled": true, "channels": [{"type": "mailapp", "to": "自分のメールアドレス"}]}
     ```

  3. **Pushover**（iPhone のアプリが 4.99 ドルの買い切り。送るのは月 10,000 通まで無料。注文の一覧が海外のサービスを通る）

     ```json
     {"enabled": true, "channels": [{"type": "pushover", "token": "アプリのトークン", "user": "利用者のキー"}]}
     ```

- 作ったら `./cfd agents orders --notify-test` で試す。初めてのとき、Mac が「"ターミナル"（か "osascript"）が "メッセージ"（か "メール"）を操作することを
  許可しますか」と聞いたら「許可」を押す。13:05 の自動実行で送れないときは、システム設定 → プライバシーとセキュリティ → オートメーション で
  許可されているかを見る（この流れは、分析役が Mac で確かめていない）
- 1 回の送信は 60 秒で打ち切り、だめなら 1 回だけやり直す。それでもだめなら記録（`data/agents/live/notify.log`）に残し、13:05 の流れは止めない
- 注文の無い日は送らない（送ってほしければ設定に `"send_empty": true` を足す）
- ntfy の公開サーバー（話題の名前を知る人なら読める）と、終わった LINE Notify は使わない

## 6. 時刻のまとめ（SBI の S 株取引ルール。2026-10-15 に利用者が写した公式の文）

| 注文を出す時刻 | 約定する値段 |
|---|---|
| 0:00〜7:00（休みの日の注文も） | その日（次の営業日）の 9:00 の値段（前場始値） |
| 7:00〜10:30 | その日の 12:30 の値段（後場始値。予行演習では使わない） |
| **10:30〜14:00** | **その日の 15:30 の値段（終値）← 毎日の注文はここ** |
| 14:00〜24:00 | 次の営業日の 9:00 の値段（朝の売りに使う。16:00 より後に出す） |

- 締めの時刻のすぐ後の注文は、前の時間の扱いになることがある → **13:50 までに出す。目安は 13:30 まで**
  （権利付最終日などは、13:30 から注文を受けない株がある。古い案内には「13:30 まで」と書いたものもある）
- 14:00〜16:00 の注文は、夕方の計算で失効することがある → 朝の売りは 16:00 より後に出す
