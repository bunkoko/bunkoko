# 統計と研究を、元の資料で確かめて台帳に入れる

台本で数字や研究を語れるのは、config/stats.csv と config/findings.csv に人が確かめて入れた行だけです（D-034・D-035）。
候補は Claude が探して下書きにし、あなたはスマホのページで元の資料と見比べて押すだけにしました。

## 分担

| | Claude | あなた |
|---|---|---|
| 国・公的機関・国際機関の統計 | 元の資料（役所のページ・PDF）を開いて、数字の載った表と行を書き写した下書きを作る。別の調べ役がもう一度開いて確かめる | 元の資料を開いて、数字・単位・誰のうちの数か・調査の年が同じなら「合っている」 |
| 誰でも読める論文（CC BY・CC0） | 記事のページでライセンスを確かめ、結果の節を読んで、研究の一文・限界・調べた人の下書きを書く | 論文の本文の結果で確かめ、取り下げ・訂正が無いのを見て「合っている」。言い方を直してもよい |
| 民間の調査（会社・シンクタンク） | 題・発行元・URL・引用の決まりのページだけを集める（中身は開かない） | 引用の決まりを読み、数字を1つ選んで、何の数字かをあなたの言葉で書いて「入れる」 |
| 有料の論文・CC BY でない論文 | 書誌と URL だけを集める（本文も要旨も開かない） | 本文を読み、あなたの言葉で一文・限界・調べた人を書いて「入れる」 |

- 民間の調査と有料の論文の本文・要旨は、ページにもチャットにも貼りません。あなたが書いた数字と言葉と書誌だけが台帳に入ります。
- 「違う」「使わない」を押した行は、台帳に入りません。

## スマホで押す

1. Claude が載せたページ「統計と研究の確かめ」を開きます。上の一覧で種類を選べます。
2. 1件ずつ、「元の資料を開く」で元のページを開いて見比べます。戻ってきてページが読み直されても、書きかけの欄と押した結果はスマホに残ります。
3. 数字や言い方が少し違うときは、「数字や言い方を直す」を開いて直してから「合っている」を押します。
4. 統計に「増え方も元の資料で確かめた」の印があるときは、同じ調査・同じ設問で、毎回増えて（減って）いるのを見たときだけ印を付けます。印が無ければ、台本で「増え続けています」とは言いません。
5. 電波が無いところでも押せます。電波が戻ると送ります。
6. 押し終わったら、Claude に「確かめた結果を取り込んで」と伝えます。

## 取り込んだあと（Mac）

Claude が台帳に書いて GitHub に入れたら、Mac で SSD に入れます。

```sh
cd /Users/bunkoko/koten
git pull
uv run koten db init
uv run koten findings build
uv run koten findings list
```

## 仕組み（Claude の作業）

- 下書き：docs/research/ の JSON（形は src/koten/sources/check.py の先頭）。
- ページを作る：`uv run koten sources page --drafts docs/research/2026-11-21-source-drafts.json`（data/sources-page.html）。アーティファクト「統計と研究の確かめ」に載せる。
- 押した結果：ページのデータベースの checks/<キー>。キーは下書きの中身から作るので、下書きを直した行は押し直しになります。
- 取り込む：データベースを JSON にして `uv run koten sources merge --drafts docs/research/2026-11-21-source-drafts.json --from その JSON`。
  - 統計は、押した日・場所（表やページ）を stats.csv の where・checked_by・checked_at に残します。下書きに replaces がある行は、置き換える行をあなたが確かめたときだけ、古い行（転載サイトを出典にした行など）を外します。
  - 研究は status を verified、verified_from を full_text、retraction_checked_at と checked_at を押した日にします。
  - どちらかの台帳が決まり（`koten db init`・`koten findings build` と同じ確かめ）に合わなくなるなら、どちらも書かずに止まります。
