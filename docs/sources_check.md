# 統計と研究を、元の資料で確かめて台帳に入れる

台本で数字や研究を語れるのは、config/stats.csv と config/findings.csv の行だけです（D-034・D-035）。
候補は Claude が探して下書きにし、AI の見直し役が元の資料を開き直して確かめます。
あなたが確かめるのは、**実際の回で使った行だけ**です（2026-11-24 利用者）。

## 台帳の行の3つの状態

| 状態 | 統計（stats.csv） | 研究（findings.csv） | 台本で使えるか | 承認 |
|---|---|---|---|---|
| あなたが確かめた | checked_by が「オーナー」 | status が verified | 使える | そのまま承認できる |
| AI が確かめた | checked_by が「AI（調べ役と見直し役）」 | status が ai_checked（CC BY・CC0 の論文だけ） | 使える | **回で使ったら、承認の前にあなたが確かめる** |
| 使わない | status が 保留 | status が draft | 使わない | ― |

- 企画は、あなたが確かめた統計を先に使います（確かめる手間を減らすため）。
- 民間の調査と有料の論文は、AI が中身を読めないので、あなたが数字や一文を書くまで台帳に入りません。
- 統計の「増え方」（trend）は、あなたが元の資料で確かめたときだけ入ります（AI だけの行には入れない）。

## 分担

| | Claude | あなた |
|---|---|---|
| 国・公的機関・国際機関の統計 | 元の資料（役所のページ・PDF）を開いて、数字の載った表と行を写した下書きを作る。別の見直し役がもう一度開いて確かめる | 回で使ったときに、該当ページの画像（数字に印）で見比べて「合っている」 |
| 誰でも読める論文（CC BY・CC0） | 記事のページでライセンスを確かめ、結果の節を読んで、研究の一文・限界・調べた人を書き、本文の該当の文を写す | 回で使ったときに、該当の文（印つき）で見比べて「合っている」 |
| 民間の調査（会社・シンクタンク） | 題・発行元・URL・引用の決まりのページだけを集める（中身は開かない） | 引用の決まりを読み、数字を1つ選んで、何の数字かをあなたの言葉で書いて「入れる」 |
| 有料の論文・CC BY でない論文 | 書誌と URL だけを集める（本文も要旨も開かない） | 本文を読み、あなたの言葉で一文・限界・調べた人を書いて「入れる」 |

- 民間の調査と有料の論文の本文・要旨は、ページにもチャットにも貼りません。あなたが書いた数字と言葉と書誌だけが台帳に入ります。

## 回で使った行を確かめる（承認の前）

確認画面（review.html）に「人が元の資料で確かめていない統計・研究」と出たら、その回で使った AI の行が残っています。

1. Mac で、確かめが要る行を書き出して GitHub に入れます。

   ```sh
   cd /Users/bunkoko/koten
   uv run koten sources todo --episode E20261107-01
   git add docs/checks
   git commit -m "確かめが要る行"
   git push
   ```

2. Claude に「E20261107-01 の確かめのページを作って」と伝えます。その回で使った行だけのページが、アーティファクト「統計と研究の確かめ」に載ります。
3. スマホで押します。
   - 統計：元の資料の該当ページの画像に、数字の載った行（黄色）と数字（赤い枠）の印があります。台本に入る文と同じなら「合っている」。「元の資料の○ページを開く」で、PDF のそのページも開けます（iPhone ではページに飛ばないことがあるので、ページの番号を見て探します）。
   - 研究：論文の該当の文（英語の原文。数字に印）が出ます。台本に入る形と合っていれば、2つの印を付けて「合っている」。「論文の該当の文を開く」で、論文のその文に飛んで印が付きます。
4. Claude に「確かめた結果を取り込んで」と伝えます。押した行が「あなたが確かめた」になって GitHub に入ります。
5. Mac で取り込み、確認画面を作り直します。

   ```sh
   cd /Users/bunkoko/koten
   git pull
   uv run koten db init
   uv run koten findings build
   uv run koten review --episode E20261107-01
   ```

- 確かめるときに数字や一文を直したら、動画の音声が古いままになります。確認画面に「音声のあとで、台本に入る文が変わった」と出たら、`uv run koten produce --episode E20261107-01 --from voice` で作り直します。

## 系列のカード（e-Stat の年ごとの数）

e-Stat の複数年の数（docs/stat_series.md）は、統計・研究とは別の「系列」のカードで確かめます。確かめるのは1系列ずつです。

- カードに出るもの：
  - 読む文（今の値の文）。
  - 元の資料の言葉：
    - API の系列：統計名・作った機関・表の題（表番号）・調査の年月・更新日・公開日・statsDataId と、選んだ分類（「分類名：項目名」）。台帳の単位の隣に、e-Stat の単位（選んだ項目の単位と、数に付いた単位）。
    - ファイルの系列：statInfId・シート・更新日（下書きの updated）・見出しのセルの文字。台帳の単位の隣に、単位のセルの文字。
  - 年ごとの数の表。抜けた年・mark・変わり目に印が付きます（見出しの分からない部分の境も変わり目）。つないだ境の年には「▲ここから見出しの言い方が変わる（同じ問いとしてつないだ）」が付きます（区切りの印より細い線）。
  - つないだ境（下書きの joins。docs/stat_series.md の「見出しの言い方だけが違う年の境（joins）」）があれば、「同じ問いとしてつないだ境（見出しの言い方だけが違う年）」：年と前と後の言い方（「2023年から：「…」→「…」」）と、根拠。使っていないつなぎには「（使っていない：わけ）」。
  - ファイルの系列は、ファイルのその部分の抜き出し。数のセルが赤、年・見出し・単位のセルが黄色です。大きい表は、数の行と年の行の表と、見出しの小さい表に分けて出します。
  - e-Stat の表・ファイルへのリンク。
  - 固定の1行：「数はプログラムが e-Stat から写した。確かめるのは、何の数か・分類・変わり目・読む文」。
  - 保留の系列には「保留中」。
- 見るのは、何の数か・分類・変わり目・読む文です。数そのものは見比べません。単位は、台帳の単位と e-Stat の単位（単位のセル）が同じかを見ます。
- つないだ境を使っている系列には、印「つないだ境の根拠も読んで、同じ問いだと確かめた」が出ます。前と後の言い方と根拠を読み、同じ問いだと思えば印を付けて「合っている」。印を付けずに「合っている」を押すと、つながずに入ります（その年で区切る）。
- **直せるのは言葉（label）だけ**です。数は直せません。数が違うと思ったら、「違う」を押して Claude に伝えます。
- 台帳にある系列のカードで「違う」を押すと、その系列は保留になります（台本で使わず、数も取りません。メモは台帳に残ります）。保留の系列で「合っている」を押しても、保留のままです。
- 数がまだ取れていない系列（`stats fetch` の前）は、「合っている」を押せません。先に Mac で `uv run koten stats fetch` を行います。
- `sources page` でファイルの抜き出しを出すには、`KOTEN_CONTACT`（メールアドレスか URL）が要ります。無いときは、その系列の表を出さずに黄色の知らせが出ます（ページは作れます）。クラウドの Claude は、個人の情報を含まない汎用の連絡先 `KOTEN_CONTACT=https://claude.com/claude-code` を使います（R10）。

## 新しい候補をまとめて入れる

Claude が新しく調べた下書きは、あなたが押さなくても、AI が確かめた行として台帳に入れられます（`--accept-rest`）。押した行はあなたが確かめた行、「違う」を押した行は入りません。

## 仕組み（Claude の作業）

- 下書き：docs/research/ の `<日付>-source-drafts.json`（統計・研究・民間の調査・有料の論文・統計の系列が1つのファイル。形は src/koten/sources/check.py の先頭。系列の項目は docs/stat_series.md の「下書きの系列の項目」）。
- 該当箇所を探す：`KOTEN_CONTACT=https://claude.com/claude-code uv run koten sources locate --drafts docs/research/2026-11-21-source-drafts.json --passages 研究の文の JSON`（クラウドの連絡先は個人の情報を含まない汎用のもの。R10）
  - 統計：元の資料の PDF を net.py で取り（data/sources-cache）、写した行が載っているページを探して画像にし、行と数字に印を付けます（data/sources-img。Git に入れない）。表の行は、写した数字をいちばん多く含み、統計の数字も含む見た目の行を選びます。PDF の場所は doc_url（index のページを出典にした行）、文字を取り出せない PDF は page_hint のページを印なしで出します。
  - 研究：調べ役が写した結果の文が、論文の本文にそのままあるかを net.py で取り直して確かめ、無い文は外します。
  - 道具：pdftotext・pdftoppm（poppler）と ffmpeg、日本語の PDF を読むための poppler-data（`apt-get install -y poppler-data`。無いと字が出ない・取り出せない）。ページを作るのは Claude の環境だけです。
  - 画像は2枚：数字のまわりの拡大（赤い枠が数字、黄色が行）と、ページの中の場所（押すと大きくなる）。
- ページを作る：`uv run koten sources page`（下書き全部）／ `--todo docs/checks/E20261107-01.json`（その回の行だけ。文と数字は今の台帳、場所と画像は下書きから）。画像はページの隣の img/ に置いて、アーティファクトに一緒に載せます。
- 押した結果：ページのデータベースの checks/<キー>。キーは下書きの中身から作るので、文を直した行は押し直しになります。
- 取り込む：データベースを JSON にして `uv run koten sources merge --from その JSON`（`--todo` を付けると、その回の行だけ。新しい候補をまとめて入れるときは `--accept-rest`。押した結果が無いときは `{}` だけの JSON を渡す）。
  - あなたが確かめた行を、AI が確かめた行で上書きしません。
  - 下書きに replaces がある行は、置き換える行を入れたときに古い行（転載サイトを出典にした行など）を外します。
  - どちらかの台帳が決まり（`koten db init`・`koten findings build` と同じ確かめ）に合わなくなるなら、どちらも書かずに止まります。
