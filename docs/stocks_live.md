## やさしい要約

1. **何を**: 会社が利益の見通しを 5% 以上引き上げた株（E1）を 1 株単位で少しずつ買い、5 営業日後に売る。注文は iPhone で手で出す
2. **何のため**: 本物の注文にかかるコストを測ることと、注文の失敗を小さい金額のうちに経験すること。儲けは目的にしない
3. **いくら**: 30 万円（10〜50 万円で選べる）。予行演習の口座には、この金額だけを入れる
4. **最悪いくら**: 借りずに株を買うだけなので、失うのは多くても入れた金額まで
5. **毎日**: 平日の 13:10 ごろ、iPhone に「今日の注文」の知らせが来る（設定した後。来なければ Claude に「今日の株の注文は？」と聞く）。
   一覧のとおりに、13:30 までを目安に注文する（多い日で 10 件ほど。手順は `docs/stocks_live_daily.md`）
6. **止める**: 「止めて」と言えば止まる。資産が 2 割減った・注文の誤りが 2 回あった、などのときも自動で止まる
7. **始める前に**: 注文を出さない練習（空運転）を 2 週間ほど（E1 が 10 行出るまで）する。SBI の受付の時間は確かめた（14:00 までの注文がその日の終値）

## 2. 何を買うか

### 2.1 第 1 案: E1 の帳を、そのまま（手で注文できる数に絞るだけ）

- E1 の帳: 通期の純利益の会社予想を 5% 以上引き上げた開示の後の株（`docs/agents.md` 10.2・12.2）。平日 13:05 の自動実行が書く。
  数字は開示の翌日から集まるので、買うのは多くの場合、開示の翌営業日以降の引け（台帳の紙の上の買いと同じ日）
- 選ぶ理由
  1. **数が少ない**。過去の検証では 1 日に平均 2.0 銘柄、何か持っている日は 41%（`docs/agents.md` 10.5）。手で注文できる
  2. **紙の上の帳と 1 対 1 で比べられる**。同じ株・同じ日の「紙の上の損益（公式の終値で）」と「口座の損益」を並べれば、差がそのまま
     コストと失敗の大きさになる
- 帳から変える所（手で注文できるようにするため。どれも結果を見る前に決めた）
  1. **1 日 5 銘柄まで**。多い日（決算の季節には 1 日に何十社も出る見込み）は、日付（YYYYMMDD）を種にしたでたらめで 5 つ選ぶ
     （`cfdbot/agents/decider.py` の `random_pick` と同じ作り。名前の順に並べてから選ぶので、後から同じ 5 つを確かめられる）。
     予想の引き上げ幅の大きい順に選ばないのは、ストップ高で買えない株にかたよって、コストの測定がゆがむため
  2. **株数は 1〜99 株**。1 銘柄の金額（3.1）÷ 前の営業日の終値を切り捨てる。0 株になる株（1 株が高い）と、100 株以上になる株
     （1 株が安い。100 株以上はふつうの注文になり、S 株ではない）は買わない（理由を記録する）
  3. **持っている株にまた E1 が出たら**（売る日でも、その前でも）、買い足さずに持ち続け、**売る日を新しい判断の日から 5 営業日後**にする。
     株数は今のまま。記録では、その日の終値で売って同じ株数を買ったとみなし、コストの測定には数えない。注文が減り、差金決済
     （同じ日の売りの代金で同じ株を買い直すこと。禁止されている）の心配も無くなる。S 株の「同じ日・同じ預り区分・同じ銘柄は、
     発注のタイミングごとに買い・売り 1 件まで」の決まりにも当たらない
  4. **予行演習の外ですでに持っている株は買わない**（2026-10-15 に足した）。S 株取引ルールでは、S 株を買って同じ銘柄の合計が 100 株以上に
     なると、その分は S 株として売れなくなる。利用者が同じ口座（特定の預り）で持っている株を `./cfd agents orders --setup --exclude 7203,6758` で教え、
     一覧には「すでに持っている株」と出る。持っている株が変わったら教え直す（`docs/stocks_live_daily.md` の週 1 回）
- 紙の上の E1 の帳（台帳）は今までどおり全部の株を数える。予行演習は、帳の一部を本物の注文で確かめるだけ

### 2.2 M2 はなぜ後か

- M2（銘柄選定の上位 10%）は毎日 約 49 銘柄を買い、約 49 銘柄を売る。**手では出せない**
- 1 株から注文できる API は、Mac で使えるものが 1 つも確かめられなかった（調査役の第 3 回 1 章）
- 100 株単位なら API で出せる見込みがあるが、TOPIX500 の株は 100 株で数十万円になることが多く（推測: 1 株 3,000〜4,000 円なら 30〜40 万円）、
  49 銘柄を 5 日分持つと 1 億円近くになる。**今の形の M2 は、個人の少額では実行できない**
- だから M2 は、(1) 1 株単位で注文できる API が見つかる、または (2) 銘柄の数を減らした形を別の仮説として事前登録して検証する、
  のどちらかの後。どちらも今はしない

## 3. 金額・口座・止める決まり・増やさない決まり

### 3.1 金額

- **口座に入れる金額（X）**: **30 万円**（チームの案）。利用者は 10〜50 万円で選ぶ。50 万円は `docs/agents.md` 12.4 の「少額」
  （1 つの帳につき 50 万円まで）と同じで、予行演習はこれを超えない。**余剰資金**（なくなっても暮らしに困らないお金）で
- **1 日に新しく買う金額（D）**: **X ÷ 7**（30 万円なら 42,857 円）。S 株取引ルールでは、成行の買いは「株数 × 制限値幅の上限の値段」
  （前の日の終値に、1 日に動ける幅を足した値段。幅は株価により約 15〜50%）で買付余力を拘束し、約定の後に差が戻る。5 日分（5D）を持ったまま、
  その日の引けで売る分の代金を待たずに、新しい買いが D の 1.5 倍を拘束しても、5D ＋ 1.5D ＝ 6.5D ≤ 7D ＝ X で足りる。
  （2026-10-15 に X ÷ 6 から直した。始める前の直しで、結果は何も見ていない。10 章）
- **1 銘柄の金額**: D ÷ その日に買う銘柄の数（5 銘柄なら 8,571 円、2 銘柄なら 21,428 円）。株数は 2.1 の 2 のとおり
- 道具は、買いごとに「株数 ×（前の終値 ＋ 制限値幅）」を記録上の現金から引いていき、足りなければその株は買わない（「買付余力が足りない見込み」と出す。
  制限値幅の表は `cfdbot/agents/live.py` の `PRICE_LIMITS`。分析役が東証の表を知識で書いたもので、公式の表で確かめる）
- 当日に値上がりしても、値幅制限（1 日に動ける幅）があるので、計画どおりの注文なら 1 日の約定の金額が D の 1.5 倍を超えることは無い
- D は**始めたときの X** で計算する。儲かっても損しても途中で変えない
- 現物だけ。信用取引・空売りはしない。**だから、失うのは多くても口座に入れた X まで**（持っている株が全部 0 円になった場合。ふつうはその一部）

### 3.2 口座の分け方（誤った注文の上限を X にするため）

誤って押した注文の上限は、X ではなく**その口座の買付余力**（買うのに使えるお金）になる。S 株は 1 回に 99 株まで出せるので、
1 株 3 万円の株なら 1 回の押し間違いで約 300 万円になりうる。だから:

- **勧める形**: 予行演習の口座は、**NISA の口座と別の証券会社**（NISA が SBI 以外なら、SBI の口座を予行演習だけに使う）にし、
  **入れるのは X だけ**。ほかの現金・株・投資信託を置かない
- **NISA も SBI にある場合**（同じ口座しか無い場合）: 少なくとも次を守る
  1. 口座の現金（買付余力）が X を超えないようにする。積み立ての代金はクレジットカードか銀行からの引き落としにし、使わない現金は銀行に戻す
  2. 注文の画面で、**預り区分が「特定」**であることを毎回見る（「NISA」で買うと、枠を使ってしまい、損が他と差し引けない）
  3. 送信の前に、**銘柄・株数・金額・預り区分**を `./cfd agents orders` の一覧と 1 つずつ見比べる。迷ったら、画面の写しを Claude に送って確かめてもらう
- どちらの場合も、予行演習とは別の売買（NISA の積み立てなど）は、その日の予行演習の注文を出し終えてからにする

### 3.3 止める決まり

`./cfd agents orders` を開くたびに（注文を出す日は毎日）、下の表を確かめ、当たれば STOP を置く（本物のときだけ。空運転では「本物なら止める」と出す）。

| 何が起きたら | どうする |
|---|---|
| `data/agents/live/STOP` を置いた（利用者が「止めて」と頼んだとき。消すまで） | 新しく買わない。持っている株は予定の日に売る |
| 記録上の資産（現金＋持っている株を最新の終値で）が、X の 80% を下回った | STOP を置く（上と同じ） |
| 注文の誤りが、直近 20 営業日に 2 回 | STOP を置き、原因を 10 章に書く |
| 1 回の買いの約定の金額が、D の 1.5 倍を超えた（押し間違い） | すぐ STOP を置き、その株は次に約定できる時点で売る |
| 往復が済んだ最初の 10 回の c（5.1）の平均が、往復 0.10% を超えた（S 株の差が大きい） | STOP を置く（6 章の条件を満たせないことが分かったため） |
| 売りが約定しない日（ストップ安の配分など）が、予定の日から 5 営業日を超えた | STOP を置き、利用者に相談する（それまでは毎日、同じ形で売りを出す） |
| 持っている株の値段が 2 営業日続けて無い、または上場廃止・売買停止・TOB（株を買い取る申し出）の発表を見た | STOP を置き、利用者に相談する |
| E1 の帳が `docs/agents.md` 12.3 で閉じた | 新しく買わない（予行演習を終える） |
| 5.3 で c* が決まった | 予行演習の 1 回目を終える。同じ金額で続けるかは利用者が決め、10 章に書く |

- **注文の誤り**に数えるもの: 計画と違う銘柄・向き・株数で約定した、計画に無い株を買った、同じ注文を二度出した、売りを予定の日に出さなかった
  （4.3 の「朝の売り」に切り替えた場合を除く）、その日の計画の買いの一部だけを出さなかった（出すなら全部、出さないなら全部）、予定より前に売った（STOP の後を除く）
- 誤りに数えないもの（記録だけする）: **不成立**（業者・板の都合で約定しなかった。例: 引けがストップ高・ストップ安の配分になると、
  S 株には配分されず約定しない（SBI の注意事項の抜粋））、**間に合わなかった日**（4.2）、**出さなかった日**（その日の買いを全部出さなかった）、
  **受注停止**（S 株取引ルール: 権利付最終日は 13:30〜15:30 ごろ、併合・分割（単元の変更あり）・単元の変更は 13:30〜17:30 ごろ、その銘柄の注文を受けない。
  `--status 受注停止` で記録する。出した買いにも不成立にも数えない）、業者の障害
- 再開: STOP を消すのは、利用者がはっきり頼んだときだけ。理由を 10 章に書く。金額は増やさない

### 3.4 増やさない決まり

- X を増やすのは、その帳が `docs/agents.md` 12.4 の 1〜5 をすべて満たした後だけ（12.3 で閉じていない、6 章の条件、`docs/survivorship.md` の
  時点ごとの TOPIX500 で「使えそう」かつ使っていない会社での確認が通る、c* でもプラス、注文できる形を確かめてある）。そのときも 1 つの帳につき 50 万円まで
- 50 万円より増やすのは、12.4 の 6（最小記録長）を超えてから
- 予行演習で儲かっても、増やす理由にしない（数か月・数十回の損益はぶれが大きく、何も言えない）

## 4. 注文のしかた（手で注文する。第 1 案）

### 4.1 時刻（`docs/agents.md` 12.2 の時刻の表に足す分）

| 何 | 時刻 | 状態 |
|---|---|---|

| **決まりとして注文を出し終える時刻** | **13:50**（締めの時刻の直後の注文は、前の時間の扱いになることがあるため、10 分の余裕を取る）。**目安は 13:30 まで** | 決めた（2026-10-15） |
| 14:00〜24:00 の注文 | 翌営業日の前場始値（9:00）。ただし 14:00〜16:00 の注文は、18:00 ごろの余力の計算で失効することがある | 確かめた |
| 0:00〜7:00 の注文（非営業日の注文も、次の営業日の 7:00 までの扱い） | その日の前場始値（9:00） | 確かめた |
| 7:00〜10:30 の注文 | その日の後場始値（12:30） | 確かめた（使わない） |
| 東証の引け | 15:30（15:25 までザラ場、15:30 に板寄せ。2024-11-05 から） | 決まっている |

- 出典: 利用者が 2026-10-15 に SBI の画面の「S 株取引ルール（基準となる市場及び取引時間等）」から写した公式の文。調査役は、古い版の操作ガイドに
  「10:30〜13:30」と書いたものも見つけた（調査役の第 4 回）。**目安の 13:30 までに出せば、古い版でも今の版でもその日の終値**になる
- **目安を 13:30 にするもう 1 つの理由（受注停止）**: 権利付最終日（配当などの権利が付く最後の日）は 13:30〜15:30 ごろ、併合・分割（単元の変更あり）・
  単元の変更は 13:30〜17:30 ごろ、その銘柄の S 株の注文を受けない。13:30 より前に出せば避けられる。出せなかった注文は「受注停止」と記録する（3.3）
- 道具に入れる時刻は 13:50（`./cfd agents orders --setup --deadline 13:50`。14:00 より後は断る）。4.2 の「30 分前」の決まりで、
  **13:20 までに一覧ができた日だけ買う**
- 注文の取り消しは受付の時間内だけ。訂正はできない（取り消して出し直す）
- `docs/stocks_short.md` 2 章の「10:30〜13:30 の注文が引けの値段」は古い版の時間割（2026-10-15 に注を足した）

### 4.2 毎日の流れ（平日）

1. 13:05 の自動実行（`./cfd agents run --prices`）が値段を取り直し、決算の数字の表を作った**直後に**、E1 の一覧を作る。
   E1 の帳に要るのは決算の数字の表と「銘柄選定の点数が付く株」だけで、後者は値段だけで分かる（銘柄選定は、その日に終値と、前の日の引け → 寄りの
   値がある株にだけ点数を付ける）。だから時間のかかる学び直しを待たずに、台帳の E1 の帳と同じ作り・同じ入力で作れる（`cfdbot/agents/decider.py` の `e1_preview`）
2. その E1 の一覧で今日の注文の一覧を作って `data/agents/live/plan.csv` に書き（同じ日は二度書かない）、**iPhone に知らせる**
   （`docs/stocks_live_daily.md` 5 章の設定をした後。設定が無ければ送らず、一覧はファイルに書くだけ。空運転の間は、題に「空運転: 出すはずの注文」と書く。
   注文の無い日は送らない）
3. その後、今までどおり情報収集 → IR 評価 → 銘柄選定 → 判断で、台帳（`ledger.csv`、続いて `ledger_extra.csv`）を書く。**台帳の中身・書く順番・
   時刻の決まりは変えない**。予行演習の部分が失敗しても台帳は書く（失敗は run.log に残る）
4. 判断の後に、先に作った一覧の E1 の株と、台帳の E1 の帳の株が同じかを確かめる。違えば知らせて run.log に残し、チームに戻す（その日の注文は一覧のまま）。

5. 利用者が SBI のアプリで S 株の成行の注文を出す（売り: 5 営業日たった株を、その日の引けで。買い: その日の引けで）。**13:30 までを目安に、
   遅くとも 13:50 まで**。送信の前に、**預り区分が「特定」**か、銘柄の番号・買いか売りか・株数が一覧と同じかを見る（3.2。手順は `docs/stocks_live_daily.md`）
6. 約定は夕方に分かる。結果を Claude に伝え、Claude が `./cfd agents orders --fill …` で `fills.csv` に書き足す（6 章）

- **買うのは、注文の締め（13:50）の 30 分前（13:20）までに一覧を作れた日だけ**（道具が時刻で判断する）。間に合わない日は、その日は買わない（「間に合わなかった」と記録）
- 間に合った日は、**計画の買いを全部出すか、全部出さないか**のどちらか（一部だけは誤り）。全部出さない日は「出さなかった日」として記録する
- E1 の行が無い日は買わない。売りはする。判断が書かれない日（自動実行の失敗など）は `./cfd agents orders --sells-only` で売りだけの一覧を作る

### 4.3 売りの決まり

- 売る日: 買った日（2.1 の 3 で延ばしたなら、その日）から 5 営業日後（東証の営業日。値段のデータで数える。`docs/stocks_short.md` 4 章の形）
- 売り方: その日の引け（後場終値）で約定する受付の時間内に、S 株の成行の売り。株数は持っている株数の全部
- 予定の日に出せないと前から分かっているときは、**「予定の日の朝（前場始値）」の売り**を出してよい。前の日の **16:00 より後**（〜24:00）か、
  予定の日の 0:00〜7:00 に出す（4.1）。16:00 より後にするのは、14:00 の直後の注文は前の時間の扱い（その日の終値）になることがあり、
  14:00〜16:00 の注文は夕方の余力の計算で失効することがあるため。記録に「朝の売り」（`--at 寄り`）と残す。誤りには数えない
- 予定の日に受注停止（権利付最終日など）で売りを出せなかったら、その日の **16:00 より後**に、翌営業日の前場始値の売りを出す
  （予定の日は `--status 受注停止`、翌日の約定は `--at 寄り` で記録。どちらも誤りに数えない）
- 引けがストップ安の配分などで約定しなかったら、翌営業日から毎日、同じ形で売りを出す（記録に「売りの遅れ」と残る）。
  **予定の日から 5 営業日を超えても売れなければ、STOP を置いて利用者に相談する**（3.3）
- 上場廃止・売買停止・TOB の発表を見たら、STOP を置いて利用者に相談する（売るか待つかは、そのときに利用者が決める）

## 5. コスト（c*）の決め方（事前登録）

### 5.1 何を測るか

1 往復（1 銘柄を買って売るまで）ごとのコスト c（買った金額に対する割合）:

```
c = (買った値段 − 買いの基準の値段) ÷ 買いの基準の値段
  + (売りの基準の値段 − 売った値段) ÷ 売りの基準の値段
  + (買いの手数料 + 売りの手数料) ÷ (株数 × 買いの基準の値段)
```

- **基準の値段**: その注文が約定した板寄せの、東証の公式の値段（引けなら終値、前場始値なら始値）。予定と違う時刻で約定した場合も、
  **実際に約定した時刻**の公式の値段と比べる（時刻のずれによる損益は c に入れない。5.2 で別に数える）
- 手数料は消費税込み。売り買いの差（スプレッド）は約定の値段に入っているので、別には足さない
- **前提**（S 株取引ルール）: 手数料は 0 円（インターネットコース）、売り買いの差は記載が無く、無い見込み。**それでも c を測る**（差があれば c に出る）。
  約定代金の 1 円未満の端数（買いは切り捨て・売りは切り上げで、どちらもこちらに有利）は、1 株の値段で計算するので c に入れない（1 銘柄 1 万円で 0.01% 未満）
- **基準の値段の取り先は Yahoo の調整していない始値・終値**（配当で直していない値）。約定から 3 営業日以内に取って `data/agents/live/ref_prices.csv` に書き足す
  （`./cfd agents orders --report` が取る。後で取ると分割で値が変わることがあるので、先に取った値を使う）
  - **`data/stocks/jp_close.csv` は使わない**（配当・分割を調整した値なので、公式の値段と違う）
  - J-Quants（JPX の公式。無料プランは 12 週間遅れ）は、後からの照らし合わせにだけ使う。0.01% より大きく違った日は 10 章に書くが、計算は Yahoo の値のままにする
    （c* の決まる日が J-Quants の遅れで動かないように）。Yahoo で取れなかった日だけ、J-Quants の値を `ref_prices.csv` に足して使う（source に jquants と書く）
- 後場始値で約定した往復（無料の日足に後場始値が無い）は c の計算から外し、数だけ記録する

### 5.2 c に入れないもの（別に数えて報告する）

| 何 | 数え方 |
|---|---|
| 不成立の割合 | 不成立の買い ÷ 出した買い（5.3 で使う） |
| ストップ高の日の不成立 | 不成立のうち、その日の終値が前の日から +10% 以上のもの（ストップ高の見当。買えた株が、上がらなかった株にかたよっていないかを見る） |
| 間に合わなかった日・出さなかった日 | 日数と銘柄数（出した買いには数えない） |
| **時刻のずれ** t | 紙の上の帳の値段（予定の日の公式の終値）と、実際に約定した時刻の公式の値段の差。朝の売り・売りの遅れ・寄りで買う形で出る。1 往復ごとに t =（買いの基準の値段 − 予定の日の終値）÷ 予定の日の終値 ＋（売る予定の日の終値 − 売りの基準の値段）÷ 売る予定の日の終値 |
| 口座と紙の上の差 | 予行演習で買った株の、口座の損益と、同じ株・同じ日の紙の上の損益（公式の終値で）の差。c ＋ t ＋ 配当の税の分になるはずで、合わなければ記録か計算の誤りを調べる |

- **`docs/agents.md` 6 章の「実際の引けの値段と記録した値段の差が往復 0.10% 以内」は、c だけでなく「c ＋ t」で判断する**
  （本物の注文が予定と違う時刻で約定すると、c は小さく見えるのに紙の上の帳との差は大きくなるため）。値は 5.3 と同じ作り（平均 ＋ 2 × 標準誤差、下限 0.02%）

### 5.3 いつ・どう決めるか

- **不成立**: 出した買いの注文のうち、約定しなかったもの（S 株は全部約定するか、しないかのどちらか。一部だけ約定したら記録して、チームに戻す）。
  **出した買い**は、注文の締めの 30 分前までに一覧を作れた日に、計画どおり出した注文（約定と不成立の合計）。間に合わなかった日・出さなかった日・
  受注停止の分は数えない
- **決める時点**: 第 1 案の形（SBI の S 株・後場終値）で**買いの注文を 60 回出し**、その 60 回がすべて片づいた（売りまで約定して基準の値段がそろった、
  または不成立で紙の上の 5 日がたった）とき
  - そのとき、往復が済んで c を計算できたもの（n 回）が **30 回より少なければ、決めずに続け**、61 回目以降を足して、片づいた時点で n が 30 回に届いたら決める
  - **買いの注文 120 回まで**に n が 30 回に届かなければ、c* は決めない（「測れなかった」）。判定には往復 0.10% を使うが、6 章の「0.10% 以内」は確かめられないので
    満たされない（＝ お金を入れない）
  - 予定どおり出し続けられれば、決算の季節 1〜2 回分（3〜6 か月）で 60 回の見込み。間に合わない日が多ければ、半年〜1 年かかる
- **c* = 平均 ＋ 2 × 標準誤差。ただし 0.02% を下回るなら 0.02%**
  - 平均・標準誤差は、決めた時点の注文（60〜120 回）のうち往復が済んだもの（n 回）の c で計算する（標準誤差 = 標準偏差 ÷ √n）
  - 「平均に、測りのぶれの 2 倍を足す」のは、平均のコストを少なめに見積もらないため。c* は**平均のコストの推定の上の端**（片側 97.7%）で、
    1 回ごとのコストが c* を超える確率の話ではない
  - 下限 0.02% は、測れていない小さなもの（端数・まれな違い）の分。手数料が 0 円で公式の値段どおりに約定すると、c はほぼ 0、標準誤差も 0 に近くなり、
    そのときは c* = 0.02%
- **不成立が 5% 以上**（60 回で 3 回以上）のとき: 板寄せで約定する形では c がほぼ 0 になり、本当の損は「約定しなかった」側に出る。そこで、
  **不成立の株は、紙の上の帳で得たはずの 5 日の差（その株 − 全銘柄の平均。`data/stocks` の終値で）をコストとして足し**、
  出した買いの全部（約定した往復の c と、不成立の株の差）で同じく「平均 ＋ 2 × 標準誤差、下限 0.02%」を c* とする。
  60 回では、本当の不成立の割合が 2% でも 5% 以上と出る見込みは約 12%、本当が 10% なら約 95%（二項分布で計算）
- 決めたら 10 章に書き、**後から数が増えても計算し直さない**。計算し直すのは、注文の形・業者・手数料の決まりが変わったときだけ
  （その時点から新しい形として、60 回を数え直す）
- 計算は `./cfd agents orders --report` の 4 章が、この決まりのとおりに出す（決める時点の前は「途中の数字」として出すが、見て何も変えない）

### 5.4 c* の使い方

- **使うのは、先のデータ（台帳）と使っていないデータでの判定だけ**: `docs/agents.md` 12.4 の 4（台帳の損益を c* で計算してプラス）と 6（最小記録長のコスト後）、
  6 章の「往復 0.10% 以内」（5.2 のとおり「c ＋ t」で判断する）
- 過去の検証の判定（M2・E1 の「まだ判断できない」、`docs/survivorship.md` の確かめ直し）は**往復 0.10% のまま**。c* で計算し直さない
  （測った後で過去の判定を変えると、事前登録の意味が無くなる）

- **注文の形ごとに分ける**: c* には「どの業者の、どの注文の形（例: SBI の S 株・後場終値）で、1 銘柄いくらの注文で測ったか」を必ず書く。形が違えば別の c*
