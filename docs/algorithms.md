# 原油・銀 CFD 向けアルゴリズム設計書

> 前提は「CFD自動売買ツール 開発コンテキスト」（2026年9月30日時点）。
> 証券会社の仕様・コストは変わるため、数値は必ずデモ口座・公式サイトで確認してから使うこと。
> ここで挙げるパラメータは **検証の出発点** であり、儲かることを保証するものではない。

---

## 0. 結論（推奨構成）

| | 原油（WTI / ブレント） | 銀 |
|---|---|---|
| **主力** | **A. ドンチャン・ブレイクアウト**（ATR トレンドフォロー） | **B. スクイーズ・ブレイクアウト**（収縮→拡大） |
| **副** | C. トレンド押し目買い / 戻り売り | C. トレンド押し目買い / 戻り売り |
| 発展形 | – | E. レジーム切り替え（D. レンジ逆張りを組み込む） |
| 時間足 | H4（4時間足） | H4（H1 も検証候補） |
| 新規停止 | API（火）・EIA（水）の **4時間前〜1時間後**、金曜 12:00 ET 以降 | FOMC・CPI・雇用統計（CSV で登録）、金曜 12:00 ET 以降 |
| 出口 | 初期損切り 2.5ATR → 含み益 1ATR で建値 → 3ATR シャンデリア | 同左 ＋ 12本で +0.5R 未満なら撤退（時間ストップ） |

**リスク配分（共通）**: 1回の損失 = 資金の 1%、全ポジション合計 3%、エネルギー・貴金属それぞれ 1.5%、
1銘柄1ポジション、1日 -3% で当日の新規停止、高値から -25% で全停止（手動解除）。

### なぜこの組み合わせか

1. **商品は「たまに来る大きなトレンド」で稼ぐ市場**。原油・銀は値動きの分布の裾が厚く（急騰・急落が多い）、
   小さな損切りを繰り返しながら大きなトレンドを取りにいくトレンドフォローと相性が良い。
   商品先物を中心に運用する CTA（商品投資顧問）の多くがこの型である。
2. **原油は「ニュースで一方向に走る → 急反転する」**。走り出しはブレイクアウト（A）で乗り、
   急反転はシャンデリア型トレーリングで利益を守る。高値掴みを避けたい局面は押し目（C）で補う。
   値動きの大きい在庫統計の直前には新規で入らない。
3. **銀は「静かな期間 → 一気に走る」を繰り返す**（例: 2026年8月は月間 +16%）。
   収縮中は ATR が小さいので損切りを近くに置け、動き出しに乗れれば損益比が大きい（B）。
   だましは早く負けやすいので、時間ストップで切る。
4. **原油（需給・地政学）と銀（金利・ドル・金）は値動きの理由が違う**ので同時に負けにくい。
   ただしリスクオフで全部売られる局面もあるため、合計リスクの上限（3%）を置く。

## 1. 銘柄の特性 → 設計への落とし込み

| 特性 | 対応 | 実装 |
|---|---|---|
| 原油は1日 2〜3%、銀は 2% と大きく、時期によって変わる | ATR で数量を決める（荒れると自動でロットが縮む） | `risk.position_size` |
| 原油は強いトレンドと急反転 | ブレイクアウト + シャンデリア型トレーリング、押し目エントリー | A, C, `exits.py` |
| 原油は EIA（水 10:30 ET）・API（火 16:30 ET）で急変 | 発表の 4時間前〜1時間後は新規停止（任意で発表前に手仕舞い） | `events.py`, `FilterConfig` |
| 地政学（ホルムズ海峡など）で週末に窓が開く | 金曜 12:00 ET 以降は新規停止。窓越えの損切りは始値で約定する前提でテスト | `friday_cutoff_passed`、`stop_gap` |
| 銀は収縮 → 爆発を繰り返す | スクイーズ・ブレイクアウト | B |
| 銀は金融政策・金利・ドルで動く | FOMC・CPI・雇用統計を CSV で登録して新規停止 | `config/events_example.csv` |
| 急変時に証券会社が証拠金率・建玉上限を変える（OANDA 2026年1月: 5%→20%、20→5ロット） | 発注前に証拠金・数量上限を毎回確認、拒否されたら半分で1回だけ再試行して通知 | `risk.py`、EA の `ExecuteEntry`/`SendEntry` |
| 分足はスプレッド負け、日跨ぎは窓・金利コスト | H4 を基本。バックテストにスプレッド・スリッページ・金利を必ず含める | `CostModel` |
| 原油と銀は分散効果がある。WTI とブレントはほぼ同じ | 相関の高いグループ（energy / metals）ごとにリスク上限 | `RiskConfig.cluster_max_risk` |

## 2. アルゴリズム詳細

すべて「足の終値で判断 → 次の足の始値で成行」。各足はその足の終値までの情報しか使わない
（`tests/test_strategies.py::test_no_lookahead` で全戦略を検査）。

### A. ドンチャン・ブレイクアウト（原油の主力）— `strategies/donchian.py`

**ルール**
- 買い: 終値 > 直前 N 本の最高値（+ ATR×buffer）かつ 終値 > EMA(200)
- 売り: 終値 < 直前 N 本の最安値（− ATR×buffer）かつ 終値 < EMA(200)
- 手仕舞い: 直前 M 本チャネルの逆側を終値で抜けたら（M < N）。加えて共通の出口管理

| パラメータ | 既定 | 探索範囲の目安 | 意味 |
|---|---|---|---|
| `entry_period` | 40 | 20〜80 | H4 で 40 本 ≒ 1.5 週間の高値・安値 |
| `exit_period` | 20 | 10〜30 | 手仕舞い用の短いチャネル |
| `trend_ema` | 200 | 0 / 100〜300 | 長期トレンドと逆向きのブレイクを捨てる（0 で無効） |
| `buffer_atr` | 0.0 | 0〜0.5 | ぎりぎりのブレイク（だまし）を除外 |

**狙い**: 原油が材料で一方向に動き出したとき、最初の数本で乗る。勝率は高くないが、
当たったときの利益（数R〜10R）で小さな負けを回収する。

**弱点**: 保ち合い相場では「抜けた → 戻る」で小さな負けが続く。EMA フィルタと
出口の建値ストップでダメージを抑えるが、数か月の停滞は起こりうる（トレンドフォロー共通の性質）。

### B. スクイーズ・ブレイクアウト（銀の主力）— `strategies/squeeze.py`

**ルール**
- 収縮の判定: ボリンジャーバンド(20, 2σ) の幅 < ケルトナーチャネル(20, 1.5ATR) の幅
  （＝ 2σ < 1.5×ATR）
- 直前 20 本のうち 6 本以上が収縮なら「準備完了」
- 買い: 準備完了かつ 終値 > 直前 20 本（収縮ボックス）の高値。売りは逆
- 損切り: ボックスの中央（`stop_box_frac=0.5`）。1〜4 ATR の範囲に収める
- 時間ストップ: 12 本（H4 で 2 日）たっても +0.5R に届かなければ撤退

| パラメータ | 既定 | 探索範囲の目安 |
|---|---|---|
| `bb_period` / `bb_mult` / `kc_mult` | 20 / 2.0 / 1.5 | kc_mult 1.25〜2.0 |
| `box_period` | 20 | 12〜40 |
| `min_squeeze_bars` | 6 | 3〜12 |
| `stop_box_frac` | 0.5 | 0.3〜1.0 |

**狙い**: 銀の「静かな期間 → 一気に走る」の走り出し。収縮中は損切りを近くに置けるので、
同じ 1% のリスクでも損益比が大きくなる。

**弱点**: 指標発表前後の一時的な上下（だまし）。時間ストップと指標前の新規停止で抑える。

### C. トレンド押し目買い / 戻り売り（両銘柄の副戦略）— `strategies/pullback.py`

**ルール**
- 上昇トレンド: EMA(20) > EMA(100)、EMA(100) が 5 本前より上、終値 > EMA(100)、ADX(14) ≥ 20
- 押し: 直近 3 本の安値が EMA(20) + 0.5ATR 以下まで下がった
- 買い: 上昇トレンド かつ 押しあり かつ 終値 > 前の足の高値（再上昇の確認）
- 損切り: 直近 5 本の安値 − 0.5ATR
- 手仕舞い: EMA(20) < EMA(100) になったら。売りは全て逆

**狙い**: ブレイクアウトより有利な価格・狭い損切りで既存トレンドに乗る。
原油の「急反転」でブレイク直後の高値を掴むリスクを分散する。

**弱点**: トレンドの終わり（押しが実は天井）では負ける。ADX と長期 EMA の傾きで弱いトレンドを除外。

### D. レンジ逆張り（補助、銀のレンジ局面のみ）— `strategies/reversion.py`

**ルール**: ADX(14) < 20 のときだけ、z = (終値 − SMA20)/σ20 が −2 未満 かつ RSI(2) < 10 で買い
（売りは逆）。z が 0（平均）に戻ったら手仕舞い。10 本で強制終了、トレーリング・建値移動なし、
週末と指標の前には手仕舞い。

**位置づけ**: トレンド局面で使うと大きく負けるので単独では使わない。E の「レンジ」枠専用。
原油は材料で一方向に飛びやすいため、既定の構成には入れていない。

### E. レジーム切り替え（銀の発展形、Python のみ）— `strategies/regime.py`

ADX で相場を分類し、使う戦略を切り替える複合戦略。各枠内は並び順が優先順位。

| 局面 | 条件 | 使う戦略（優先順） |
|---|---|---|
| トレンド | ADX ≥ 25 | C 押し目 → A ドンチャン |
| 中間 | 20 ≤ ADX < 25 | B スクイーズ |
| レンジ | ADX < 20 | B スクイーズ → D 逆張り |

ポジションは **エントリーした子戦略の手仕舞いルール・出口設定** で管理される
（例: D で入ったら 10 本で終了、A で入ったらシャンデリア）。
EA には未移植なので、まず A〜D を EA で動かし、E は Python 側で有効性を確かめてから移植を検討する。

## 3. 出口管理（共通）— `exits.py`

足の確定時に次の順で評価する（EA も同じ順番）。

1. **最大保有本数・時間ストップ**: n 本経っても +x R に届かなければ次の始値で撤退
2. **建値ストップ**: 終値ベースの含み益がエントリー時 ATR × 1.0 に達したら、損切りを
   建値 + 0.1ATR へ（ヒゲだけでは動かさない）
3. **シャンデリア型トレーリング**: 保有中の最高値 − 現在の ATR × 3（売りは最安値 + 3ATR + スプレッド）
4. 新しい損切り位置が現在値に近すぎる（ストップレベル内）なら、置けないので次の始値で成行決済
5. 0.1 ATR 未満の移動なら書き換えない（サーバー負荷・バックテストとの整合性）

- 損切りラインは必ず **証券会社側の逆指値** として置く。EA が止まっても最後のラインは残る
- 一部利確（`partial_tp_r`）は既定では無効。トレンドフォローは大きな勝ちを伸ばすのが本質で、
  利確を早めると期待値が下がりやすい。使う場合はウォークフォワードで効果を確認する
- 週末・指標前の手仕舞い（`flatten_before_weekend` / `flatten_before_events`）は D では有効、
  トレンド系では無効（トレンドを週をまたいで持つため）。代わりに金曜午後の新規停止で窓リスクを抑える

## 4. リスク管理 — `risk.py`

### 数量の決め方

```
数量 = 資金 × 1% ÷ (損切り幅[USD] × USD/JPY)      ← 最小単位の刻みに切り捨て
```

**計算例**（仮定: 資金 100 万円、1ドル = 150 円、銀 68 ドル・日次変動 2%、WTI 95 ドル・日次変動 2.5%、
H4 の ATR ≒ 日次値幅 ÷ √6 と概算）

| | 銀 | WTI |
|---|---|---|
| H4 ATR（概算） | 約 0.55 ドル | 約 0.97 ドル |
| 損切り幅 2.5 ATR | 約 1.39 ドル | 約 2.4 ドル |
| 最小単位 1 つの損失 | 10oz × 1.39 × 150 ≒ 2,085 円 | 10bbl × 2.4 × 150 ≒ 3,600 円 |
| 許容 1 万円での数量 | 48oz → **40oz** | 27.8bbl → **20bbl** |
| 建玉の金額 | 約 41 万円 | 約 29 万円 |
| 必要証拠金（5%） | 約 2 万円 | 約 1.4 万円 |

- **実質レバレッジは 1 倍前後に収まる**（下の「レバレッジの考え方」参照）。20 倍のレバレッジは使い切らないので、
  証券会社が証拠金率を 5% → 20% に上げても、この規模なら証拠金不足にはなりにくい
  （`scripts/demo.py` のストレステストでも証拠金不足による見送りは 0 回）。
  効いてくるのは **最小単位と建玉上限** の方。
- 1% ルールを守れる最低資金の目安は、H4（上表）なら銀 約 21 万円・WTI 約 36 万円。
  日足で損切り幅を銀 4 ドル・原油 6 ドルとした開発コンテキストの試算では約 100 万円。
- 最小単位でも 1% を超える場合は **見送る**（`min_lot_overshoot=1.0`）。資金が少ないうちに
  無理に最小単位で入ると、1回の損失が 2〜3% になり破綻確率が跳ね上がる。

### 上限と停止条件

| 項目 | 既定 | 目的 |
|---|---|---|
| `risk_per_trade` | 1% | 1回の損失 |
| `max_total_risk` | 3% | 全ポジションが同時に損切りされた場合の合計（建値ストップ後は 0 と数える） |
| `cluster_max_risk` | energy 1.5% / metals 1.5% | WTI とブレント、金と銀の重複を防ぐ |
| `max_positions_per_symbol` | 1 | 同じ銘柄に複数戦略が同時に入らない（ネッティング口座でも安全） |
| `daily_loss_limit` | 3% | 取引日（17:00 ET 区切り）の損失がこれを超えたら当日は新規停止 |
| `max_drawdown_halt` | 25% | 高値からの下落。超えたら全停止し、人が原因を確認するまで再開しない |
| `max_margin_utilization` | 50% | 必要証拠金の合計の上限。超える分は数量を減らす |
| `max_leverage_symbol` | 1.0 倍 | 1銘柄の名目建玉 ÷ 資産の上限（0 で無効）。超える分は数量を減らす |
| `max_leverage_total` | 2.0 倍 | 全銘柄の名目建玉の合計 ÷ 資産の上限（0 で無効） |

### レバレッジの考え方

レバレッジは倍率を決めて使うのではなく、**1回の損失を資金の x% に揃えた結果として決まる**。

```
1ポジションの実効レバレッジ ＝ 1回の許容損失(%) ÷ 損切り幅(価格比 %)
例: 1% ÷ 2.0%（銀の 2.5ATR）＝ 0.5 倍
```

1% ルールは損切りが執行される前提なので、**窓開けでは損失が名目建玉に比例する**
（1.5 倍で 10% の窓なら資金の -15%）。レバレッジ上限はこの「損切りが効かない場面」の上限を決めるためのもの。
平常時はほとんど効かず、静かな相場で損切り幅が狭くなったときにだけ数量を抑える。

**リスク水準ごとの目安**（合成データ 4 通り × 5.7 年の平均。H4、原油+銀の推奨構成。成績は無意味だが、
規模の関係は参考になる。レバレッジ上限は 1銘柄 1 倍 / 合計 2 倍、合計リスク上限は 1回の 3 倍、停止条件なし）

| 1回の損失 | 平均レバレッジ | 最大レバレッジ | 最大DD（平均） | 最大DD（最悪） |
|---|---|---|---|---|
| 0.5% | 0.2 倍 | 0.6 倍 | 9% | 13% |
| **1.0%（既定）** | 0.4 倍 | 1.3 倍 | 24% | 33% |
| 1.5% | 0.7 倍 | 1.8 倍 | 32% | 38% |
| 2.0% | 0.8 倍 | 2.0 倍（上限なしなら 2.7 倍） | 42% | 51% |

- 最大 DD は 1回の損失にほぼ比例して増える。取引数・保有時間・連敗数（最大 10 連敗前後）は変わらない
- 取引回数は原油・銀あわせて **年 110 回前後（週 2 回程度）**、平均保有は **約 3 日**。デイトレードではなくスイング
- 0.5% では資金 100 万円だと最小単位でも 0.5% を超える場面が増え、見送りが増える

**引き上げる場合の手順**
1. 実データのウォークフォワード（検証期間だけ）で、1% のときの最大 DD を測る
2. `1回の損失 = 1% × 許容できる DD ÷ (検証期間の最大 DD × 1.5〜2)` で決める（1.5〜2 は「過去より悪いことが起きる」余裕）
3. 上限は 2%。それ以上は連敗だけで DD が停止条件（25%）に届く
4. 1回の損失を上げたら、`max_drawdown_halt`・`daily_loss_limit`・レバレッジ上限も見直す
5. 1回の損失を上げるより、**値動きの理由が違う銘柄を増やす**方が、同じ DD でリターンを上げやすい
   （分散が効く分だけ、合計の建玉を増やせる）

### 証券会社のルール変更への備え（EA）

- 発注前に毎回 `OrderCalcMargin`（証拠金）、`SYMBOL_VOLUME_MAX` / `SYMBOL_VOLUME_LIMIT`（建玉上限）を確認
- 数量は `SYMBOL_TRADE_TICK_VALUE_LOSS` から円換算で計算（為替の変化も自動で反映）
- 発注が「証拠金不足・数量不正・建玉上限」で拒否されたら、半分の数量で 1 回だけ再試行し、スマホに通知
- 再起動しても同じ足で二重発注しないよう、最後に処理した足・最後にエントリーした足を
  グローバル変数に保存

## 5. フィルタの時刻表

| イベント | 米東部時間 | 日本時間（夏） | 日本時間（冬） | 既定の新規停止 |
|---|---|---|---|---|
| API 週間在庫 | 火 16:30 | 水 5:30 | 水 6:30 | 12:30〜17:30 ET |
| EIA 週間石油在庫 | 水 10:30 | 水 23:30 | 木 0:30 | 6:30〜11:30 ET |
| 金曜の新規停止 | 金 12:00 以降 | 土 1:00 以降 | 土 2:00 以降 | 週明け再開まで |
| 週末手仕舞い（任意） | 金 16:00 までに | 土 5:00 | 土 6:00 | D のみ |

- 時刻は米東部時間で判定しているので、サマータイムの切り替えは自動で反映される
- 米国の祝日週は EIA の発表日がずれる。その週はずれた日時を CSV（`--events`）に追加する
- 銀向けの FOMC・CPI・雇用統計は日程が不規則なので CSV で管理する（`config/events_example.csv`）
- 新規停止の判断は「次の足の始値（＝約定予定時刻）」で行う。H4 足だと、発表の 4 時間前に
  判断した注文は発表の直前に約定してしまうため、発表前の幅を 4 時間（1本分）にしている

## 6. バックテストの約束事 — `backtest.py`

| 項目 | 扱い |
|---|---|
| 価格 | データは Bid。Ask = Bid + スプレッド。買いは Ask で建てて Bid で決済 |
| 約定 | シグナルの次の足の始値（成行 + スリッページ） |
| 損切り | 足の安値（売りは高値 + スプレッド）が逆指値に届いたら逆指値 − スリッページで約定 |
| 窓開け | 始値が逆指値を越えていたら **始値で約定**（週末の窓・指標の急変を再現） |
| 同じ足で損切りと利確の両方に届いた | 損切りを優先（保守的） |
| 逆指値の書き換え | 足の確定時だけ（EA と同じ） |
| スプレッド | 銘柄仕様の値と、CSV の `<SPREAD>` 列の大きい方。`--spread-mult` でストレステスト |
| 金利調整額・キャリングコスト | 保有時間に比例して日割り（週末分も含む） |
| 為替 | 損益は円。USD/JPY は定数か時系列 |

**先読みの検査**: 期待値ゼロのランダムウォーク上で全戦略を動かすと、平均損益は 0R 付近
（誤差の範囲）になることを確認済み（`tests/test_backtest.py::test_no_edge_on_random_walk`）。
なお、足データのバックテストは逆指値ちょうどで約定する前提なので実際より少し有利になる。
その分はスリッページ設定で吸収する（デモ口座の実績で調整）。

## 7. 検証の進め方

1. **データを用意**: フィリップ MT5（デモ）から H4（と H1）を 5 年以上 CSV で書き出す。
   サーバー時刻の方式（`--server-tz`）を最初に確認する（MT5 の気配値表示の時刻と UTC を比較）
2. **コストを実測**: デモ口座で時間帯別のスプレッドを記録し、`config/instruments_phillip.json` を更新
3. **単体バックテスト**: `scripts/backtest.py`。戦略別・決済理由別・見送り理由別の集計を見る
4. **ウォークフォワード**: `scripts/walkforward.py`（学習 24 か月 / 検証 6 か月、隣接平均で「台地」を選ぶ）
5. **ストレステスト**: スプレッド・スリッページ 2〜3 倍、証拠金率 20%、建玉上限の縮小
6. **EA の突き合わせ**: MT5 ストラテジーテスターで `ea_log_signals=true` → `scripts/compare_signals.py`
   で Python とシグナルが一致するか確認（Mac 版 MT5 のテスターで実行する。中身は Windows 版と同じ）
7. **デモ口座で 1〜3 か月** → **少額で本番**（`rk_risk_per_trade` を 0.25〜0.5% に下げて開始）

### 合格ラインの目安（提案）

| 指標 | 目安 | 理由 |
|---|---|---|
| 検証期間だけをつないだ成績 | プラス、PF 1.2 以上 | 学習期間の成績は過大評価になる |
| ウォークフォワード効率 | 0.5 以上 | 検証/学習の年率比。低いほど過剰最適化 |
| 取引回数 | 銘柄×戦略で年 20 回以上 | 少ないと偶然と区別できない |
| 採用パラメータ | 期間ごとに大きく飛ばない | 飛ぶなら「台地」がなく不安定 |
| コスト 2 倍 | まだプラス | スプレッド拡大に耐えられるか |
| 最大ドローダウン | 資金 1% ルールで 20〜25% 以内 | 停止条件（25%）に触れない |

**期待値の持ち方**: トレンドフォローは勝率が 5 割を下回ることも多く、数か月利益が出ない
期間は普通に起きる。短期間の成績で止めたり、パラメータをいじり直したりしないこと
（それ自体が過剰最適化になる）。

## 8. 既知の制約と今後の拡張

- **合成データの成績は無意味**。`scripts/demo.py` は動作確認用
- **EA はこの環境でコンパイルしていない**。MetaEditor でコンパイルし、エラーがあれば修正すること
  （MQL5 標準関数のみ使用、括弧の対応・関数定義は機械的に確認済み）
- **サクソ（限月あり）**: 限月交代時の価格調整は未実装。サクソを使う場合は、つなぎ足の作り方と
  ロールオーバー時の手仕舞い・建て直しの方針を決めてから実装する
- **EIA の祝日ずれ** は自動では判定しない（CSV で追加）
- **Python と EA の差**: スプレッド判定は Python がバー単位、EA は現在値（`ea_spread_wait_min` で待機可）。
  週末手仕舞いは両者とも足単位（H4 なら最大 4 時間早く閉じる）
- **拡張候補**: 金銀比価や金のトレンドを銀のフィルタに使う、WTI−ブレントの価格差、
  天然ガス（季節性・限月影響が大きいので別設計）、E の EA 移植、サクソ OpenAPI 用の発注層
