### まだ決めること

#### D-027 「参考にした本」の載せ方（アフィリエイト）

- 調べた決まり（公式のページは開けず、写しで確かめた。要確認）：
  - YouTube：アフィリエイトのリンク自体は禁止されていません。専用のアカウントで大量に貼ると、スパムと見られえます。
  - Amazon アソシエイト：決まった文言の表示が要ります。申請から180日で3件売れないと、取り下げられることがあります。
  - ステマ規制（2023年10月から）：直接の対象は広告主です。ただ、Amazon アソシエイトのリンクがどちらに当たるかは灰色です。載せるなら「（広告）」を読める大きさで書きます。
  - 収益化が止まる心配は、リンクよりも「量産型」と見られることのほうがずっと大きいです。
- 選択肢（商業色の弱い順）：
  - A：本を載せない
  - B：説明欄に書誌（書名・著者・出版社・年）だけを書き、リンクは付けない
  - C：説明欄にはブログの参考文献のページへのリンクを1つだけ置き、アフィリエイトはブログにだけ置く
  - D：説明欄に直接アフィリエイトのリンクを置く
- リンクを付けたら、動画に「プロモーションを含みます」と出す必要があるか：
  - YouTube の「有料プロモーション」のチェックは、ブランド（出版社など）からお金や物をもらって作った内容のためのものです。自分で選んだ本のアフィリエイトのリンクだけで要るとは、公式のヘルプには書かれていません（解説によって意見が割れる。要確認）。
  - チェックを入れると、動画の冒頭に「プロモーションを含みます」と出ます。
  - 日本の法律（ステマ規制）で直接に表示を求められるのは広告主です。ただ、Amazon の規約が表示を求めるので、リンクを載せるなら説明欄のリンクのすぐ上に「（広告）」と Amazon の決まった文言を書きます。
  - 出版社から本をもらう・お金をもらって紹介する場合は、チェックを入れます。
- 推奨：B。「胡散臭くしない」に合い、規約の追いかけも要りません。収入が要るようになったら、収益化（YPP）のあとで C を足します。
- 得失：B だと、SPEC の「収益の柱は書籍アフィリとブログ」が当面崩れ、収入は YPP の広告だけになります。決めたら SPEC を書き換えます。

#### D-028 資料の画像（方針は決まった。取り先と使い方を決める）

- 「取り先」とは：動画の画面に出す古い絵・書・版本の画像を、どこのサイト（博物館・図書館の画像の公開サービス）から取るか、です。サイトごとに、商用で使えるか・出典の書き方・手を加えてよいかの決まりが違います。
- 候補（規約の原文は、この環境から開けず要確認）：

  | 取り先 | 何があるか | 商用 | 条件 |
  |---|---|---|---|
  | ColBase（国立文化財機構） | 東京・京都・奈良・九州の国立博物館が持つ絵巻・屏風・書・浮世絵 | 可・申請不要 | 出典が要る。手を加えたら書く。寺社から預かった品（寄託品）は入らない |
  | 国会図書館デジタルコレクション | 江戸・明治の版本の挿絵・錦絵・名所図会 | 可・申請不要（保護期間満了のもの） | 公開範囲が「インターネット公開（保護期間満了）」のものだけ。出典を画像の近くに |
  | 国書データベース（国文学研究資料館） | 写本・版本の挿絵 | 国文研が持つ分はパブリックドメイン | ほかの機関の画像は1点ずつ条件が違う |
  | メトロポリタン美術館・シカゴ美術館・クリーブランド美術館 | 浮世絵・書・屏風（海外にある日本美術） | 可（CC0 の作品だけ） | 出典はお願い。館の推薦のように見せない |

- 使わない：e国宝（個人の利用だけ）、東京国立博物館のイメージアーカイブ（商用は有料）、大英博物館（非営利だけ）、CC BY-SA・NC の画像。
- 探す道具にだけ使う：ジャパンサーチ・文化遺産オンライン・ウィキメディア・コモンズ（条件は元の館で確かめる）。
- 決めること（論点）：
  1. どの取り先を使うか。推奨：上の表の4つ。海外の館は日本の作品が少ないので補いにします。
  2. 画像をどこに使うか。推奨：一節・背景の章の画面（資料画像カード）と、写真の足りない所の背景。サムネイルには、自分の写真を中心に使います。
  3. 出典の出し方。推奨：画像が出ている間は画面の隅に短く出し、説明欄にも一覧を書きます。
  4. 手を加えるか。推奨：切り抜き・ゆっくりズームまで。色を付けて元の絵のように見せることはしません（作者の人格への配慮。著作権法60条）。
  5. 取り方と台帳。推奨：使う画像だけを人が選び、取ったページの URL・権利の表示・確かめた日・出典の文・手を加えたかを台帳に残します（誤った著作権の申し立てへの備えにもなる）。
  6. 気をつける絵。地獄草紙・九相図・無残絵などは、使えても年齢制限につながりうるので、サムネイルには使いません。
- 決まったら：SPEC の資料画像カード（今は NDL のページ画像だけ）と画像の台帳を作ります（M6）。
- 写真の数：台本の語りの段落は、資料・事実のカードでなければ写真になります。足りない数は Mac の #12 で見ます。

#### D-010 検索結果を並べ直すモデル（リランカー）

- リランカーとは：悩みの文と一節を1組にして読み、合う度合いを1つの数で返す小さなモデルです。文章は書きません。検索で絞った上位50件を並べ直すのに使います。
  - grader とは別のものです。grader は、評価セットの点を後から付ける採点役（既定は Claude の Haiku）です。
  - 台本を書く LLM（Claude）や augment の gemma とも別です。
- 「評価の点を付けてから比べる」とは：
  1. 評価セット（悩み20件）の候補に、人と grader が「合う 1／合わない 0」を付けておく（答え合わせの表）
  2. リランカーなしとありで検索し、上位10件がどれだけ答え合わせの表の「合う」で埋まるか（nDCG）を数えて比べる
  3. 良くなったときだけ入れる
  - grader は、この答え合わせの表を作る役で、本番の検索の流れには入りません。
- 本番の流れ：悩み → 検索（BM25・密ベクトル）→ 上位50件 → リランカーで並べ直す → 10件 → 企画の LLM が「合う・合わない」を判断して、理由を付けて選ぶ。
  - オーナーの案（grader で合致・無関係を分けてから、リランカーで並べる）は、この最後の LLM の判断にあたります。安いリランカーを先に、高い LLM を後に置くほうが、速くて安く済みます。
- 「モデルのライセンス」とは：Hugging Face から落とすリランカーの重みファイルの利用条件です。収益化するので、非営利だけのもの（jina-reranker-v3 の CC BY-NC など）は使えません。MIT や Apache-2.0 なら使えます。
- 候補（どれも MIT か Apache-2.0 とされる。モデルカードは要確認）：
  - hotchpotch/japanese-reranker の small-v2・base-v2（軽い）
  - cl-nagoya/ruri-v3-reranker-310m（日本語の点が高いとの報告）
  - BAAI/bge-reranker-v2-m3（多言語に強い）
- 推奨：Mac で評価の点を付けたあと（#11）、候補ごとに次のように比べ、良くなったものだけ入れます。
  1. settings の rerank.model を候補のモデル名にする
  2. `uv run koten eval export` を回し直し、増えた行（リランカーが上位に上げた一節）にも点を付ける。前に付けた点は残ります
  3. `uv run koten eval retrieval` を回す。上位10件に点の無い一節（unjudged）がほぼ0になっていることを確かめてから比べる
  - 速さは別に測ります。モデルは最初の1回だけ Hugging Face から落とします（net.py は通りません。e5 と同じ）。
