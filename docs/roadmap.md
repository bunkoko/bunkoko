## 3. オーナーが判断すること

推奨どおりでよければ、まとめて「推奨どおり」で構いません。それぞれの論点は次のとおりです。

### 早めに（M8a・M8b で使う）

#### D-018 団体名義の古い辞書の扱い（例：三省堂『漢和大字典』1903、平凡社『大辞典』1934〜36）

- 何が問題か：団体の名前だけで出た本には、没年で数える人がいません。著作権法53条では、公表から数えます。1967年までに公表したものは満了の見込みです。ただし、確かめないと分からないことが2つあります。
  - あとで個人の名前が著作者として出ていないか（53条2項）。出ていれば、その人の没年で決まります。
  - 本当に団体の名前だけで出たのか。奥付を見ないと分かりません。
  - 『漢文大系』のように、校訂者や注釈者の名前が出ている叢書は、団体名義ではありません。その人たちの没年で決まります。
- 案1（今の扱い）：1冊ずつ人が奥付を見て確かめ、理由を書いてから使います。安全です。手間は1冊15〜30分です。
- 案2：「団体名義で1967年までに公表したもの」を、コードで自動で使えるようにします。速いですが、名義の取り違え（実は個人名義）をそのまま通すおそれがあります。
- 推奨：案1。使う辞書は数冊なので、手間は小さく済みます。

#### D-020 ほかの電子テキスト（Standard Ebooks・Wikisource・Kanripo・ctext・Perseus）の扱い

- 何が問題か：どの電子テキストを、本文の出どころとして DB に入れてよいかです。
  - Standard Ebooks：自分たちが手を入れた部分は CC0 です。元の本文は Gutenberg や影印から来ています。ただ、Perseus や Wikisource（CC BY-SA）を元にした版もあり、そのときは元の条件を引き継ぐおそれがあります。
  - Wikisource・Perseus：CC BY-SA です。R2 で本文を保存できません。
  - Kanripo（漢籍）：ライセンスが書かれていません。
  - ctext：規約で自動の取得を禁じているとされます（要確認）。
- 得失：手がかりだけにすると、漢文やギリシア語の原文は、保護期間の切れた影印から人が起こすことになり、手間がかかります。
- 推奨：
  - Standard Ebooks は、元が Gutenberg か影印の版だけを使います。版ごとに、巻末の記録（colophon）で元を確かめます。
  - ほかは探す手がかりだけにします。
  - Kanripo は、管理者にライセンスを問い合わせます。

#### D-023 古文を自前で今の言葉にした訳にも「試訳」と出すか

- 何が問題か：R5 は、外国語の古典を自前で訳したものに「試訳」と出す決まりです。徒然草のような日本の古文を、自分たちで今の言葉にした場合は決まっていません。
- 出す：チャンネル独自の訳で、決まった訳ではないと視聴者に分かります。読み違いがあっても誠実です。
- 出さない：画面はすっきりしますが、AI が下書きした訳が定まった訳のように見えます。
- 推奨：出す。D-014 で、古い訳があるときはそれを使うと決めたので、試訳になるのは古い訳が無い一節だけです。

#### D-024 英訳から訳したとき（重訳）の書き方

- 何が問題か：『自省録』の原文はギリシア語です。手元にあるのは Long の英訳（1862）です。英訳からの日本語訳は、原文から訳したものではありません。書かなければ、原文から訳したと誤解されます。
- 選択肢：
  - (a)「ロングの英訳（1862）からの試訳」と書く
  - (b) 保護期間の切れた原文の校訂本を起こしてから、原文から訳す（人手と語学力が要る）
  - (c) 書かない（誤解のもと）
- 推奨：(a) で始め、(b) は後回しにします。

#### D-025 百人一首や物語の訳を、青空文庫から足すか

- 何が問題か：今の対象は、NDC 1類（哲学・思想）・914（随筆）・915（日記）です。百人一首（911 詩歌）や、物語の訳（913）を足すと、題材が広がります。
- NDC ごと足す：913 は小説が数千作品あります。付加情報づけ（今の全件で約7日）と索引が大きく増えます。悩みと関係の薄い小説の一節も、候補に混じります。
- 作品を選んで足す：sources.yaml の include_works に、選んだ作品だけを書きます。手間は選ぶことだけです。
- 推奨：作品を選んで足す。候補は、百人一首の評釈・徒然草の訳・方丈記などです。

#### 国会図書館からの取得を始めるか（settings の [ndl] fetch_enabled）

- 何が問題か：次世代デジタルライブラリーの API の条件は「営利目的かつ継続的な利用を除き申請不要」とされます。しかし「継続的」の定義は見つかりません。画像の配信（IIIF）の条件の本文も読めていません。
- 待つ：M8a は、人が画面を見て書き起こす形で進められます。困りません。
- すぐ始める：条件に反していたときの影響が読めません。
- 推奨：NDL の答えを D-003 に書いてから、true にします。答えが「申請が要る」なら、申請するか、人がブラウザから保存する方法にします。

### あとで（M6 より前に）

#### D-027 照合に使った本を、説明欄の「参考にした本」に載せるか

- 何が問題か：載せると、出典の誠実さと、アフィリエイトの収入（SPEC の収益の柱）につながります。気をつけることは次の2つです。
  - 景品表示法のステルスマーケティングの決まり（2023年10月から）で、広告であることの表示が要るとされます（要確認）。説明欄に「（広告）」を付けます。
  - YouTube のアフィリエイトの決まり（要確認）。
- 語りで書名を出さない決まり（D-015・R8）とは別の話です。説明欄に書名を書くのは引用ではないので、問題になりにくいと考えます。
- 推奨：載せる。「（広告）」を付ける。

#### D-022 日本語WordNet を、今の意味の下書きの材料に使うか（M8c）

- 何が問題か：日本語WordNet は自由に使えますが、写しには著作権表示が要ります。訳の誤りもあります（否定が抜けた語釈の例がある）。
  - HDD に置くには、権利判定に新しい区分（「独自のライセンス」）を足すことになります。緩めるのではなく、区分を1つ増やす変更です。
- 使う：下書きが速くなります。
- 使わない：昔の辞書と人の知識で書くので、手間が増えます。
- 推奨：画面には出さず、下書きの材料にだけ使います。誤りは、人が今の辞書2冊で確かめる流れ（M8c の決まり）で拾います。

#### D-026 新しい形式「ことばを読む」を作るか

- 何が問題か：1つの語を、昔の辞書・今の意味・世論調査の数字・古典の用例でたどる形式です。
  - 形式が増えると、量産型と判定されにくくなり、企画の幅も広がります。
  - M8c（今の意味）が無いと作れません。章立てと画面の型を新しく作る手間もかかります。
- 推奨：M8c のあとで1本試し、視聴の数字を見て決めます。

#### 資料の画像やフリー素材の写真を、M6 の画面に使うか

- 何が問題か：SPEC では、画面は自分の写真・保護期間の切れた資料の画像・統計グラフで作り、AI の画像は使いません。足すかどうかで、次の得失があります。
  - 資料の画像（ColBase・NDL・メトロポリタン美術館の CC0 など）：古典の雰囲気が出ます。ただし、所ごとの利用条件と出典の書き方を確かめる必要があります（要確認）。
  - フリー素材の写真（Unsplash・Pexels など）：手軽ですが、ほかのチャンネルと同じ写真になり、「再利用されたコンテンツ」と見られるおそれがあります（YouTube の収益化の決まり）。人物写真などには、規約の細かい決まりもあります。
  - 自分の写真だけ：独自性はいちばん高いですが、撮る手間がかかります。
- 推奨：自分の写真を中心にし、資料の画像を足します。フリー素材は控えめにします。決めるのは M6 の前でかまいません。

#### D-010 検索結果を並べ直すモデル（リランク）

- 何が問題か：上位の候補の質を上げるために、並べ直すモデルを入れるかどうかです。
  - 候補：hotchpotch/japanese-reranker-cross-encoder（small・large）、BAAI/bge-reranker-v2-m3。
  - 入れると、処理時間が延び、モデルのライセンスの確認も要ります。
  - 評価セット（20件）の点が無いと、入れて良くなるかを比べられません。
- 推奨：Mac で評価の点を付けたあとで比べ、良くなったものだけ入れます。

#### D-017 照合（②）について、弁護士に相談するか

- 何が問題か：②は、著作権法30条の4（人が内容を楽しむ目的ではない利用）に頼っています。判例はありません。弱いところは次の3つです。
  - 打ち込むときに人が本を読んでいます。そのため「人が知覚しない処理」（3号）に当たりにくく、柱書き（本文）だけが頼りになります。
  - 照合の目的が「訳者の解釈を知ること」で、思想を楽しむ目的だと反論される余地があります。
  - 本の文を画面などに出すと、目的外の使用（49条1項2号）として複製したとみなされます。今の作りでは出していません。
- 推奨：収益化（YouTube パートナープログラムの申請）の前に1回相談します。尋ねることは次の2つです。
  - 照合が「楽しむ目的」に当たらないか
  - 3号ではなく、柱書きに頼ってよいか
