# ロードマップ: 証券会社の決定 → 口座開設 → データ取得 → 本番稼働

> 2026年9月30日時点の情報で作成。証券会社の手続き・仕様は変わるので、各ステップで公式サイトを確認すること。
> アルゴリズムの中身は [algorithms.md](algorithms.md)、ツールの使い方は [README](../README.md) を参照。

## 全体像

| 時期（目安） | フェーズ | やること | 次に進む条件 |
|---|---|---|---|
| 1週目 | **0. 準備** | 運用資金を決める／公式情報の確認／フィリップのデモ口座を申し込む | 資金額が決まり、デモにログインできた |
| 1〜2週目 | **1. データ取得** | MT5 から価格履歴（H4・H1・D1）と USD/JPY を書き出す。サーバー時刻を確認 | 5年分前後の CSV が揃い、時刻の方式が分かった |
| 1〜3週目 | **2. コスト実測** | デモでスプレッドを時間帯別に記録（EIA の週を含めて最低1週間） | 銘柄仕様ファイルを実測値に更新した |
| 2〜4週目 | **3. 検証（Mac）** | バックテスト → ウォークフォワード → ストレステスト | 合格ライン（algorithms.md 7章）を満たす戦略がある |
| 4週目 | **4. 証券会社を決める** | 下の判断表で決定 | 決定した |
| 4〜5週目 | **5. 本口座開設** | 申込・本人確認・入金（入金は少額から） | 本番の MT5 にログインできた |
| 4〜6週目 | **6. Windows 環境** | ミニPC購入・設定、EA のコンパイル、ストラテジーテスターで突き合わせ | Python と EA のシグナルが一致した |
| 2〜4か月目 | **7. デモで実運用** | EA をデモ口座で 1〜3 か月動かし、毎週記録を確認 | 想定どおりの頻度・コスト・挙動 |
| 5か月目〜 | **8. 少額で本番** | 1回のリスク 0.25〜0.5% で開始 → 3か月問題なければ 1% へ | – |
| 継続 | **9. 運用サイクル** | 月1回の再最適化、指標カレンダーの更新、確定申告 | – |

フェーズ 1〜3 は並行して進められる。**証券会社の決定をデモの後に置いている**のは、
スプレッド・データの長さ・銘柄数を実際に確かめてから決めるため（デモは両社とも無料）。

- [ ] **運用資金を決める**（本番で使う額。生活資金とは分ける）
  - 目安: フィリップなら 50〜100 万円、サクソなら 100〜240 万円（下の「資金の目安」参照）
- [ ] **フィリップ MT5 のデモ口座を申し込む**
  - 公式サイト → FX → 取引ツール・ダウンロード →「Phillip MT5 デモ口座のご案内」→ 申込フォーム
  - 申込後に表示される **口座ID・パスワード・サーバー名** を控える（メールでも届く）
  - 同じ画面から **Mac 版 MT5** をダウンロード
  - **有効期限は登録から 1 か月**、仮想資金 1,000 万円。期限が切れたら再申込み（フェーズ 7 でも注意）
- [ ] （任意）**サクソの開発者ポータル** に登録してシミュレーション環境を触る
  - Saxo Developer Portal でアカウントを作り、シミュレーション用のトークン（24 時間有効）を発行
  - Python から口座情報・価格が取れることを確認するだけでよい
- [ ] 開発コンテキスト 7 章の未確認事項をメモしておき、フェーズ 1〜2 で埋める

## フェーズ 1. データ取得（1〜2週目）

### 1-1. MT5 の設定

1. MT5 にデモ口座でログイン
2. ツール → オプション → チャート →「チャートの最大バー数」を **Unlimited**（無制限）にして再起動
3. 気配値表示で銘柄を右クリック →「すべて表示」→ 銀・WTI・ブレント・金・USD/JPY を表示

### 1-2. バーの書き出し

1. 表示 → 銘柄（Ctrl+U）→ **バー** のタブ
2. 銘柄と時間足を選び、期間を **2020年12月〜現在** にして「リクエスト」
   - フィリップの商品 CFD は **2020年12月7日開始** なので、それ以前のデータは無い
   - デモ口座のサーバーがどこまで遡れるかは実際にリクエストして確認する（足りなければ本口座開設後に再取得）
3. 「バーのエクスポート」で CSV 保存

| 銘柄 | 時間足 | 用途 |
|---|---|---|
| 銀・WTI（必須）、ブレント・金（任意） | **H1** | 学習の売買の足（`scripts/train.py`） |
| 同上 | **M5** | 約定の再現（損切り・利確の順番と時間帯ごとのスプレッド）。H1・H4・D1 はここからも作れる |
| 同上 | H4, D1 | 時間足の比較・上位足フィルタ（無ければ M5/H1 から自動で作る） |
| USD/JPY | H1 | 円換算 |

保存先は Mac の `bunkoko/data/`（`.gitignore` 済みでコミットされない）。ファイル名は `XAGUSD_H4.csv` のように揃える。

### 1-3. サーバー時刻の確認（重要）

時刻がずれると、EIA フィルタや週末判定がすべてずれる。

1. 平日に MT5 の気配値表示の時刻と、そのときの UTC（日本時間 − 9 時間）を比べる
2. 差が **夏 +3 時間 / 冬 +2 時間** なら `--server-tz ny_close`（既定のまま）。多くの MT5 業者はこの方式
3. 違う場合は `--server-tz 9`（UTC からの時差）などを指定し、EA の `ea_server_tz` も合わせる
4. 確認できたら、読み込んだデータの最初の足（週明け）が **日曜 17:00〜18:00（米東部時間）** 付近に来るか見る

### 1-4. データが足りないとき

- 2020年12月より前も検証したい場合は、別のデータ提供元（スポットの銀・原油の分足履歴など）を
  **研究用に限って** 使う。スプレッドや取引時間が違うので、最終判断はフィリップのデータで行う
- サクソの OpenAPI は 1 回の取得が 1,200 本まで。長期の履歴は分割して取得する

### 1-5. 指標カレンダー

`config/events_example.csv` をコピーして、FOMC・CPI・雇用統計・祝日で日程がずれた EIA を登録する
（FRB・米労働統計局・米エネルギー情報局の公表スケジュールから転記）。**毎月 1 回更新**する。

## フェーズ 2. コスト実測（1〜3週目）

- [ ] デモで **最低 1 週間**（EIA 発表のある水曜を含む）、銘柄ごとにスプレッドを記録
  - 手軽な方法: 表示 → 銘柄 → **ティック** のタブで期間を指定して書き出し、Bid と Ask の差を時間帯別に集計
  - 見るべき時間帯: 平常時 / 毎日の再開直後（日本時間 夏 朝7時 / 冬 朝8時）/ EIA 発表前後 / 週明け
- [ ] 成行注文を数回出して、スリッページ（注文時の価格と約定価格の差）を記録
- [ ] **金利調整額**（1 日保有したときの額）を確認
- [ ] 実測値で `config/instruments_phillip.json` の `spread`・`slippage`・`financing_long/short` を更新し、
  `verified` を `true` にする
- [ ] MT5 の銘柄仕様（銘柄を右クリック → 仕様）で、**最小ロット・ロットの刻み・契約サイズ・
  ストップレベル・証拠金率** を確認して同じファイルに反映

## フェーズ 3. 検証（Mac、2〜4週目）

**まずはポートフォリオ学習**（H1 の CSV を `data/` に置いて実行。詳しくは [training.md](training.md)）:

```bash
python scripts/train.py      # config/train.toml の instruments・events に実測値のファイルを指定しておく
```

戦略を個別に深掘りする場合:

```bash
# 1. 推奨構成で全体を見る（実測コスト・実レートで）
python scripts/backtest.py --csv WTI=data/XTIUSD_H4.csv --csv SILVER=data/XAGUSD_H4.csv \
    --instruments config/instruments_phillip.json --fx-csv data/USDJPY_H4.csv \
    --events config/events.csv

# 2. 戦略ごとにウォークフォワード（学習 24 か月 / 検証 6 か月）
python scripts/walkforward.py --csv WTI=data/XTIUSD_H4.csv --symbol WTI --strategy donchian \
    --grid '{"entry_period": [30, 40, 55], "exit_period": [10, 20], "exit.trail_atr": [2.5, 3, 3.5]}' \
    --instruments config/instruments_phillip.json --fx-csv data/USDJPY_H4.csv

# 3. ストレステスト
python scripts/backtest.py ... --spread-mult 2 --slippage-mult 2
```

- データが約 5.8 年なので、学習 24 か月・検証 6 か月だと検証期間は 7 回前後取れる
- 合格ラインは [algorithms.md 7章](algorithms.md#7-検証の進め方)。満たさない戦略は本番に入れない
- 結果（期間・パラメータ・成績）は日付付きで保存しておく。後から「なぜこの設定か」を説明できるように

## フェーズ 4. 証券会社を決める（4週目）

### 判断表

| 条件 | フィリップ（MT5 の EA） | サクソ（OpenAPI） |
|---|---|---|
| 運用資金 | **100 万円未満ならこちら**（最小単位 10） | 最小単位 25 なので資金が約 2.5 倍必要 |
| 開発 | EA（MQL5）は**実装済み** | Python の発注部分は**未実装**（追加開発が必要） |
| 限月・ロールオーバー | 満期なし（処理不要） | 先物ベースで限月あり。**ロールオーバー処理を追加開発** |
| 銘柄数 | 商品 CFD 4〜8 銘柄（要確認） | 19 銘柄 |
| Mac | Mac 版 MT5 に公式対応（研究用）。本番は Windows | どこでも動く |
| データ | MT5 からそのまま書き出せる | API で取得（1 回 1,200 本まで） |

### 資金の目安（1回の損失 1% を守れる最低ライン、銀と WTI を各 1 ポジション）

| | H4（損切り 2.5ATR） | D1（損切り 銀4ドル・原油6ドル） |
|---|---|---|
| フィリップ（最小 10） | 約 40〜50 万円 | 約 100 万円 |
| サクソ（最小 25） | 約 90〜100 万円 | 約 240 万円 |

（1ドル=150円、銀 68 ドル・WTI 95 ドルでの概算。価格・変動率で変わる）

### 推奨

**フィリップで始める**。EA が用意済みで、限月処理が不要、少ない資金で 1% ルールを守れる。
サクソは「資金が 240 万円以上」かつ「Python だけで完結させたい」場合に、発注部分と
ロールオーバー処理を追加開発してから検討する（それまではシミュレーション環境で研究のみ）。

### 決定前に確認すること（フィリップのサポートに問い合わせ）

- [ ] 商品 CFD の取扱銘柄（サイト内で 4 / 5 / 8 銘柄と記載が分かれている）
- [ ] MT5 上のシンボル名、契約サイズ、最小ロット・刻み・上限
- [ ] 口座がネッティングかヘッジングか
- [ ] EA による自動売買・VPS/常時稼働 PC からの利用に制限がないか（書面で確認できると安心）
- [ ] サーバー時刻の方式（フェーズ 1-3 の確認結果と一致するか）

## フェーズ 5. 本口座の開設（4〜5週目）

### フィリップ・キャピタル証券

1. 公式サイトから口座開設を申し込む。**FX・株価指数 CFD・商品 CFD はそれぞれ別口座**なので、
   **商品 CFD 口座** を選ぶ（既に FX 口座がある場合はマイページから追加申込み）
2. 本人確認
   - **マイナンバーが確認できる書類** と **本人確認書類**（氏名・現住所・有効期限・生年月日が分かるもの）
   - メールのリンクからスマートフォンで提出すると **最短即日** で開設
3. 審査（投資経験・資産状況などを聞かれる）→ ログイン情報の通知
4. 本番用 MT5 にログインし、銘柄仕様がデモと同じか確認（違えば銘柄仕様ファイルを更新）
5. **入金は少額から**。フェーズ 8 まで本番で取引はしない

### サクソバンク証券（選んだ場合）

1. 公式サイトから個人口座を申し込む（本人確認・マイナンバー）
2. FX・商品 CFD などは申込から短時間、その他は 0〜2 営業日程度で開設通知（審査で数日かかる例もある）
3. 商品 CFD が基本口座に含まれるか、追加申請が必要かを確認（情報が分かれている）
4. OpenAPI は本番口座があれば無料。開発者ポータルでアプリを登録し、本番用の認証（OAuth）を実装する

## フェーズ 6. Windows 環境（4〜6週目）

- [ ] ミニPC（Windows 11 **Pro**、有線 LAN）を用意。BIOS で通電時自動起動、Windows の自動ログイン、
  MT5 をスタートアップに登録（開発コンテキスト 4.3 章）
- [ ] Mac からリモートデスクトップで操作できることを確認
- [ ] `mql5/Experts/CfdCommodityEA.mq5` を `MQL5\Experts\` にコピーして **コンパイル**（エラーは修正）
- [ ] ストラテジーテスターで `ea_log_signals=true` にして実行 → `scripts/compare_signals.py` で
  Python とシグナルが一致するか確認（不一致が出たら原因を直すまで先に進まない）
- [ ] 通知設定: MT5 アプリ（iPhone）の MetaQuotes ID を登録。n8n を使う場合は Webhook の URL を許可
- [ ] `.txt` パラメータを `%APPDATA%\MetaQuotes\Terminal\Common\Files\` に置いて読み込めるか確認

## フェーズ 7. デモで実運用（2〜4か月目）

- EA をデモ口座で動かす（銀・WTI、各戦略 1 チャート）
- **フィリップのデモは 1 か月で期限切れ**。期限前に再申込みし、EA を新しい口座で貼り直す
  （本口座があればデモの再発行方法をサポートに確認）
- 毎週: 取引一覧をバックテストの同じ期間と比べる（シグナルの一致、約定価格の差、見送り理由）
- 確認すること: 週末・EIA 前後の動き、再起動したときに二重発注しないか、通知が届くか、
  停電・回線断からの自動復帰

## フェーズ 8. 少額で本番（5か月目〜）

- `rk_risk_per_trade` を **0.25〜0.5%** にして開始
- 3 か月、想定の範囲（取引回数・勝率・最大 DD）に収まっていれば 1% に上げる
- 最大 DD の停止（25%）や日次停止が出たら、再開前に原因を確認して記録する

## フェーズ 9. 運用サイクル（継続）

| 頻度 | やること |
|---|---|
| 毎日 | 通知の確認（エラー・発注拒否・停止） |
| 毎週 | 取引の記録、バックテストとの差の確認 |
| 毎月 | データを追加で書き出し → ウォークフォワードで再最適化 → `.txt` を差し替え。指標カレンダーの更新 |
| 半年ごと | 戦略の入れ替え検討（合格ラインを割った戦略は止める） |
| 毎年 | **確定申告**（CFD の損益は申告分離課税。FX などと損益通算でき、損失は申告すれば翌年以降 3 年繰り越せる） |
