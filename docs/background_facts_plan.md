# 古典の「背景」を台本に入れる設計（M5b 案）

- 作成：2026-10-25
- 状態：案。7章の「決めてもらうこと」に答えをもらってから実装を始める（CLAUDE.md の「判断に迷ったら止めて質問する」に従う）。
- 土台にしたのは「事実カード方式」。そこに、段階的に出す進め方と、文ごとに確かめる判定のしくみを組み合わせた。

---

## 0. 要点

- これからは、一節の意味だけでなく、その言葉が書かれた時代、作者の歩み、作品の成り立ちも短く語る。共感に加えて、「へえ」と思える知的な面白さを足すため。
- 背景の事実は LLM に書かせない。DB に入れた事実を `{{fact:事実ID}}` の記号で差し込む（統計の `{{stat:}}` と同じやり方）。DB に入る事実は2種類ある。
  - 人が出典で確かめて書いた1文
  - 青空文庫のデータからコードが作る1文
- LLM が書くのは、事実と事実のあいだをつなぐ短い語りと、解釈だと分かる言い方の読みと、悩みへの当てはめだけ。
- 1回目は新しい外部アクセスなしで出す。図書カードの説明文と Wikidata は2回目以降に回す。ウィキペディアはコードで取りに行かない。

## 1. 何が変わるか（視聴者から見て）

### 今と、これから

| | 今 | これから |
|---|---|---|
| 古典の章の流れ | 出典 → 一節 → 意味 → 当てはめ | 出典 → **背景（事実カード1〜3枚）** → 一節 → 意味 → 当てはめ |
| 背景の長さ | なし | 1回あたり約1分半〜2分半（12分の約15〜20%） |
| 全体の尺 | 目標12分（10〜15分） | 変えない。背景の分は「悩みの場面」や「まとめ」を少し短くして作る |

### 視聴者が得るもの

- **書いたときの作者**：どこで暮らし、何をしていたか。
- **作品の生まれ方**：いつ、どこで、何語で書かれたか。最初はどこに載ったか（初出）。もとの題名（原題）。
- **訳書のとき**：いま聞いている日本語は誰の訳か。訳についての事実と、もとの本（原著）についての事実は、別々の事実として扱う。
- **そのころの世の中**：同じころの出来事を並べて見せる。「それが原因で書いた」とは言わない。原因として言えるのは、出典にそう書いてある場合だけ。
- **人のつながり**：兄弟、師弟、出会い、属していた会などのうち、出典に書いてあるものだけ。
- **時の目印**：コードが計算する。例「この本が出てから、100年あまりがたちます」「その年、作者は○歳になる年でした」。
- **形式Dの2人比べ**：2人の作者の年を並べる。同じ年なら「同じ年でした」と言う。この文もコードが作る。

**画面**
- 事実カード：DB の文そのものと、小さな出典表記を出す。
- 年表カード（M6）：生没年の帯と、出来事の印を出す。
- 説明欄に「背景の出典」の欄を設ける。

### 語りの例

例に出す事実は、いま DB にあって確かめられるものだけにした。作品名、著者名、訳者名、一節、章の名前がそれに当たる。人が確かめてから入れる事実は、〈 〉の中に「何が入るか」だけを書いた。中身は出典で確かめるまで書かない（6章の確認リストを参照）。

**例1：徳冨蘆花『みみずのたはこと』（形式D・1つ目の考え。E20261025-02 を作り直す場合）**

```
［語り・LLM］ 1人目は{{author_short:C1}}です。
              この言葉が書かれたころの日々に、少し寄り道をさせてください。
［事実・自動］ {{fact:A-p（代表の人物ID）-lifespan}}
              →「徳冨蘆花は〈生年〉年に生まれ、〈没年〉年に亡くなりました。」
                （年は青空文庫の作家データから入る）
［事実・人が確認］ {{fact:F-p（人物ID）-001}}
              →〈この本を書いたころの作者の暮らしや出来事を1文で〉
［事実・人が確認］ {{fact:F-w（作品ID）-001}}
              →〈『みみずのたはこと』がどんな本で、いつ出たかを1文で〉
［語り・LLM］ そうした日々の記録の中に、次の一節があります。{{source:C1}}
［一節］ {{quote:C1}}
              →「然し我々は人間です。人間として衝突は自然の約束であります。」
［語り・LLM］ 人と人がぶつかるのは、自然の決まりごとのようなものだ、と言っています。
              ……（今の悩みへの当てはめ）
```

**例2：岡倉天心『茶の本』（村岡博訳）（形式D・2つ目の考え）**

```
［語り・LLM］ 2人目は{{author_short:C3}}です。
［事実・自動］ {{fact:A-w（作品ID）-translation}}
              →「ここで読むのは、村岡博による日本語訳です。」
                （青空文庫の翻訳者の記録から）
［事実・人が確認・原著について］ {{fact:F-w（作品ID）-orig-001}}
              →〈もとの本が、いつ・どこで・何語で出たかを1文で〉
［語り・LLM］ その本の最初の章に、こんな一節があります。{{source:C3}}
              → 岡倉天心『茶の本』（村岡博訳）「第一章　人情の碗」
［一節］ {{quote:C3}}
              →「東西両大陸が互いに奇警な批評を飛ばすことはやめにして…」
［語り・LLM］ 東と西が、お互いを皮肉るのはやめよう、という呼びかけです。……
```

- 原著についての事実は「原著について」と印を付けた行に入れる。訳書の題名に原著の事実をくっつけた文は作らない。
- 前後の文脈（context_text）に作者自身の言葉があれば、一節と背景を重ねて読んでよい。その場合も「〜と重ねて読むこともできます」のように、解釈だと分かる言い方にする。

**例3：比べる章（形式D）**

```
［事実・コードが作る］ {{fact:D-same_year-（2つの事実ID）}}
   →「〈作者Aの出来事〉の年は、〈作者Bの本〉が出た年でもありました。」
［語り・LLM］ ぶつかることを自然と受け止める考えと、皮肉の応酬をやめようという考え。
              あなたの今の関係には、どちらが近いでしょうか。
```

- この文は、人が確かめた2つの事実の年がそろって同じときだけ作る。年まで分かっている事実同士に限る。

### LLM が書くと止められる例

| 書いてしまった文 | 止まる理由 |
|---|---|
| 「〇〇の思想に影響を受けた、蘆花らしい言葉です」 | 「影響を受け」と短い名前「蘆花」が直書き（G1）。影響の主張も出典の事実に無い（G3F） |
| 「人づきあいに疲れて、この本を書いたのでしょう」 | 作者の動機の推測（G3F） |
| 「百年以上前の言葉ですが」 | 「〜年以上前」の直書き（G1）。言いたいときはコードが作る「出てから○年あまり」の事実を使う |
| 「1906年に…」 | 語りに年の直書き（G1）。年は事実カードの中でだけ言う |

## 2. 事実をどこから持ってくるか

調査はこのクラウド環境から行った。青空文庫、Wikimedia、NDL のサイトはどれも開けなかった（プロキシの 403 か、DNS の失敗）。そのため、ほとんどの項目は検索結果の抜粋でしか見ていない。下の表の「確認状況」が「未確認」のものは、Mac のブラウザで本文を読み、docs/decisions.md に書いてから使う。

### 情報源ごとの条件

| **ジャパンサーチ** | 資料のメタデータ | 原則 CC0。データベースごとに条件が違う | **未確認** | 優先度は低い |

### 「確かめた事実」とみなす基準（案）

- 人の歩みの出来事、作品の成り立ち、刊行の事実は、次のどちらかを満たすときだけ verified（確認済み）にする。
  - 種類の違う出典が2つある。
  - 一次の出典が1つある。一次の出典とは、刊行の事実なら NDL の書誌、作者自身の言葉なら作者の PD 本文、生没年なら青空文庫の CSV のこと。
- 図書カードの説明文、出典の無い Wikidata の項目、ウィキペディアは、それだけでは確認済みにしない。手がかりとして使う。
- 確認した人の名前（checked_by）が無い行は読み込まない。

### 2回目に外部アクセスするときの条件

- すべて src/koten/net.py を通す（レート制限、キャッシュ、User-Agent）。
- 1秒1件以下で、同時に1本だけ。
- 429・503 が来たら Retry-After まで待つ（net.py に足す）。
- User-Agent には .env の KOTEN_CONTACT に書いた本物の連絡先を入れる。
- Wikidata への問い合わせは、標準の SPARQL 1.1 だけで書く。WDQS は別の仕組み（QLever）へ移る予定と言われている（二次資料）。
- 取得物は HDD の raw/ に置く。台本づくりは SSD だけを読む。

## 3. データの持ち方

### 置き場所

- 台本づくりが読むものは、すべて SSD の `<SSD_ROOT>/db/koten.sqlite` に置く（db.py の SCHEMA_VERSION を 2 から 3 にする）。台本・企画・serve は HDD を読まない。
- `koten facts build`（夜間などに回す一括処理。`koten index build` と同じ扱い）だけが HDD の parquet と config の CSV を読み、SSD の表を作り直す。一部だけ失敗することはなく、全部入るか、全部入らないかのどちらか。

### SSD の表

| 表 | 中身 |
|---|---|
| persons | person_id（例 `aozora:person:000280`。CSV の0埋めのまま）、代表の ID（別名をまとめたもの）、名前、短い名前（例：蘆花・天心。人が決める）、読み、生年月日、没年月日、生年を人が確かめた印 |
| works_meta | work_id、題名、題名の読み、原題、初出（そのままの文）、底本、底本の親本、図書カードの URL、author_ids、translator_ids |
| facts | 1行が1つの事実（下の表） |
| fact_sources | 1つの事実に出典を何件でも持てる。種類（aozora_csv・ndl_bib・corpus など）、題、URL、場所（章や記録の番号）、根拠のメモ（どこに何とあったか、100字以内）、ライセンス、説明欄に出す出典表記、取得日 |
| fact_links | 事実と作品・人のつながり。時代の事実は、人が「この作品に付けてよい」と結んだときだけ出す |
| fact_usage | どの回のどの章でどの事実を使ったか。同じ話を10回のうちに繰り返さないためと、説明欄の出典に使う |

### facts の列

| 列 | 意味 | 例・決まり |
|---|---|---|
| fact_id | 決まった ID。台本はこれで事実を指す | 人が書いた事実は `F-p000280-001`・`F-w（作品ID）-orig-001`・`F-era-0001`、自動の事実は `A-p000280-lifespan`・`A-w（作品ID）-translation` |
| subject_type / subject_id | 誰（何）についての事実か | person は代表の人物 ID。別名でも同じ事実を使う |
| scope | 対象の範囲 | person・work・original_work（原著）・translation（訳）・era（時代）。訳者のいる作品の事実は original_work か translation のどちらかを必ず付ける |
| kind | 事実の種類 | lifespan、first_pub、translation、original_title、life_event、residence、work_origin、relation、era_event、years_since、age_in_year。死因の種類は読み込みで断る |
| text_ja | 読み上げてカードに出す1文 | です・ます調で80字以内。「。」で終える。数字は `{year:1906}`・`{date:…}` の記号で書く。和暦はコードが付ける |
| card_text | カード用の短い文 | 20字以内 |
| date_start / date_end / date_precision | 日付と、どこまで分かっているか | day・month・year・circa など。分かっている細かさより詳しく言わない |
| entities | 文に出る固有名と読み | 例 `{"name":"…","yomi":"…"}`。名前が文に入っていなければ断る。読みは M6 の読み上げ辞書に使う |
| origin / status | 誰が作ったかと、使えるか | origin は auto・curated（2回目から wikidata・card_draft）。status は auto・verified・needs_review・disputed・rejected。使えるのは auto と verified だけ |
| sensitive | 気をつける話題 | none・health・religion・politics |
| interest | 話の面白さ（人が付ける） | 1〜3 |
| checked_by / checked_at | 確かめた人と日 | 人が書いた事実には必須 |
| text_sha | 差し込む文の指紋 | 確認のあとで文が変わったら気づくため |

### Git に入れるもの（小さい）

- `config/facts.csv`：人が書いた事実。
- `config/fact_sources.csv`：その出典。
- この2つは `stats.csv` と同じく、1行でもおかしければ1件も入れない。
- `config/fact_guard.yaml`：G1 が見る元号の一覧、注意する言い回し、例外にする語。
- `config/person_short_names.yaml`：短い名前（蘆花、天心など）。

### 読み込みで断るもの

- 出典の URL も場所も無い。ライセンスが無い。CC BY なのに出典表記が無い。
- 確認した人の名前が無い。
- 文に記号以外の数字がある。`{year:}` の年が日付の列と合わない。
- 文に「」の引用がある。entities の名前が文に無い。
- 除外の言葉に当たる。worries の keyword_block と blocked_keywords.yaml の自傷・自殺、医療のカテゴリに加えて、事実用に 自死・心中・服毒 などを足す。
- 死因の種類（kind）。
- 訳者のいる作品で scope が work のまま。
- 生年・没年が persons と食い違う。この場合は disputed（食い違いあり）にして使わない。

### 年と和暦の決まり（コードで固定する）

- 和暦は 1873-01-01 以降だけ付ける。それより前は西暦だけにする（旧暦と新暦の換算がぶれるため）。
- 元号が年の途中で変わった年（1912・1926・1989・2019）は、年までしか分からないとき和暦を付けない。日まで分かるときは境目（1912-07-30、1926-12-25、1989-01-08、2019-05-01）で決める。
- 年齢は「その年に○歳になる年」とだけ言う。1873年より前に生まれた人は、人が生年を確かめた印があるときだけ言う。
- 「出てから○年あまり」は10年単位で切り下げる。年がたっても言い直さずに済む。
- 底本の初版の年を「書いた年」として出さない。重版や改版の年かもしれないため。

### 企画と台本の記録

- **plan_json**：章ごとに fact_ids を持つ。回ごとに `facts: {事実ID: 指紋}` の写しを持つ。版は 1.1。
- **台本JSON**：段落の種類に `fact` を足す。画面の種類に `fact_card` と `timeline` を足す。章に `facts` の一覧を持つ。版は 1.1 で、1.0 もそのまま通るので、M5 の3回分はそのまま使える。
- **verification**：`facts` に、使った事実ごとの ID、章、指紋、出典、ライセンス、出典表記、確認者を残す。

## 4. 台本の作り方

### 記号

| 記号 | 使い方 |
|---|---|
| `{{fact:事実ID}}` | kind="fact" の段落の text に、これだけを書く（`{{stat:}}` と同じ）。差し込むのは事実の文そのもの。使える状態（auto・verified）で、この回の企画に入っている事実でなければ解決しない |
| `{{author_short:候補ID}}` | 短い名前（例：蘆花）。DB から入る。毎回フルネームだと硬いので足す。決まっていなければ主な名前を使う |

既存の `{{source:}}`・`{{author:}}`・`{{title:}}`・`{{quote:}}`・`{{stat:}}`・`{{worry:}}` は変えない。タイトルで使える記号も author・title・worry のまま。

### プロンプト（prompts/script_v3.md を新しく作り、settings.toml の script.prompt を変える）

次の今の1行を消す。

> 著者の経歴・年号・作品の成り立ちなど、渡していない事実を書かない。

代わりに次を入れる。

> - 背景の事実（著者の歩み・年・年号・場所・人の関係・作品の成り立ち・時代の出来事）は、kind を "fact" にし、text に {{fact:事実ID}} だけを書いて出す。1つの段落に1つ。渡した事実IDだけを、それぞれ1回まで。
> - 語り（narration）では、事実を言い直さない、付け足さない。年・元号・世紀・〜年前・年齢・人名・地名・団体名・作品名を語りに書かない。
> - 事実どうしの前後（翌年・晩年・その後）や因果（〜だから書いた・〜の影響で）を語りで作らない。言えるのは、事実の文に書いてあるときだけ。
> - 作者の気持ち・ねらい・人柄を推し量らない。
> - 語りで事実を指すときは「この旅」「その本」「そうした暮らし」のように指すだけにする。事実を渡していない章では背景にふれない。
> - 一節を背景と重ねて読むときは「〜と重ねて読むこともできます」のように、解釈だと分かる言い方にする。
> - 背景のあとは、必ず一節か悩みに戻る。講義にしない。

章ごとの入力に、次の欄を足す。

```
この章で使える背景の事実（文は変えずに {{fact:}} の段落で出す。使わなくてもよい）：
- 事実ID：F-p000280-001（徳冨蘆花／出来事／出典あり）
  読み上げる文：……
```

- LLM には、置き場所を決められるように、差し込んだあとの文を見せる。言い換えは G1 と G3F が止める。

### LLM が書いてよいこと・いけないこと

- **書いてよい**：事実の並べ方、短いつなぎ（「少し寄り道をさせてください」「そうした日々の記録の中に」）、解釈だと分かる読み、悩みへの当てはめ、視聴者への問いかけ。
- **書いてはいけない**：
  - 日付、元号、年齢、人名、地名、団体名、題名
  - 出来事、関係、因果、動機、時代の決めつけ（「当時の人はみな…」）、「影響」
  - 事実の言い直し
  - タイトルの中の事実

### 章ごとの役割（writer.py の ROLE_GUIDE を書き換える）

| 役割 | これから |
|---|---|
| opening | 事実は出さない。冒頭30秒で悩みを言う決まり（D-011）は変えない。企画に事実があるときだけ「言葉が生まれた背景にもふれます」と言ってよい |
| context | 事実は出さない |
| classic | ①出典 ②背景（事実1〜2つ）③一節 ④意味 ⑤当てはめ。②は④のあとに置いてもよい（「実はこの言葉を書いた人は…」）。毎回同じ並びにならないようにする |
| work_intro（B） | 名前を「作品と書き手」に変える。事実4〜5つで、書き手の歩み、作品の成り立ち、時代を紹介し、悩みとのつながりで終える。今の「作品の成り立ちや著者の経歴は書かない」は消す |
| worry_block（C） | 一節1つにつき事実は1つまで |
| view_a / view_b（D） | 最初に「人物と時代」として事実2〜3つ。訳書なら訳の事実は必ず入れる。そのあと出典、一節、意味 |
| compare（D） | コードが作る「同じ年」の事実を1つまで置いてよい。前の章の事実は「さきほどの旅」と指すだけ。どちらが正しいかは決めず、問いかけで終える |
| summary | コードが作る年表のふり返り（20秒以内）を1つまで置いてよい。全部の本の刊行年が確認済みのときだけ作る |
| ending | 事実は出さない |

- 事実のない章は、今（M5）とまったく同じに書く。情報が足りなくても回は止まらない。

### 事実の選び方（新しい src/koten/facts/select.py）

- その章の一節の作品、作者（代表の ID）、訳者についての事実を候補にする。時代の事実は、人が結んだもの（fact_links）だけを候補にする。
- 次の順で並べる。
  1. 作品の事実 → 人の事実 → 時代の事実
  2. 役割ごとの種類の優先順
  3. 人が付けた面白さ
  4. 最近10回で使っていないもの
- 形式A・C では、時代の事実は1回に1つまで。
- 一節の選び方（悩みとの近さ）は変えない。事実がある作品を優先するかは、7章で決めてもらう。

### 時間の配分（config/formats.yaml）

- 章の長さの確かめ（目安の±30%）では、事実の文字数も数える。読み上げる文だからである。

## 5. 検証ゲートの変更

### G1（コードで確かめる。gates.py）

追加するのは次の5つ。

1. **事実の段落の形**
   - text が `{{fact:ID}}` だけである。
   - その章に割り当てた事実である。
   - 回の中で1回だけ使われている。
   - `{{fact:}}` を語りや章タイトルに書いたら不合格。
2. **語りへの漏れ**：記号を取り除いた語りと章タイトルで、次を見つけたら不合格。
   ```
   年      (?<![\d０-９])(1[0-9]{3}|20[0-9]{2}|[１２][０-９]{3})\s*年
   年代    \d+年代
   元号    (明治|大正|昭和|…|江戸|室町|鎌倉|平安)(時代|期|年間|初期|末期|[0-9０-９一二…元]+年) ※一覧は fact_guard.yaml
   世紀    [0-9０-９一二…]+世紀
   年前    [0-9０-９一二…百千]+年(前|後|あまり|余り|以上)
   年齢    [0-9０-９一二…]+(歳|才)  ※一節か事実のある章だけ（悩みの場面の「30歳」は許す）
   ```
3. **名前**：次の名前の直書きを不合格にする。今の G1 はフルネーム（例：徳冨蘆花）しか見ていない。
   - SSD の persons にいる人の名前（2字以上。別名も含む）
   - この回の作者・訳者の短い名前と下の名前（例：蘆花、天心）
   - 使える事実の entities にある固有名
   - works_meta の『題名』
4. **注意する言い回し**（fact_guard.yaml）：晩年、生涯、生前、没後、亡くな、留学、洋行、師事、門下、影響を受け、出版、刊行、初出、連載、執筆、原著、訳され、当時、文壇 など。
5. **言い直し**：語りに、事実の文と同じ10字以上の続きがあれば不合格。

**例外**
- その章の一節（quote_text）と前後の文脈（context_text）に出てくる語は許す。一節そのものが明治や年を言っている場合の、誤った不合格を防ぐため。
- 普通の言葉と同じ名前（例：白鳥）は fact_guard.yaml の例外に書く。

**メッセージと書き直し**
- G1 のメッセージは直し方まで書く（例：「年は {{fact:}} の段落でだけ言う」）。
- 書き直しは今と同じ2回まで。
- 誤った不合格が多ければ、M5b で回数を数え、規則ではなく一覧のほうを直す。

### G2F（新しく足す。LLM を呼ぶ前に、コードで確かめる）

企画に入った事実ごとに、次を確かめる。

- 状態が auto か verified である。
- 出典とライセンスがあり、必要な出典表記がある。
- 除外の言葉に当たらない。
- この章の作品・作者・訳者についての事実か、人が結んだ時代の事実である。
- 訳書なら scope が original_work か translation である。
- 指紋が企画のときと同じである。違えば注意として残し、今の確認済みの文を使う。

だめな事実はその章から外し、理由を verification の G2F に残して回は続ける。章の事実が全部外れたら、その章は背景なしで書く。

### G3（判定。prompts/judge_v2.md を新しく作り、script.judge_prompt を変える）

- 判定役に見せるのは次の2つ。書き手への指示や下書きの経緯は今と同じく渡さない。
  - 一節と前後の文脈（今と同じ）
  - **その章とそれまでの章で実際に使った事実の文**。〔DBの事実〕の印を付ける。渡したが使わなかった事実は見せない。使わなかった事実を語りで言い換えたら「根拠なし」になるようにするため。
- 事実のある章では、判定役が**語りの1文ずつ**に種類を付ける。種類は、一節の説明、背景の主張、つなぎ、問いかけ、解釈、当てはめのどれか。あわせて、根拠になる事実 ID（supported_by）と、問題を返す。
- 返す形：`{"faithful":…, "passage_problems":[…], "sentences":[{"seg_id","text","type","supported_by","ok","problem"}]}`
- 問題にするもの（G3F）：
  - 事実と一節に無い人、場所、年、出来事
  - 事実の文と食い違う、または変えた
  - 事実のあいだの前後や因果を作った
  - 作者の動機や気持ちを決めた
  - 時代を決めつけた
  - 解釈を事実のように言った
  - 原著と訳を取り違えた
- **合否はコードが決める**。次のどれかがあれば、その章は不合格。
  - ok=false の文が1つでもある。
  - 「背景の主張」なのに supported_by が空。
  - supported_by が見せていない事実 ID を指している。
- 事実のある章は必ず判定にかける。

### 直らないとき

1. 今と同じく、問題を伝えて2回まで書き直させる。
2. それでも背景のせいで通らない章（G3F や G1 の漏れ）は、**その章だけ背景を外して1回書き直す**。「chN：背景を外した（理由）」と視聴の注意に残す。
3. それでも一節の判定（G3）が通らなければ、今と同じく「人の確認へ」にする。

### G5・G6・視聴の注意

- **G5**：使った事実の文も、除外の言葉で調べ直す。
- **G6**（人の確認を立てる）：
  - health・religion・politics の事実を使った。
  - 確認のあとで文が変わった（指紋が違う）。
  - 2回目以降、人が確かめていない下書きの事実を使った。
- **視聴の注意**（回は止めない）：
  - 「事実を渡したのに1つも使っていない」
  - 背景が回の25%を超えた
  - 背景が章の目安の1.5倍を超えた（書き直しの手がかりとして伝える）

### 描画の前（M6）

- `koten facts check --episode` で全部の `{{fact:}}` を解決し直す。
- 使えなくなった事実や、文が変わった事実があれば、人の確認に戻す。

### 最初に確かめる話題（**どれも未確認**。台本には入れない）

## 7. 利用者に決めてもらうこと

1. **背景の決まり（いちばん大事）**
   - A：背景の事実は DB の文を `{{fact:}}` でそのまま差し込む。LLM はつなぎだけを書く。R6 の「著者情報」に、経歴・年・場所・人の関係・作品の成り立ち・時代の出来事を含めると書き足す。
   - B：LLM が事実を自分の言葉で語り直す。名前と数字だけを記号にし、1文ずつ判定にかける。語りは自然になるが、著者情報の文を LLM が書くことになり、R6 を緩めることになる。
   - **推奨：A**。あわせて、CLAUDE.md に1行足すこと（文言は利用者が直す）と、M6 の前に M5b を入れることの承認をお願いしたい。
2. **ウィキペディア**
   - (1) コードで取らず、LLM にも渡さない。人がブラウザで読み、元の出典を探す手がかりにするのは可。
   - (2) R2 を直して raw/ に保存できるようにする。
   - **推奨：(1)**。(1) のうち「人が手がかりにするのも不可」とするかも決めてほしい。
3. **確認済みとみなす基準**
   - 出典2つ、または一次の出典1つ（案）。
   - 出典1つと利用者の確認。この場合は回に「人の確認」が立つ。
   - **推奨：前者**。図書カードの説明文だけでは確認済みにしない。
4. **事実の文を誰が書くか**
   - 人だけが書く。
   - LLM が出典 URL 付きの下書きを確認待ちの一覧に作り、人が確かめた行だけを入れる。
   - **推奨：後者**（checked_by は必須）。
5. **図書カードの説明文**（取り扱い規準を Mac で読んだあと）
   - 手がかりとしてだけ使う。
   - 要約して事実の文にし、「青空文庫 図書カード（CC BY 4.0、要約・改変）」と書く。
   - **推奨：手がかりだけ**。
6. **Wikidata をいつ始めるか**
   - 1回目の受け入れのあとに、対応づけできる数を数えてから始める（推奨）。
   - すぐ始める。
   - どちらの場合も、KOTEN_CONTACT に本物の連絡先が要る。
7. **NDL サーチの API**
   - 営利として申請する。
   - 当面は人がブラウザで調べる。
   - **推奨：当面はブラウザ**。
8. **気をつける話題**
   - 死因・自殺の事実は使わない（確認してほしい）。
   - 病気の事実（例：病床で書いた作品）は、1回目は使わず、必要になったら個別に決める（推奨）。もう1つの案は、人の確認を必ず立てて使うこと。
9. **時間の配分**
   - 4章の案（背景は約15〜20%、上限25%、12分のまま。悩みの場面とまとめを少し短くする）でよいか。
   - それとも、背景の分だけ約1分伸ばすか（10〜15分の内側）。
   - **推奨：12分のまま**。形式Aの一節を最大6から5にすることも確認してほしい。
10. **一節の選び方**
    - 事実がある作品を優先するか。
    - **推奨：しない**（悩みとの近さを優先する）。
11. **繰り返しと「同じ年」**
    - 同じ事実を10回のうちに繰り返さない（案）でよいか。
    - 形式Dで、コードが作る「同じ年」の文を使ってよいか。
    - **推奨：どちらもよい**。
12. **事実を使わなかったとき**
    - 事実を渡したのに使わなかったら、視聴の注意にとどめる（推奨）。
    - 書き直させる。
13. **冒頭・タイトル・サムネイル**
    - 背景の話題（例：「〇〇に会いに行った作家」）を入れるのは、事実の正しさが約10回分たまるまで待つ。
    - **推奨：待つ**。
14. **画像**
    - M6 で「近代日本人の肖像」の肖像を1枚ずつ確かめて使うか。
    - 地図は入れない（案）でよいか。
