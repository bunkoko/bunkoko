# 古典の「背景」を台本に入れる（M5b）

- 2026-10-26：利用者の判断（下の「決めたこと」）にそって実装した。実データでの確認はまだ（Mac で行う）。
- 判断の記録：docs/decisions.md の D-012（背景の語り方）・D-013（ウィキペディアの扱い）。
- 仕様：docs/SPEC.md の R2・R6・§8.7・§8.8。

## 何が変わるか（視聴者から見て）

これまで古典の章は「出典 → 一節 → 意味 → 今の悩みへの当てはめ」だった。これからは、その言葉が書かれたころの作者の歩み、作品の成り立ち、時代を短く語り、共感に加えて「へえ」と思える知的な面白さを足す。

- 形式A（悩みを古典で考える）：一節の章ごとに背景を20〜30秒（事実2つまで）
- 形式B（1冊を読む）：作品紹介の章で、書き手の歩みと作品の成り立ちを（事実5つまで）
- 形式C（テーマ回）：悩みの章ごとに背景を1つ、15〜25秒
- 形式D（対立する2つの考え）：それぞれの考えの最初に「人物と時代」を40〜60秒（事実3つまで）
- 回の長さは12分のまま。背景の分だけ、ほかの章（悩みの場面・まとめ）が少し短くなる。形式Aの一節は最大5つ

## 決めたこと（2026-10-26、利用者）

1. **背景は AI が自分の言葉で語ってよい**。根拠は DB の確認済みの事実だけ。人名・地名・作品名・団体名・年・月・年齢・数は、事実の項目の記号（`{{fact:事実ID.year}}` など）で差し込む。判定役が1文ずつ事実と照らし合わせ、人が確認する。
2. **事実の文は AI が下書きし、人が確かめる**。確かめた人（checked_by）と、ウィキペディア以外の確かめた出典が無い事実は使わない。
3. **ウィキペディアはプログラムで取得するが、手がかりにだけ使う**。事実は別の資料で確かめる。
4. **尺は12分のまま**。

## 事実の流れ

```
青空文庫の作品CSV ──（koten facts build）──→ 自動の事実（生没年・訳者・初出・原題・出てから○年）
                                                   │
Wikidata（CC0）・ウィキペディア（手がかり）          │
   │（koten facts draft：AI が下書き）                │
   ▼                                              ▼
HDD exports/facts/review_*.csv ──人が確かめる──→ config/facts.csv・fact_sources.csv
                                  （koten facts accept）    │（koten facts build）
                                                           ▼
                                               SSD の facts 表（台本づくりはここだけを読む）
                                                           │
                       企画（章に事実を付ける）→ 台本（記号で語る）→ G1・G3（1文ずつ）→ 人の確認
```

## 事実の持ち方

- 1つの事実は、確かめた1文（text_ja）と項目（slots）を持つ。例：
  - text_ja：「甲野一郎は、1905年に架空の国の作家を訪ねました。」
  - slots：`{"person": "甲野一郎", "year": "1905", "person2": "架空の国の作家"}`
- 項目の種類は名前の頭で決まる：person・place・org・title（『』を付ける）・periodical（「」を付ける）・year・month・age・number。`year_wareki` で和暦（1873年より前と、年だけ分かる改元の年は付けない）。
- 読み込みで断るもの（1行でもあれば1件も入れない）：
  - 文の中の数字が項目に無い、項目の値が文に無い、「」の引用がある
  - 確かめた人が無い、確かめた出典（confirm）がウィキペディアだけ
  - 死因の事実、除外カテゴリの言葉
  - 書誌に無い人物・作品
- 自動の事実は、青空文庫の作品CSV（作家別作品一覧。CC BY 4.0 とされる。要確認）から作る。訳書の初出は、訳と原著のどちらのものか分からないので作らない。
- 表：SSD の persons・works_meta・facts・fact_sources・fact_usage（db.py の版 3）。

## 台本の作り方

- 企画（plan）：章の一節の作品・作者（別名は代表の人物にまとめる）・訳者についての事実を、formats.yaml の facts の数まで選ぶ。訳書なら「ここで読むのは○○の訳」を先に置く。人が確かめた事実を自動の事実より先にし、直近10回で使った事実は外す。事実が付いた章は fact_sec の秒数を足す。plan_json は版 1.1（章の fact_ids と、回の facts＝事実の文の指紋）。
- 台本（prompts/script_v3.md）：章に渡した事実の文と、項目の記号（差し込んだあとの値つき）を見せる。渡していない背景は書かない、前後関係や因果を作らない、作者の気持ちを決めつけない、解釈は解釈と分かる言い方、背景のあとは一節か悩みに戻る。
- 台本JSONは版 1.1：背景の段落に facts（使った事実ID）と、画面 fact_card（M6 で事実のカード）。章に facts。

## 検証

- **G1**：事実の記号は、その章に渡した事実と前の章で使った事実だけ。語りと章タイトルに、年（「1906年」）・元号の年・世紀・「百年前」、この章の事実の項目（作品名は『』つき、雑誌名は「」つき）、書誌の人名（3字以上）を直接書いていない。その章の一節と前後の文脈に出てくる語は除く。
- **G3**：背景の事実を使った章（と、その後の章）は prompts/judge_v2.md で1文ずつ判定する。判定役は文ごとに種類（一節の説明・背景の主張・つなぎ・解釈・当てはめ・問いかけ）と根拠の事実ID・可否を返し、コードが合否を決める：
  - 可否が否の文がある
  - 背景の主張なのに根拠が無い
  - 差し込んだ事実と根拠が合わない
  - 見せていない事実を根拠にしている
- **背景を外す**：背景のせいで2回の書き直しでも通らない章は、背景を外して書き直す（「視聴の注意」に残る）。
- **G6**：企画のあとで事実の文が変わった・使えなくなった回は人の確認へ。
- **記録**：verification の facts に、使った事実・指紋・出典・確認者を残す。台本ができた回は fact_usage に書く。`koten script --show` は背景の段落に【背景｜事実ID】を付け、最後に確認済みの文を並べる。

## Wikidata・ウィキペディア（koten facts draft）

- Wikidata：青空文庫の作家ID（P7311。0埋めなし）・作品ID（P7312。図書カードURLの cards/ から .html の前まで）で項目を探し、ちょうど1件のときだけ使う。死因（P509・P1196）と肖像（P18）は読まない。取り込み元（P143）以外の出典が付いた記述を「出典あり」とする。生年・没年・刊行日の年が下書きと合えば、確かめる候補として書いておく（確認者は人が書く）。
- ウィキペディア：Wikidata の項目から日本語版の記事名を取り、最新版の wikitext を HDD の raw/wikipedia/ に置く。AI の下書き（prompts/facts_draft_v1.md）にだけ渡す。下書きの CSV には版を指す URL（oldid）を残す。取り込むと、手がかり（lead）の出典として「ウィキペディア日本語版「…」（CC BY-SA 4.0）」が入る。
- 取得はすべて net.py（1秒1件・キャッシュ・連絡先入りの User-Agent。429・503 は Retry-After だけ待つ）。

## 要確認（Mac で、使う前に）

- 青空文庫の「収録ファイルの取り扱い規準」：作品CSV（書架情報）が CC BY 4.0 か（CC0 へ移る告知もある）と、出典表記の書き方
- Wikidata の P7311・P7312 の今の定義と、青空文庫の作家・作品がどれだけ対応づくか（koten facts draft の結果で数える）
- Wikimedia の User-Agent の決まりと利用の上限（今の設定は1秒1件）
- ウィキペディアの文を言い換えた文が、継承（SA）の条件にかかる「改変物」にならないか。事実の文は短い1文にし、別の資料で確かめた事実として自分の言葉で書く
