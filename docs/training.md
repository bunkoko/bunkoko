# 複数銘柄のポートフォリオ学習（H1）

原油・銀・金などを組み合わせ、**リスクを抑えつつ利益を狙う構成**を、データから自動で決める仕組み。
CSV を `data/` に置いて 1 コマンドで学習し、そのまま MT5 の EA に渡せるファイルまで作る。

## すぐ使う

```bash
# 1. MT5 から H1 のバーを書き出して data/ に置く（ファイル名の先頭がシンボル名ならよい）
#    例: data/XTIUSD_H1.csv, data/XBRUSD_H1.csv, data/XAGUSD_H1.csv, data/XAUUSD_H1.csv, data/USDJPY_H1.csv
# 2. 学習
python scripts/train.py
# 3. 結果を見る
open output/train/<日時>/report.md
```

- 動作確認だけなら `python scripts/train.py --demo`（合成データ。成績は無意味）
- 設定は `config/train.toml`（コメント付き）。書かなかった項目は既定値
- 同じデータ・設定の計算結果はキャッシュされる。途中で止めても、もう一度実行すれば続きから再開する

### ファイル名のルール

| 置くファイル | 扱い |
|---|---|
| `XAGUSD_H1.csv`, `XAGUSD-H1.csv`, `xagusd.csv` | 銀として読む（区切りは `_` `-` 空白 `.` のどれでも） |
| `XTIUSD` / `USOIL` | WTI、`XBRUSD` / `UKOIL` はブレント、`XAUUSD` は金 |
| `USDJPY_H1.csv` | 円換算に使う（無ければ固定レート） |
| `XAUUSD_H4.csv` など別の時間足 | 読み飛ばす |
| 上記以外のシンボル名 | `config/train.toml` の `[data] symbol_map` に追加すれば読める |

## 何を「学習」しているか

深層学習のような予測モデルではなく、**検証済みのルール（A〜D の戦略）の組み合わせ・パラメータ・資金配分**を
データから決める。期間をずらしながら「学習 24 か月 → 直後の 6 か月で検証」を繰り返す（ウォークフォワード）。

```
各期間ごとに（学習期間のデータだけで決める）
  1. 銘柄 × 戦略ごとに、パラメータの組み合わせを全部バックテスト
     → 隣り合う組み合わせとの平均で評価し、安定して良い「台地」を選ぶ
  2. 銘柄ごとに、評価（シャープレシオ）が基準以上で最も良い戦略を 1 つ採用
  3. 採用した戦略の日次リターンの相関から資金配分を決める
     - リスク寄与を均等にする（ERC）: WTI とブレントのように相関が高い組は自動的に小さくなる
     - 全体の年率ボラティリティを目標（12%）に合わせる
     - 学習期間の最大DD が上限（15%）を超えるなら全体を縮小
     - 配分は「1回の損失」の大きさとして表す（0.25%〜2% の範囲）
  4. 直後の検証期間で成績を測る（ここが本当の成績）
```

最後に、**直近 24 か月で同じ手順を行った結果を本番用の構成**として、EA 用ファイルに書き出す。

### 予測モデル（機械学習）にしない理由

- H1 でも 5〜6 年分のデータでは、相場の局面（トレンド・レンジ・急変）の数は数十回しかない。
  自由度の高いモデルはその少ない局面を覚えてしまい、未来で通用しにくい
- ルールなら EA にそのまま移せて、Python と EA の結果を突き合わせられる（MT5 は ONNX 形式のモデルも
  読めるので、将来ルールの上に予測モデルを重ねることはできる）

## 検証期間の成績は 2 通り出る

| | 中身 | 使い方 |
|---|---|---|
| 近似 | 各戦略の日次リターンを配分どおりに足し合わせたもの | 配分の考え方が正しいかの確認 |
| **実際の資金・全ルールで再現** | 本番と同じ資金・最小単位・レバレッジ上限・1 銘柄 1 ポジション・日次損失停止でバックテスト | **これで判断する** |

レポートの判定は「実際の再現」で、シャープレシオ 0.5 以上・最大DD が停止条件未満・取引 30 回以上を満たすか。
満たさなければ本番に使わない。

## 計算時間

1 件（1 銘柄 × 1 戦略 × 1 パラメータ、H1 で約 5.8 年分）のバックテストは約 0.5 秒。

| 構成 | 件数 | 時間の目安 |
|---|---|---|
| 既定（4 銘柄 × 4 戦略、`config/train.toml`） | 約 1,300 件 | 実測: 3 並列の開発環境で 4 分 35 秒。M5 の Mac なら 1〜2 分程度の見込み |
| 探索範囲を 10 倍に広げた場合 | 約 13,000 件 | M5 で 15〜30 分程度の見込み |

「2 日以内」に対しては大きく余裕がある。`[compute] time_budget_hours`（既定 12 時間）を超える見積もりになったときだけ、
組み合わせを間引いて予算内に収める。**探索範囲を広げるほど偶然良く見えるものを選びやすくなる**ので、
計算資源が余っていても範囲は必要以上に広げない方がよい。

## iPad（M4）を計算に参加させる

この Mac が計算を配り、iPad などの端末が受け取って計算する。コードとデータは Mac から自動で送られる。

1. Mac で、他の端末からの参加を受け付けて学習を始める
   ```bash
   python scripts/train.py --listen 0.0.0.0
   ```
   次のような行が表示される（macOS が受信の許可を聞いてきたら許可）
   ```
   python remote_worker.py http://192.168.1.10:8765 Ab3xY...
   ```
2. iPad に、numpy と pandas が使える Python アプリを入れる（a-Shell、Pyto、Juno など。
   アプリによって入っているライブラリが違うので確認すること。タイムゾーン情報が無い場合は `pip install tzdata`）
3. `scripts/remote_worker.py` を iPad に送り（AirDrop・ファイル App）、アプリで 1. の行を実行
4. 計算中は **アプリを前面に出したまま、自動ロックを「なし」に**する（iPadOS は裏に回ったアプリを止める）

**期待できる効果は小さい**: iPadOS ではアプリが複数のプロセスを使えないので、iPad は 1 コア分しか計算しない。
M5 の Mac（10 コア前後）に対して 1 割程度の上乗せ。既定の構成なら Mac だけで数分で終わるので、
iPad が役立つのは探索範囲を大きく広げたときだけ。iPad が途中で止まっても、そのタスクは時間切れで
Mac 側に回されるので結果は失われない。同じ手順で別の Mac も参加できる（こちらは全コアを使いたい場合、
同じコマンドを複数回起動する）。

通信は同じネットワーク内だけで、起動ごとに変わるトークンが無いと受け付けない。

## 出力（`output/train/<日時>/`）

| ファイル | 中身 |
|---|---|
| `report.md` | 判定・検証期間の成績・本番用の構成・期間ごとの結果 |
| `ea/cfdbot_<銘柄>_<戦略>.set / .txt` | 本番用の構成の EA パラメータ（1回の損失は配分済み）。**H1 のチャートに貼る**（違う時間足では EA が起動しない） |
| `final.json` | 本番用の構成（パラメータ・配分・学習期間の評価） |
| `windows.csv` | 期間ごとの採用戦略・配分・検証成績 |
| `oos_equity.csv` / `oos_trades.csv` | 検証期間だけをつないだ資産曲線と取引（実際の再現） |
| `oos_returns_approx.csv` | 検証期間の日次リターン（近似） |

## 主な設定（`config/train.toml`）

| 項目 | 既定 | 意味 |
|---|---|---|
| `[account] equity` | 100 万円 | 実際の運用資金。最終検証と EA の数量計算に使う |
| `[portfolio] target_vol` | 12% | リスクの大きさ。上げると 1回の損失・レバレッジが比例して上がる |
| `[portfolio] max_train_dd` | 15% | 学習期間の最大DD の上限（検証期間はこれより悪くなりうる） |
| `[portfolio] min_score` | 0.3 | これ未満のシャープレシオの戦略は使わない（その銘柄は見送り） |
| `[portfolio] allocation` | erc | 配分方法（erc / inverse_vol / sharpe_tilt / equal） |
| `[account] max_risk_per_trade` | 2% | 配分後の 1回の損失の上限 |
| `[walkforward] train_months / test_months` | 24 / 6 | 学習・検証期間の長さ |
| `[strategies.*]` | – | 探索する戦略・銘柄・パラメータの範囲 |

## 運用の流れ

1. 毎月、MT5 から H1 を書き出して `data/` を上書き → `python scripts/train.py`
2. `report.md` の判定と、本番用の構成が前回から大きく変わっていないかを確認
3. 問題なければ `ea/*.txt` を Windows の `Common\Files` に置き換える（EA が定期的に読み直す）。
   戦略や銘柄の組み合わせが変わった場合は、チャートへの EA の貼り直しが必要
