# トレンドフォローの改良（複数の期間・量の管理・出口）

`docs/review.md` 4 章の A・B。今の構成（タートル 55/20 日足＋行き過ぎフィルタ、`config/baselines/turtle55_d1_ext.json`）に、
データを増やさずにできる改良を 5 つ試す。**仮説と判定の条件はここに先に書き、結果を見てから変えない。**

書いた日: 2026-10-11（実行する前）。

## 1. 試すもの（5 つ）

| 名前 | 内容 | 理由 |
|---|---|---|
| **multi**（A. 複数の期間） | 55/20 の代わりに、20/10・55/20・120/40 の 3 本を同じルールで同時に持つ（1 回の損失は各 3 分の 1）。向きが揃えば合計は今と同じ、割れれば小さくなる | CTA の定番。1 本の期間の当たり外れをならす。期間を「選ぶ」のではなく「全部持つ」ので過去に合わせにくい。行き過ぎフィルタは 3 本とも今のまま |
| **volcap**（B1. 変動が高い時は量を減らす） | 4 商品（期間C は 3 商品）を同じリスクで持った「かご」の直近 20 日の変動が、それまでの中央値より高いとき、新規の 1 回の損失をその比で減らす（下限 0.5 倍。増やすことはしない） | 商品が同じ向きに動く局面（リスクオフなど）では、銘柄ごとの ATR で量を決めても全体の変動が膨らむ。減らすだけなので、良い局面を逃す形の損はない |
| **no_be**（B2-1. 建値への移動をやめる） | 含み益 1 ATR で損切りを建値に移す決まりを外す（初期の損切り 2.5 ATR とシャンデリア 3 ATR はそのまま） | 建値への移動は、戻りで切られて大きなトレンドを逃しやすい（トレンドフォローでは損になりやすいとされる） |
| **trail5**（B2-2. 追いかける損切りを広げる） | シャンデリアを 3 ATR → 5 ATR | 商品の大きなトレンドは途中の戻りが深い。広げると取り逃しが減る（代わりに利益の戻しは増える） |
| **tp2r**（B2-3. 一部利確） | 含み益 2R で半分を利確（残りは今のまま） | 勝ちの一部を確定して、成績のばらつきを減らす（トレンドフォローでは平均は下がりやすいが、ばらつきの減り方しだい） |

- 試した数: これまでの 28 ＋ 5 ＝ **33**
- 数字（20/10・120/40、20 日・0.5 倍、5 ATR、2R・半分）は、ここに書いた値のまま。結果を見て動かさない

## 2. 確かめ方

- 3 つの期間で、今の構成（基準）と比べる（`docs/cross_asset.md` と同じ型）
  - **期間A**: 先物の長期データ（Yahoo: GC=F・SI=F・CL=F・BZ=F）、2001-01〜2021-05
  - **期間B**: フィリップの MT5 の日足、2021-06〜（本番と同じ条件。Mac でだけ計算できる）
  - **期間C**: 使っていない市場（銅・プラチナ・天然ガス、Yahoo）、2001-01〜
- コスト: 期間A・C は `docs/universe.md` と同じ（往復 0.08%、建玉に年 3%、証拠金率 5%）。期間B はフィリップの実測
- 資金 1,000 万円、1 回の損失 1%。日ごとの資産の変化率からシャープ・年率・最大DD を出す
- **統計**: 候補と基準の日ごとの成績の差（候補 − 基準）の PSR（差の平均が本当にプラスである確率）
- volcap の「かご」: 銘柄ごとの日次リターンを直近 60 日の変動で割って平均（前日までの値だけ）。その直近 20 日の標準偏差を
  「かごの変動」とし、それまでの中央値（250 日以上たまってから）÷ 今の変動 を 0.5〜1.0 に収めて、新規の量に掛ける

## 3. 判定（結果を見る前に決めた）

- **採用候補**: 期間 A・B・C の**すべて**でシャープが基準より良く、かつ期間A（一番長い）で差の PSR が 95% 以上
- **参考**: 3 期間のうち 2 つで良い。採らないが、デモの後に再検討する材料にする
- それ以外: 採らない
- 採用候補が複数あっても、EA に入れるのはデモの区切りで 1 回に 1 つ。順番は期間A の差の PSR が高い順
- 最大DD・取引回数・前半後半は表示するが判定には使わない（条件を増やすと「どれかに当たる」ため）

## 6. カルマンのトレンド（事前登録。2026-10-12、計算する前に書いた）

`docs/review.md` の議論から。物理のモデル（ブラウン運動＋ゆっくりした流れ）でトレンドを推定し、55 日ブレイクの代わりにする。

### モデル

対数の価格 y を「なめらかな流れ＋揺れ」で表す（状態空間モデル。カルマンフィルタで推定）。

- y_t = level_t + ε_t（ε: 揺れ、σ_ε）
- level_t = level_{t−1} + slope_{t−1}（水準そのものには揺れを入れない）
- slope_t = slope_{t−1} + ζ_t（ζ: 流れの変わりやすさ、σ_ζ）

推定するパラメータは **σ_ζ・σ_ε の 2 つだけ**（最尤法。格子で探す）。流れの推定値 slope をその不確かさで割った z を使う。

### 決まり（数字は結果を見て動かさない）

- 入る: z > 1 で買い、z < −1 で売り。手仕舞い: z の符号が変わったら（買いは z < 0、売りは z > 0）。
  損切り・建値・シャンデリアは今の出口と同じ。行き過ぎフィルタ（1.5 倍・20 日）も今のまま
- パラメータの推定: 最初は 500 本たまってから。以後 250 本ごとに、その時点より前の直近 2,000 本で推定し直す
  （未来の値は使わない）。推定の前の期間は売買しない
- 期間B（フィリップ 2021-06〜）は 5 年しか無いので、パラメータの推定には同じ商品の先物の履歴（Yahoo、その時点より前の値）を使い、
  フィルタはフィリップの値に当てる。期間 A・C は自分の値で推定する
- 比べ方・コスト・資金は 2 章と同じ。判定は 3 章と同じ（期間 A・B・C すべてで基準より良く、期間A で差の PSR 95% 以上 → 採用候補）
- 試した数: 34 ＋ 1 ＝ **35**
- 見込み（正直に）: 大きくは変わらない。同じ型（12 か月モメンタム・MACD）は 59 市場でタートルと同程度だった。
  「物理のモデルで作ったルールは、経験則のルールと同じ所に行き着く」と分かれば、この方向は閉じる

```
./cfd trend                       # 基準と kalman だけ（既定）
./cfd trend --variants all        # 1 章の 5 つも
```

### 2026-10-12 期間A・C（クラウドの環境。6 章）

**採らない。期間A でシャープ 0.42 → −0.31（差の PSR 1%）、期間C でも悪い。期間B を足しても変わらない。**

| | 期間A（基準 0.42） | 期間C（基準 −0.05） |
|---|---|---|
| kalman | −0.31（最大DD 14.8% → 47.5%、取引 342 → 1,238 回） | −0.15（取引 387 → 1,300 回） |

- 何が起きたか: 最尤法で推定したパラメータは、どの商品・どの時点でも「流れがとても変わりやすい」側に寄った
  （金 σ_ζ ≈ 0.4%/日、WTI ≈ 0.75〜1%/日で格子の上端）。その結果、フィルタの記憶は数日しかなく、流れの符号が年 55〜60 回
  変わる。符号で手仕舞いするので取引が 3.6 倍になり、損切りと往復コストで削られた
- これは不具合ではなく、モデルの答え。「次の日の価格を一番良く説明する」なめらかな流れは、ほとんど直近数日の動きで、
  数週間続くゆっくりした流れは尤度にほとんど効かない（= ブラウン運動との差が小さい）。だからこの物理モデルは、
  売買に使える遅いトレンドを拾わない
- 55 日ブレイクのような「遅い」ルールは、尤度では選ばれないが成績では勝つ。物理のモデルを使うなら、
  パラメータを尤度ではなく成績で選ぶことになり、それは経験則の最適化と同じ（docs/training.md で検証期間に届かなかった道）
- 試した数: 35。**物理のモデルでトレンドを推定する方向は閉じる。** 残るのは 2 つの差の戻り（オルンシュタイン＝ウーレンベック）
  だけだが、両建てのコストが倍になるので、今は進めない
